# Generic run-scoped structured Logs

## Outcome and scope

Trusted Engine producers can submit structured Logs through the existing run event bridge. The Runner supplies lifecycle, validation and delivery while producers own their meanings. The default production path stays silent.

This replaces the design in closed, unmerged PR 689. Retain its small generic interface and lifecycle guarantees; omit its Benchmark recorder, claims and ownership arbitration. Closed PR 692's discovery, dataset access and provisional scoring are outside this design. Review and merge these documents before a separate implementation PR; merging this PR does not complete OME-934 or authorize unrelated producer work.

## Interface

A dependency-free Engine module defines the port:

```python
type LogScalar = str | int | float | bool | None

class StructuredLogEmitter(Protocol):
    def __call__(self, body: str, attributes: Mapping[str, LogScalar]) -> None: ...

class RunLogScopeFactory(Protocol):
    def open_run_scope(
        self,
        rendered_url4: str,
        emit_structured_log: StructuredLogEmitter,
    ) -> AbstractContextManager[None] | None: ...
```

`build_executor` and `Url4Executor` accept one optional factory, default None. The composition root supplies a concrete adapter only in a later producer issue. A fake adapter tests this same injection path now. No registry or composite implementation is needed for the first consumer.

The factory receives the exact rendered URL4 once per execution, after world resolution. It may inspect the string or silently decline by returning None. The Runner never interprets it. Factory invocation, context entry/exit and emission are synchronous, fast and non-blocking: no filesystem, network, database, dataset access or paid work. This is trusted in-process instrumentation; these restrictions are a contract, not a sandbox capable of preempting a blocking callback.

## Lifecycle

1. Resolve the existing world and create the execution's bridge.
2. Create a run-bound emitter and invoke the optional factory immediately around `url4_run` in the task running it.
3. Enter a returned context once. If entry fails, continue execution without instrumentation; the adapter must unwind its own partial entry because Python does not call exit on a failed entry.
4. Exit the entered context after success, failure or cancellation, while the bridge is still open. Exit may emit a final Log.
5. Invalidate the emitter in a finally block, then follow existing bridge/world cleanup and result serialization.

The adapter cannot suppress or replace execution errors through its context-manager return value. Ordinary instrumentation exceptions are contained; cancellation and process-control signals retain their existing semantics. A teardown failure must not mask the original execution failure/cancellation.

Each emitter belongs to one run and its event-loop thread. Concurrent/nested scopes restore their outer state; retained child-task emitters become inert on exit. Off-thread submissions are dropped before touching the non-thread-safe bridge. No new queue, polling task or background worker is introduced.

## Validation and delivery

A valid record has a nonempty exact built-in string body and a mapping with exact built-in string keys and exact built-in scalar values: str, int, finite float, bool or None. Empty attributes are valid. Nested values, bytes, non-finite floats, invalid bodies/keys/values and malformed mappings drop the entire record. Never coerce values or publish a valid-looking subset. Snapshot the attributes on submission so later caller mutation cannot rewrite a queued record.

The Runner owns severity (INFO), run/root trace attachment, timestamps, sequencing and delivery metadata. Producer attributes cannot override envelope fields. Map submissions through an app-local bridge input into existing LogData; do not change `url4.observe.Log`, wire discriminators or packages/url4.

Injected records must use the same ordinary-Log admission, eviction and drop accounting as existing Logs. They must not become non-evictable events accidentally. Preserve the current soft/hard-cap behavior for authoritative Span/cost events; contain injected submission failures so instrumentation cannot fail execution. Existing bridge capacity limits apply; producer-specific size/retention limits belong to each producer's approved schema. This seam does not claim a new exact byte-memory bound for arbitrary caller strings.

Logs are best-effort and may be lost. Final results remain authoritative. A future cumulative-progress producer must tolerate missing snapshots; saved failure evidence must travel with its error/result rather than depend on this queue.

## Failure containment and privacy

Missing/declining instrumentation is silent. Factory, entry, emission, validation, sink and exit failures must not change results, public errors, model calls, scoring or execution policy. Invalid/expired emissions are inert. Use bounded internal warnings identifying only a stable lifecycle phase and exception type; never exception messages, URL4, Log body/attributes or other payloads. Diagnostics use the normal internal logger, not this emitter, avoiding recursion.

The generic interface validates shape, not semantic safety. Concrete producers must allowlist their own fields and exclude prompts, answers, rubrics, credentials, raw responses and arbitrary exceptions. Do not expose this trusted interface directly to untrusted callers or forward raw runtime logs through it.

## Implementation placement and acceptance

Current seams on origin/main ad0c965d: `runner/executor.py` owns `_Bridge`, `_RunState` and `Url4Executor.execute`; `runner/main.py::build_executor` owns composition. Add `run_log_contract.py` for the port and `runner/run_logs.py` for containment/validation. Generic modules depend only on the port, never a concrete adapter or Benchmark module.

Acceptance tests must prove:

- exact-once factory invocation after world resolution; scope surrounds only `url4_run`, exits before bridge close, and excludes result serialization;
- ordered INFO Logs through the real composition/lifecycle stream using an injected fake, including scope-exit emission;
- unchanged default/declining behavior, original execution errors and cancellation under instrumentation failures;
- whole-record validation, attribute snapshotting, off-thread rejection, expiry and concurrent/nested isolation;
- equal ordinary-Log pressure/eviction/drop behavior while Span/cost behavior stays unchanged;
- payload-free bounded warnings and no semantic imports into generic Runner modules;
- all Engine gates pass, with no URL4/Client changes or altered existing tests.
