# Structured Logs through URL4's existing observation interface

## Recommendation and approval boundary

Extend URL4's existing Log capability with structured attributes and a node-scoped emitter. The Engine forwards these attributes through its existing bridge. This is the recommended emission interface for model-call activity.

This design replaces the Engine-specific logging submission path proposed in #689. It provides generic structured-log emission. It does not replace evaluation lifecycle management, terminal Case accounting or provisional scoring from #692.

Owner approved this design and the cross-package split on 2026-09-09. OME-1165 owns the URL4 package change; OME-934 owns Engine forwarding and safe buffering, under OME-887. Implementation follows the docs merge in separate worktrees and draft PRs, URL4 first. Draft PR 876 remains draft until the owner requests readiness; a docs merge alone completes neither delivery issue.

## Existing capability and missing pieces

On origin/main ad0c965d, `packages/url4/src/url4/observe.py` provides Log plus task-local usage/response sinks. `dag/executor.py` binds those sinks during node resolution. `dag/node.py::ExecutionContext.log` already emits a Log associated with the current span. Engine `runner/executor.py::_log_frame` forwards severity/body into LogData; LogData already supports flat attributes.

The missing pieces are a public node Log emitter, optional attributes on the observation Log, and Engine forwarding. Reusing these avoids a separate Engine bridge input, factory, queue, Benchmark registry or ownership-claim system solely for emission. It also preserves node-span attachment rather than replacing it with run-root attachment.

## Proposed URL4 interface

Illustrative spelling; semantics below are the review contract:

```python
type LogScalar = str | int | float | bool | None

class LogSink(Protocol):
    def __call__(
        self,
        body: str,
        attributes: Mapping[str, LogScalar] | None = None,
        *,
        severity: str = "INFO",
    ) -> None: ...

def current_log_sink() -> LogSink | None: ...
```

Add an optional attributes field after the existing `Log(span_id, severity, body)` fields so existing construction remains valid. Extend `ExecutionContext.log(severity, body, *, attributes=None)` compatibly. Bind the new safe sink alongside the existing node sinks, using an explicit callable rather than exposing ExecutionContext or inspecting bound-method internals.

The sink belongs to the node whose resolve bound it. Observed nested execution binds its own sink and restores the outer binding afterward. Unobserved nested execution inherits an active outer sink and creates no new span. Outside an active binding, including an expired binding inherited by a child task, fresh `current_log_sink()` calls return None. The emitted span identifies that observation context, not exact semantic operation ownership.

## Lifetime, validation and failure semantics

- Each safe sink belongs to one node scope and its event-loop thread. Invalidate it in a finally block on success, failure or cancellation, and restore any outer binding. Child tasks inherit that sink while its scope remains active. After expiry, accessor calls return None when their current binding has expired; retained callables silently drop submissions. ContextVar reset alone is not revocation, including in copied child-task contexts.
- Emission is synchronous and non-blocking. It creates no tasks or I/O. Off-thread and expired calls drop the complete record before touching the observer. Producers own cleanup of heartbeat tasks.
- Validate exact built-in nonempty string bodies, string attribute keys and flat scalar values. Floats must be finite; bytes, nested values, unsupported types and invalid mappings are rejected whole. No coercion or partial publication. None attributes means empty attributes. Severity must be an exact built-in string. Normalize with `strip().upper()` and accept exactly DEBUG, INFO, WARN and ERROR, matching the existing wire vocabulary; the default is INFO. Reject empty/unknown values, including WARNING, TRACE, FATAL, numeric levels and non-string values, as whole-record failures. Do not change existing direct-log behavior or its fallback rules.
- Take a defensive copy of attributes before observation and expose it as an immutable mapping. Neither later mutation of the caller mapping nor mutation through the observation can change a queued record. Preserve existing no-attribute Log construction; test both mutation paths explicitly. Generic shape validation is not content redaction.
- Ordinary validation/submission/observer exceptions from the new safe sink are contained. Cancellation and process-control signals are not swallowed. Any internal warning is bounded and contains only phase/exception type, never payload or raw exception text, and cannot recurse through the sink.
- Preserve the existing Observer contract and `ExecutionContext.log` failure behavior. Do not change how RunStarted, NodeStarted/Finished, usage, responses or existing direct logging propagate observer failures. The safe producer sink is an explicit convenience with separate failure semantics.
- An in-process synchronous callback cannot be preempted if it blocks. Observers and producers must honor their existing non-blocking contract; this is not a sandbox.

These are approved generic rules, not Benchmark or Engine semantics. URL4 must have no Engine imports, Gateway field names, model-call schemas, Case identity or scoring knowledge. Core observation support remains framework-free; OTel, HTTP, NATS and concrete exporters stay outside the base observation module.

## Engine and Client implications

The Engine forwards Log attributes in `_log_frame` into the existing LogData. It retains existing sequencing and trace/span attachment with no second event type or queue. Correct the bridge pressure contract as follows: at either the soft or hard capacity limit, incoming Logs may be dropped and buffered Logs may be evicted to admit authoritative events. All such losses are counted. Authoritative events alone exhausting the hard capacity retain the existing overflow failure.

Optional Logs must never cause an otherwise admissible authoritative event to fail: remove enough buffered Logs to admit that event, including when the hard cap is reached before the soft cap. This is a targeted admission/eviction correction, not a bridge rewrite. Require a paired regression: the same authoritative lifecycle sequence succeeds both with and without optional Logs, with identical authoritative outcomes and accurate Log-loss counts. Separately test authoritative-only hard-cap exhaustion still fails.

OME-1161 owns the Engine model-call producer: approved completion/failure/heartbeat vocabulary, safe observed facts, bounded producer records and cancellation cleanup. Privacy filtering belongs there. Before shipping, each production activity schema must define concrete maximum serialized record size and emission-rate limits, including burst/heartbeat behavior and what happens at those limits. The bridge event-count limit does not bound arbitrary payload sizes. The generic Log extension does not capture model data by itself.

No Client wire event type or transport change is proposed: LogData already has attributes. OME-1135 still owns strict decoding of the eventual activity schema and the Logs tab. That compatibility claim needs an end-to-end wire/Client test, not only an in-memory Engine test. OME-699 remains responsible for authoritative Case/member/role attribution; a node span alone is insufficient.

Benchmark progress requires evaluation-scoped state, typed terminal-outcome observation and explicit setup/teardown. OME-932 owns those mechanisms and their integration with the canonical grader/scorer. This logging interface supplies emission only.

Preserve #692’s useful requirements in that separate design: deduplicate Case terminals, emit cumulative snapshots, recover from dropped updates, and reconcile against the authoritative final result. OME-932 chooses the factory/interface for evaluation lifecycle management; this spec does not decide it. OME-1153's saved failure diagnostics require separate error-detail propagation and must not depend on evictable Logs.

## Alignment with the design repository

Checked OpenMined/screamingface-design at commit `50e4353749d488c2ae352a1a73f70970fd3c924c`. Its [URL4 product description](https://github.com/OpenMined/screamingface-design/blob/50e4353749d488c2ae352a1a73f70970fd3c924c/solutions/screamingface/product/url4/index.md) requires an independent library, inverted I/O and optional transport dependencies. This proposal preserves those rules and serves arbitrary adapters, not just model calls.

The [v0.5 spec index](https://github.com/OpenMined/screamingface-design/blob/50e4353749d488c2ae352a1a73f70970fd3c924c/kevin-mcdonough/docs/adrs/URL4-Spec.md) is draft; Part D's generated page is a placeholder. Architectural consistency is established, but no normative structured-Log contract was verified there. Document this as an additive library observation interface; no grammar change or new wire event is proposed. Durable error-detail changes need their own protocol check.

## Probe evidence and required verification

Scratch `.docs/url4-log-alternative/probe.py` temporarily added the sink, attributes and Engine forwarding without production edits. Actual Url4Executor execution demonstrated distinct concurrent-run spans, copied attributes, rejection of malformed/off-thread submissions and ordinary Log eviction. Context reset and inactive calls were exercised. The experiment is not production coverage.

Before delivery, formal tests must cover:

1. Existing Log construction and direct observer/log behavior; optional attributes through the new safe sink; no-observer behavior and package import isolation.
2. Concurrent scopes; observed nested binding/restoration; unobserved nesting without a new span; inherited child-task bindings; expired accessors returning None and retained callables silently dropping; off-thread submission, cancellation and original-error preservation.
3. Whole-record validation; caller and observation mutation attempts; every accepted severity, lowercase/padded normalization and rejected aliases/types; payload-free bounded diagnostics.
4. Real Engine bridge/lifecycle sequencing into existing wire Logs. Paired authoritative lifecycle runs with/without optional Logs must both succeed at soft- and hard-cap pressure, including hard-cap-below-soft-cap configuration; count every Log loss. Authoritative-only hard-cap exhaustion must retain its overflow failure.
5. Existing Client decoding of structured wire Logs without a new discriminator; actual activity-schema/UI behavior remains on OME-1135.
6. Separate URL4 and Engine full gates in their implementation issues; no live provider tests or weakened existing tests.

## Alternatives

The Engine-only factory remains useful if a proven consumer requires explicit run-wide setup/teardown. It is not selected as the foundational emission path because URL4 already owns node observation and Logs. Closed PR 689's isolation/failure tests may inform the implementation; its Benchmark claim machinery and PR 692's dataset discovery/scoring do not belong in this change.
