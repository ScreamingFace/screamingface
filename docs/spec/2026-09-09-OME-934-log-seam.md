# Structured Logs through URL4's existing observation interface

## Recommendation and approval boundary

Extend URL4's existing Log capability with structured attributes and a node-scoped emitter. The Engine forwards these attributes through its existing bridge. This is the recommended emission interface for model-call activity; it replaces the Engine-only factory proposal in this draft.

This document is proposed, not implementation approval. OME-934 currently prohibits packages/url4 changes. Before coding, approve the revised placement, retain an Engine delivery issue and allocate a separate URL4 package issue under a cross-cutting parent. No package issue or implementation is included here. Draft PR 876 must remain draft until the owner asks otherwise; a docs merge alone does not complete OME-934.

## Existing capability and missing pieces

On origin/main ad0c965d, `packages/url4/src/url4/observe.py` provides Log plus task-local usage/response sinks. `dag/executor.py` binds those sinks during node resolution. `dag/node.py::ExecutionContext.log` already emits a Log associated with the current span. Engine `runner/executor.py::_log_frame` forwards severity/body into LogData; LogData already supports flat attributes.

The missing pieces are a public node Log emitter, optional attributes on the observation Log, and Engine forwarding. Reusing these avoids a separate Engine bridge input, factory, queue, Benchmark registry or ownership-claim system solely for emission. It also preserves node-span attachment rather than replacing it with run-root attachment.

## Proposed URL4 interface

Illustrative spelling; semantics below are the review contract:

```python
type LogScalar = str | int | float | bool | None

class LogSink(Protocol):
    def __call__(
        self,
        body: str,
        attributes: Mapping[str, LogScalar] | None = None,
        *,
        severity: str = "INFO",
    ) -> None: ...

def current_log_sink() -> LogSink | None: ...
```

Add an optional attributes field after the existing `Log(span_id, severity, body)` fields so existing construction remains valid. Extend `ExecutionContext.log(severity, body, *, attributes=None)` compatibly. Bind the new safe sink alongside the existing node sinks, using an explicit callable rather than exposing ExecutionContext or inspecting bound-method internals.

The new sink is available only under an active observed node resolve. Outside that scope it is None. Unobserved nested evaluations must not implicitly claim a new span: preserve the existing inherited-sink behavior where applicable and document/test it. The emitted span is the current observation context, not a claim of exact semantic operation identity.

## Lifetime, validation and failure semantics

- Each safe sink belongs to one node scope and its event-loop thread. Invalidate it in a finally block on success, failure or cancellation, and restore any outer binding. A child task may use an inherited sink only while that node scope remains active. ContextVar reset alone is not revocation; retained callable references must become inert too.
- Emission is synchronous and non-blocking. It creates no tasks or I/O. Off-thread and expired calls drop the complete record before touching the observer. Producers own cleanup of heartbeat tasks.
- Validate exact built-in nonempty string bodies, string attribute keys and flat scalar values. Floats must be finite; bytes, nested values, unsupported types and invalid mappings are rejected whole. No coercion or partial publication. None attributes means empty attributes. Accept the existing standard severity names after explicit normalization; reject unknown values through the new sink.
- Snapshot attributes before observation so caller mutation cannot change a queued event. The production representation must prevent mutation through the observation itself while preserving compatibility for existing no-attribute Logs; test this explicitly. Generic shape validation is not content redaction.
- Ordinary validation/submission/observer exceptions from the new safe sink are contained. Cancellation and process-control signals are not swallowed. Any internal warning is bounded and contains only phase/exception type, never payload or raw exception text, and cannot recurse through the sink.
- Preserve the existing Observer contract and `ExecutionContext.log` failure behavior. Do not change how RunStarted, NodeStarted/Finished, usage, responses or existing direct logging propagate observer failures. The safe producer sink is an explicit convenience with separate failure semantics.
- An in-process synchronous callback cannot be preempted if it blocks. Observers and producers must honor their existing non-blocking contract; this is not a sandbox.

These are proposed generic rules, not Benchmark or Engine semantics. URL4 must have no Engine imports, Gateway field names, model-call schemas, Case identity or scoring knowledge. Core observation support remains framework-free; OTel, HTTP, NATS and concrete exporters stay outside the base observation module.

## Engine and Client implications

The Engine forwards Log attributes in `_log_frame` into the existing LogData. It retains existing sequencing, trace/span attachment, admission, Log eviction and drop accounting; no second event type or queue. Authoritative Span/cost behavior remains unchanged. Test the hard-cap failure case separately: failure containment must apply only to safe Log submission, never hide an existing authoritative-event overflow.

OME-1161 owns the Engine model-call producer: approved completion/failure/heartbeat vocabulary, safe observed facts, bounded producer records and cancellation cleanup. Privacy filtering belongs there. The generic Log extension does not capture model data by itself.

No Client wire event type or transport change is proposed: LogData already has attributes. OME-1135 still owns strict decoding of the eventual activity schema and the Logs tab. That compatibility claim needs an end-to-end wire/Client test, not only an in-memory Engine test. OME-699 remains responsible for authoritative Case/member/role attribution; a node span alone is insufficient.

OME-932 may need independent run-scoped state to accumulate typed Case outcomes and provisional scores. Do not add a run-scope factory just for emission; decide its remaining need when that producer is designed. OME-1153's saved failure diagnostics require separate error-detail propagation and must not depend on evictable Logs.

## Alignment with the design repository

Checked OpenMined/screamingface-design at commit `50e4353749d488c2ae352a1a73f70970fd3c924c`. Its [URL4 product description](https://github.com/OpenMined/screamingface-design/blob/50e4353749d488c2ae352a1a73f70970fd3c924c/solutions/screamingface/product/url4/index.md) requires an independent library, inverted I/O and optional transport dependencies. This proposal preserves those rules and serves arbitrary adapters, not just model calls.

The [v0.5 spec index](https://github.com/OpenMined/screamingface-design/blob/50e4353749d488c2ae352a1a73f70970fd3c924c/kevin-mcdonough/docs/adrs/URL4-Spec.md) is draft; Part D's generated page is a placeholder. Architectural consistency is established, but no normative structured-Log contract was verified there. Document this as an additive library observation interface; no grammar change or new wire event is proposed. Durable error-detail changes need their own protocol check.

## Probe evidence and required verification

Scratch `.docs/url4-log-alternative/probe.py` temporarily added the sink, attributes and Engine forwarding without production edits. Actual Url4Executor execution demonstrated distinct concurrent-run spans, copied attributes, rejection of malformed/off-thread submissions and ordinary Log eviction. Context reset and inactive calls were exercised. The experiment is not production coverage.

Before delivery, formal tests must cover:

1. Existing Log construction and direct observer/log behavior; optional attributes through the new safe sink; no-observer behavior and package import isolation.
2. Concurrent/nested scopes, inherited child tasks, stale callable expiry, off-thread submission, cancellation and original-error preservation under every instrumentation failure path.
3. Whole-record validation, immutable snapshots, all severity cases and payload-free bounded diagnostics.
4. Real Engine bridge/lifecycle sequencing into existing wire Logs, ordinary pressure/drop behavior, hard-cap handling and unchanged Span/cost events.
5. Existing Client decoding of structured wire Logs without a new discriminator; actual activity-schema/UI behavior remains on OME-1135.
6. Separate URL4 and Engine full gates in their implementation issues; no live provider tests or weakened existing tests.

## Alternatives

The Engine-only factory remains useful if a proven consumer requires explicit run-wide setup/teardown. It is not selected as the foundational emission path because URL4 already owns node observation and Logs. Closed PR 689's isolation/failure tests may inform the implementation; its Benchmark claim machinery and PR 692's dataset discovery/scoring do not belong in this change.
