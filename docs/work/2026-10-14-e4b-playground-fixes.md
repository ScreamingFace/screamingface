## Fix: sf.Reduce("median"|"mean") takes select

### Intent

The README row "S4, median form" uses `sf.Reduce("median", extract=sf.Extract("field",
path="answer"), weights=sf.signal("field:confidence"))`. It returns the nearest member's whole
JSON reply, because the median block refuses `select="value"` and its default is `nearest`.
`sf.Median` and `sf.Mean` cannot read a JSON field. So no recipe gives the weighted median
NUMBER of a JSON field. The fix: the median and mean blocks take `select="nearest" | "value"`,
the word of `sf.Median` and `sf.Mean`, as a second name for `mode`. The block keeps only the
mode, so the url4, the evidence and the repr do not change. Stacks: screamingface (source,
tests, README, CHANGELOG), screamingface-engine (one offline recipe test and its fixture).

### Planned changes

- `packages/screamingface/src/screamingface/blocks.py`: `_numeric_select` maps `select` to the
  mode with `_NUMERIC_MODES` before the option check; `_SELECT_CHOICES`; the "does not take
  option" message of the median and mean blocks lists `select`; an invariant that
  `_NUMERIC_MODES` and `_NUMERIC_SELECTS` name the same words; the `Reduce` docstring.
- `packages/screamingface/src/screamingface/reducer.py`: the `Median` docstring points to the
  block form for a JSON field (docstring only).
- New `packages/screamingface/tests/test_reduce_numeric_select.py`.

  `recipe_s4_median.url4` (`s4_median_by_confidence`).
- `apps/screamingface-engine/tests/unit/test_combine_recipes.py`: append one Engine run test.
- New `apps/screamingface-engine/tests/unit/data/combine_contract/recipe_s4_median.url4`
  (generated by `write_recipe_fixture`).
- README (weighted median and mean paragraphs, the "S4, median form" row, the recipes code
  block), CHANGELOG, and the E4b spec docs.
- `sf.Median` and `sf.Mean` keep `extract` as an operator name (pinned public surface; spec P10).
