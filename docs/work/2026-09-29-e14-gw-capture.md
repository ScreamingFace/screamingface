## CI fix (2026-09-30)

Intent: the CI step "AI Gateway Tests / Run Postgres timing benches" fails on PR 1155. The p99
overhead measured 38 to 163 ms against the 5 ms budget. Ticket: OME-1434.

Cause (from the CI logs): each traced call makes two autocommitted INSERTs, so it waits for two
fsyncs. On shared runner disks, about 1% of commits stall for 40 to 160 ms. That is the p99.

Owner decision (2026-09-30, Q31): write the prompt row and the capture row in ONE transaction
(one commit for each call), and run the bench Postgres with durable commit off. The 5 ms budget
stays the same.

Planned changes:

- `core/cache_versions/capture_store.py`: `TortoiseCaptureSink.record` runs both writes in one
  `in_transaction()`. The AIDEV-NOTE gets the correct WHY. The CV-24 INVARIANT text stays.
- New test `tests/unit/cache_versions/test_capture_sink_transaction.py`. No existing test is
  edited. The sink has only Postgres tests in this branch, and this test must run on SQLite.
- `tests/integration/test_capture_overhead_postgres.py`: start Postgres with `fsync=off`,
  `synchronous_commit=off`, `full_page_writes=off`. Update the docstring INVARIANT.
  `_BUDGET_SECONDS`, `_CALLS`, `_ATTEMPTS` and all assertions do not change.

  asserts 20 commits. It counts the xid delta (`txid_snapshot_xmax(txid_current_snapshot())` on a
  separate connection), not `pg_stat_database.xact_commit`: the pg_stat counters are flushed lazily
  for each backend, so a read after the calls can miss them. Each write transaction takes one xid,
