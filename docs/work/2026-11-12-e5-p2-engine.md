# e5-p2-engine — E5 P2 Engine: the Engine drives every Run's fan-out

## Intent

The Engine half of E5 P2 (`OME-1837`): the Engine starts and stops a Run's Candidates itself, so
`sf.evaluate(..., detach=True)` can return at once and its owner can reattach by `run_id` from any
machine. Spec `docs/spec/2026-11-04-e5-p2-detached-run.md` and plan
`docs/plan/2026-11-04-e5-p2-detached-run.md` (docs PR #1747). One PR, five commits, E1 to E5.

- **Gates:** E1: the Run tests on SQLite and Postgres (199 Postgres cases, testcontainers), ruff,

  the full gates.
- **Deviations:** E1 rewrites the prior tests that P2's rules change (the plan's E1 and E5
  groups): a stop leaves a bound Candidate `scheduled` and owed a stop (R9), a `pending`
  Candidate is never reconciled (R8), the pending grace is gone (R12), retention works by id
  (R13). `test_run_records.py` gains one type annotation, since `RunSpec` has typed fields a
  `dict[str, str]` no longer unpacks into. The plan had `run_follow_stamp_s` "at most half of a
  non-zero `orphan_grace_s`"; it is derived down to that (`Settings.follow_stamp_s`) instead of
  refused, so a deployment that set a short grace alone, as P1 allowed, still starts.
- **E2 deviations:**
  - **Retention deletes the keys a Run names** (owner decision 2026-11-12): its context and each
    recorded result. What no record names goes by age, by the bucket's 31-day rule or the folder
    adapter's `delete_older_than`. So the port has `delete(keys)`, not `delete_prefix`, and the
    S3 signer keeps its one-object bound. Spec R13 and §4.4 need that wording in the docs PR.
  - **The record is folded from the frames alone**, not from the run summary: the closing
    summary log is yielded by the executor, never dropped, so the frames give the Client's
    record by construction.
  - **A holder answers from the topics whose claim it won**, from the win until it marks the
    claim finished, not only while its child runs: that also covers the spawn window.
  - **Non-ASCII stays escaped** in the outcome and SETTLED codecs. The record's 48 KiB cap is
    measured escaped, which bounds both.
  - **The claims adapter does not time out an unreachable broker itself**; the worker's 5 s
    claim budget bounds every call.
  - **`last_frame` on the runner port moves to E3**, where the driver first reads it.
  - **`RUN_RESULTS_DIR` is not deploy-time**: only local mode sets it.
  - **Prior tests beyond the plan's E2 list**, each approved in session: the fake `schedule` of
    `test_answer_seed_threading.py`, `test_cache_policy_threading.py`, `test_queue_admission.py`
    and, under `tests/integration/`, `test_e2e_compose_flow.py` and
    `test_run_control_resilience.py` gains the two new parameters; the stand-in run params of
    `test_runner_settlement.py` and `test_supervisor_terminal_root_source.py` gain
    `result_prefix=None`; `test_supervisor_launch.py` uses version "9" as its unknown version;
    `test_catalog_wiring.py` pins the two run-results credential settings.
  - **Owner checks before deploy:** the broker's JetStream file store holds the outcome stream's
    512 MiB beside `events.maxBytes`; the runner pool rolls before the App (R15).
