# e5-p2-engine — E5 P2 Engine: the Engine drives every Run's fan-out

## Intent

The Engine half of E5 P2 (`OME-1837`): the Engine starts and stops a Run's Candidates itself, so
`sf.evaluate(..., detach=True)` can return at once and its owner can reattach by `run_id` from any
machine. Spec `docs/spec/2026-11-04-e5-p2-detached-run.md` and plan
`docs/plan/2026-11-04-e5-p2-detached-run.md` (docs PR #1747). One PR, five commits, E1 to E5.

- **Deviations:** E1 rewrites the prior tests that P2's rules change (the plan's E1 and E5
  groups): a stop leaves a bound Candidate `scheduled` and owed a stop (R9), a `pending`
  Candidate is never reconciled (R8), the pending grace is gone (R12), retention works by id
  (R13). `test_run_records.py` gains one type annotation, since `RunSpec` has typed fields a
  `dict[str, str]` no longer unpacks into. The plan had `run_follow_stamp_s` "at most half of a
  non-zero `orphan_grace_s`"; it is derived down to that (`Settings.follow_stamp_s`) instead of
  refused, so a deployment that set a short grace alone, as P1 allowed, still starts.
- **E2 deviations:**
  - **Retention deletes the keys a Run names** (owner decision 2026-11-12): its context and each
    recorded result. What no record names goes by age, by the bucket's 31-day rule or the folder
    adapter's `delete_older_than`. So the port has `delete(keys)`, not `delete_prefix`, and the
    S3 signer keeps its one-object bound. Spec R13 and §4.4 need that wording in the docs PR.
  - **The record is folded from the frames alone**, not from the run summary: the closing
    summary log is yielded by the executor, never dropped, so the frames give the Client's
    record by construction.
  - **A holder answers from the topics whose claim it won**, from the win until it marks the
    claim finished, not only while its child runs: that also covers the spawn window.
  - **Non-ASCII stays escaped** in the outcome and SETTLED codecs. The record's 48 KiB cap is
    measured escaped, which bounds both.
  - **The claims adapter does not time out an unreachable broker itself**; the worker's 5 s
    claim budget bounds every call.
  - **`last_frame` on the runner port moves to E3**, where the driver first reads it.
  - **`RUN_RESULTS_DIR` is not deploy-time**: only local mode sets it.
  - **Prior tests beyond the plan's E2 list**, each approved in session: the fake `schedule` of
    `test_answer_seed_threading.py`, `test_cache_policy_threading.py`, `test_queue_admission.py`
    and, under `tests/integration/`, `test_e2e_compose_flow.py` and
    `test_run_control_resilience.py` gains the two new parameters; the stand-in run params of
    `test_runner_settlement.py` and `test_supervisor_terminal_root_source.py` gain
    `result_prefix=None`; `test_supervisor_launch.py` uses version "9" as its unknown version;
    `test_catalog_wiring.py` pins the two run-results credential settings.
  - **Owner checks before deploy:** the broker's JetStream file store holds the outcome stream's
    512 MiB beside `events.maxBytes`; the runner pool rolls before the App (R15).
- **E3 deviations:**
  - **The driver settles a Candidate through the registry itself**, for a permanent refusal and
    for a run whose outcome never arrived (R7), rather than publishing an outcome for the writer:
    the driver is in the App, and `settle` is first-wins, so a runner outcome that lands later
    still fills the cost and the record.
  - **The cancel route and the tick share `runs/stopping.make_stops`**, which makes owed stops and
    returns what failed. The route keeps its own recheck and 503; no `stop_run` wrapper was needed,
    since `RunRegistry.stop` already records the stop.
  - **`scheduling.py` holds model admission and the schedule call.** The selector refusal and the
    cache-policy convergence read the request's headers, so they stay in the route; the driver's
    cache policy comes from the start's `use_cache`.
  - **`tick()` returns the Runs to drive** and `run()` starts their tasks, so a tick can be tested
    alone.
  - **The App's lifecycle reads its task attributes with a default**, so the two prior tests that
    build it without `install_runs` stay unchanged.
- **E4 deviations:**
  - **`RunRegistry.records(owner, run_id, indexes)`** reads the records of the named Candidates
    only, so the event stream settling one Candidate and the result route never load the whole
    Run. Spec §4.4 needs it in the docs PR.
  - **`POST /runs` answers the Run as the summary reads it**, without each Candidate's `start` or
    `record`: the Client has its starts, and the answer stays small. `GET /runs/{id}` alone
    carries them.
  - **The codes:** every 422 the routes do not name more precisely is `invalid_request`, the
    Runs-off 404 is `runs_off`, and the 413 is `request_too_large`.
  - **The event stream's closes:** a Run that is off, foreign, unknown or asked without identity
    is closed with 1008 right after the handshake, its reason the code (a close before it reaches
    the client as a bare 403); a registry that cannot say whose the Run is, 1013; `run.ended` is followed by a 1000 close; a Run deleted while followed
    closes 1008. Each frame is an object whose `type` is its name.
  - **A Candidate seen live is followed to its terminal frame**, even one that went from
    `pending` to ended between two polls; one that ended before the follower saw it settles at
    once. A terminal frame not forwarded within 30 s no longer holds its `candidate.settled`.
  - **No Origin check on the WebSocket:** Engine auth is header-borne, never a cookie
    (`cors.py`), so a page on another site cannot open the socket as the owner.
  - **The context is served as `text/plain; charset=utf-8`**; a result with the media type its
    record names, or `application/octet-stream` when that is not a plain media type.
- **E5 deviations:**
  - **The registry suites that build `RunSpec` from names stay as they are.** A Run registered
    before P2 has no starts, and the registry still holds, never orphans and settles such Runs
    (R10, R11), so `RunSpec` keeps start-less Runs. Only the route refuses a names-only body.
  - **Each start-binding test goes where its P2 version is a driver test** (at-capacity retry, a
    stopped Run takes no start, a start that loses to a stop); a test that also checked a read or
    a cancel keeps that half. `test_runs_start_never_blocks.py`, whose tests all went, is
    rewritten onto P2.
  - **The start route still answers a topic stopped before its schedule `409 run_canceled`**, the
    runner's signal that nothing ran.
  - **`schedule_run` loses `enqueued_at`**, which only the bind moment fed. The runner port keeps
    the parameter, which nothing passes now; removing it touches every runner and its fakes.
