# e14-sdk-submit — freeze the cache version, then submit with the receipt (E14, OME-1307)

## Intent

`Leaderboards.submit` (sync and async) calls the engine `POST /v1/cache-versions {"trace_id": T}` first (contract C2a),
then `POST /v1/scores` with `cache_version_receipt` and `trace_id` (plus `revision_of` and `paper_url` when given),
decodes the C4 response (`reported_result`, `reported_results_count`, `notices`), keeps the receipt for a resubmit after a
name error, and follows the C2a and C4 timeout and retry policies. A freeze failure never stops the submit: it goes on
with no receipt and the score carries `cache_version_warning`. Plan:
`docs/plan/2026-09-29-e14-reproducible-submission/SDK-submit.md`. Spec: `docs/spec/2026-09-29-e14-reproducible-submission/`
(SC-18, SC-19, SC-20; C2a, C4).

## Review fix 1 (blocking finding: the freeze can stop a submit, SC-E1)

Status: done.

- **Intent:** `EngineCacheVersions.freeze` and `AsyncEngineCacheVersions.freeze` must never raise for a failure of the
  engine request. Today they catch only `httpx.TransportError`. `httpx.DecodingError` and `httpx.TooManyRedirects`
  (`httpx.RequestError`, not `TransportError`), and the SDK `AuthenticationError` and `EngineUnavailableError` from the
  Access auth flow, leave `freeze`, so `submit` sends no `POST /v1/scores`.
- **Planned changes:**
  - `packages/screamingface/src/screamingface/_engine/cache_versions.py`: after the `TransportError` branch (retry
    kept), catch `httpx.HTTPError`, `AuthenticationError` and `EngineUnavailableError` in both twins, return a fixed
    token, no retry. Not `BaseException`, not `CancelledError`.
  - `packages/screamingface/tests/test_submit_cache_version.py`: new SC-19 rows (append only), sync and async.
  - This ledger.
- **Reason vocabulary** (each matches `^[a-z0-9_]{1,64}$`): `timeout`, `unreachable` (transport error, other
  `httpx.HTTPError`, `EngineUnavailableError`), `engine_auth_failed` (`AuthenticationError`), `no_trace`,
  `invalid_response`, `http_<status>`, and a safe server `code`.
- **Test plan:** SC-19 rows `decoding_error`, `too_many_redirects`, `engine_authentication_error`,
  `engine_unavailable_error`: submit still POSTs, no receipt, no `trace_id`, warning
  `cache_version_unavailable: <token>`. One test: those failures make exactly one engine call (no retry). RED first.
- **Acceptance:** new rows fail on the current code, pass after the fix; all prior tests unmodified and green; gates green.
- **Outcome:** files as planned: `_engine/cache_versions.py` (`_UNRETRIED` tuple and `_unretried_failure`, used in both
  twins; the `TransportError` retry branch is unchanged), `tests/test_submit_cache_version.py`, this ledger.
  RED: 16 of 16 new cases (4 rows x 2 modes submit-and-warn, 4 cases x 2 modes no-retry) failed on the old code because
  the exception left `freeze` (`httpx.DecodingError` etc. raised from `submit`, no `POST /v1/scores`). GREEN: all pass.
  Gates: `run_gates.py screamingface --base HEAD` (append-only check on, no skip) -> ALL GATES GREEN.
- **Deviations:** (1) The new rows are in a second table `_PARAMS_SC19_NOT_TRANSPORT` with its own test, not inserted into
  `_PARAMS_SC19`: the append-only gate rejects an insert into an existing table. (2) Gates ran against `--base HEAD`
  (this fix only) so the approved snapshot exception (a) is not needed. (3) `EngineUnavailableError` and other
