## Frozen-copy rework (2026-10-08)

The owner replaced the cache-revision design with a frozen copy (spec
`02-frozen-copy-design.md`, plan `F-C1-docs.md`). The sections above describe the first C1 and
are history. This section is the current state. Base: `e14-b5-sdk-reproduce` (final B5 code in

`guides/EvaluationPage.vue` by the design review.

- **Intent:** the public docs and the glossary say only what the final code does.
- **Changed files:** `CONTEXT.md`, and in `public-docs/src/pages`: `learn/CachingPage.vue`,
  `learn/LeaderboardPage.vue`, `learn/Url4Page.vue`, `sf-client/guides/LeaderboardsPage.vue`,

  `sf-client/api/ClientsPage.vue`, `sf-client/api/ModulesPage.vue`. No other file.
- **Where the text lives:** the full mechanics are on the caching page (capture, the seven partial
  reasons, local runs, replay, why a replay fails). The reason table of `sf.reproduce` is on the
  API leaderboards page. Every other page has one or two sentences and a link.
- **Glossary:** Cache Revision and Reproducible are gone. Frozen Copy, Capture Status and
  Reproduction are short definitions in the style of their neighbours. `CandidateResult` carries
  the status too.
- **Facts the pages state** (code: `capture_outcomes.py`, `connector.py`, `web_tools.py`,
  `_reproduction.py`, `_evaluation/url4.py`, `_runtime/server.py`)
  - `sf.evaluate(..., capture=True)` stores every model answer (cache hit or live call, judges
    included) and every web-tool result as the tool returned it (before the Engine cuts it to
    length), forever. Capture is best effort and adds no provider call.
  - `partial` reasons: `open` (no copy id), `seal` (also a cancelled run, which is never sealed),
    `failed`, `refused`, `missing` (an older gateway, or a gateway refusal before the copy check),
    `error` (forgiven by a later stored call of the same request), `ambiguous`. A provider error
    that the gateway stored does not make a run partial.
  - Local runs: the local runtime starts a real AI gateway with its own SQLite database. A local
    capture can be `complete`, but its copy lives only in that gateway. Only the same local setup
    can replay it. A hosted reproduction gets `frozen_copy_unavailable`. Uploading a local copy is
    a planned follow-up.
  - Money: a confirmed replay pays no provider and no web-search service. An Engine that does not
    confirm replay mode at the start is stopped and reported `replay_unsupported`, with an
    `EvaluationWarning` when the stop fails. A finished run whose summary does not name the copy
    is reported `replay_unsupported` too (it may have paid providers) and not as a replay.
  - `frozen_copy_unavailable` also covers a web-tool lookup that the gateway did not answer
    (transport failure or a non-404 error).
  - A failed replay is not proof against the score and not a confirmation either (known limits:
    same request with different answers, a different web-tool set).
  - Any authenticated gateway account that holds the copy id can read a stored answer for the
    exact request (Q16).
  - `answer_seed` and `capture` are on the `evaluate` signatures and tables of the Clients,
    Modules and Evaluation pages. `reproduce()` is on the Clients and Modules pages and in the
    AsyncClient awaited list. `CandidateResult.answer_seed` is documented.
