## Frozen-copy rework (2026-10-08)

The owner replaced the cache-revision design with a frozen copy (spec
`02-frozen-copy-design.md`, plan `F-C1-docs.md`). The sections above describe the first C1 and
are history. The text of this section is the current state. Base: `e14-b5-sdk-reproduce`
(final B5 code in this checkout).

- **Intent:** the public docs and the glossary say only what the final code does.
- **Changed files:** `CONTEXT.md`, and in `public-docs/src/pages`: `learn/CachingPage.vue`,
  `learn/LeaderboardPage.vue`, `sf-client/guides/LeaderboardsPage.vue`,
  `sf-client/guides/Url4Page.vue`, `sf-client/api/LeaderboardsPage.vue`,
  `sf-client/api/CandidateResultPage.vue`. No other file.
- **Glossary:** Cache Revision and Reproducible are removed. Frozen Copy and Capture Status are
  new. Reproduction now means a replay against a Frozen Copy.
- **What the pages now say**
  - `sf.evaluate(..., capture=True)` makes a frozen copy: every model answer (cache hit or live
    call, judges included) and every web-tool result, kept forever. Capture is best effort and
    adds no provider call.
  - `CandidateResult.frozen_copy_id` and `capture_status` (`None` means unknown, not partial).
    An `EvaluationWarning` follows a `capture=True` run that the Engine did not capture.
  - Why a run is `partial` (code: `capture_outcomes.py`): `open`, `seal`, `failed`, `refused`
    (a streaming call is never stored), `missing` (older gateway), `error` (forgiven by a later
    stored call of the same request), `ambiguous` (a `max-age` re-issue or a retried transport
    attempt). A provider error that the gateway stored does not make a run partial, and the
    replay gives the same error.
  - Money: a confirmed replay pays no provider and no web-search service. An Engine that does
    not confirm replay mode at the start is stopped and reported `replay_unsupported`, with an
    `EvaluationWarning` when the stop fails. When the start was confirmed but the finished
    run's summary does not name the copy, the run is already over, may have called providers,
    and is reported `replay_unsupported` and not as a replay (`_require_replay_statement`).
  - Reasons of `sf.reproduce` in check order: `partial`, `unknown`, `replay_unsupported`,
    `frozen_copy_miss`, `frozen_copy_unavailable`, `run_failed`, `benchmark_revision_changed`,
    `score_differs`.
  - Known limits (design §9): same request with different answers served in capture order,
    parallel branches can swap them; a web-tool set that differs between run and replay; a local
    Engine with no gateway cannot open a copy (Q14); the copy id is public with the score and
    Q16 allows anyone with the id to read a stored answer for the exact request.
- **Left out on purpose:** gateway routes and headers, and the engine and SDK start headers.
  The client pages name only SDK calls and result fields.
- **Gates (public-docs):** `npm ci` exit 0. `npm run build` exit 0 (vue-tsc, then vite:
  "1889 modules transformed", "built in 699ms"). `npm run lint` exit 0 (oxlint: no output;
  ESLint: "No issues found"; no file changed by auto-fix). `prettier --check` on the six touched
  pages: "All files formatted correctly". No other test exists in `public-docs`.
- **Greps:** no match for cache-revision, `only-if-cached`, `cache_revision`, `unknown_cache_revision`

  outcome name `not_reproducible`, two older English uses on `sf-client/Index.vue` and
