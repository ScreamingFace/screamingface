# e5-p2-client — E5 P2 Client: follow a Run, detach, reattach and report anywhere

## Intent

The Client half of E5 P2 (`OME-1837`): the Client sends the whole evaluation once (`POST /runs`
with every Candidate's start and a context), follows the Run on one WebSocket, and builds the
Report from the Engine's records and results. It never starts a Candidate. `sf.evaluate(...,
detach=True)` returns a `Run` at once; `Run.wait()` and `Run.report()` work from any machine.
Spec `docs/spec/2026-11-04-e5-p2-detached-run.md` (§4.1, §4.2, §4.3, §4.6, D13 to D16) and plan
`docs/plan/2026-11-04-e5-p2-detached-run.md`, Client PR, C1 and C2 (docs PR #1747). The Engine
half is PR #1759; this PR merges after it is deployed.

Stacked on #1759 (branch `OME-1895-e5-p2-engine`, owner decision 2026-11-14): the Client's
tests read the Engine's recorded runs (`apps/screamingface-engine/tests/fixtures/candidate_runs`)
and the end-to-end check needs its routes. Rebased onto `main` once #1759 merges; the PR opens
then.

## Test plan

Written before the code, per the plan's C1 and C2 test lists and the spec's §6 Client row:
the recorded runs give the same `_RunOutcome` through the Engine's record; a queued Candidate
shows as queued; 256 Candidates are followed without a thread each; declared result order,
first-settled completes first, a failed Candidate's row while its sibling runs; an abort or
Ctrl-C sends one `DELETE /runs/{id}`; a large result is re-fetched from the result route and a
pre-P2 manifest still redeems its ticket; `on_event` gets every event in order per Candidate;
an older Engine raises the upgrade message and Runs off the Runs-off message; the D15 message;
a reconnecting follower delivers no event twice; a context whose checksum does not match is
refused; `detach=True` returns at once; `Run.wait()` and `Run.report()` on a second machine give
a `Report` equal field by field to an attached run's; `deadline` without `detach` raises.
