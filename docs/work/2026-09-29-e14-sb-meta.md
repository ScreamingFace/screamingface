# e14-sb-meta — edit submission metadata: authors and paper URL (E14a)

## Intent

Let the owner of a public-board submission edit `authors` and `paper_url` after submit, with
optimistic concurrency (`If-Match` / `ETag` on `metadata_revision`), an event history in the same
transaction, and a coded error body. Content identity (`content_hash`, score, rank) never changes.
Adds `paper_url` to the submit payload and to the leaderboard/history read DTOs, and renders a safe
paper link in the portal. Plan: `docs/plan/2026-09-29-e14-reproducible-submission/SB-meta.md`.

## Design notes

- OD-M7 (b): `paper_url` is on `RankedLeaderboardEntry` and `HistorySubmission` only. The ranked
  board fills it with one extra read of the ranked ids inside the same `read_snapshot()`
  (`ScoreStore.paper_urls_for_score_ids`, chunked like `models_for_score_ids`). So the plan's
  "both selects of `_build_leaderboard_query` add `paper_url`" and "`list_owned_entries` passes
  `paper_url`" were NOT done: `LeaderboardStoreEntry` splats a raw row into a model that has no
  such field. `my_submissions` (a private board's own rows) therefore carries no `paper_url`.
- `ScoreMetadataPatch` lives in `schemas.py` (the plan names no file for it); `_EDITABLE_FIELDS`
  and the route helpers live in `routes/score_metadata.py`.
- History responses follow `get_score` (changed in review round 1): the store returns a
  `MetadataHistoryPage` with the decision (`private`, `benchmark_id`); the route marks
  `PRIVATE_CACHE_HEADERS` only when the board is private, else `turned_private` is the last await
  before a public answer and a flip gives the plain 404.
- `GET /v1/scores/{id}` returns the stored `authors` as it is (null when the row has none); only
  `_score_to_schema` derives `[submitted_by]`. The plan's MD-13 says GET shows the derived value;
  it does not, and this unit does not change GET (`routes/scores.py` is not in the plan). MD-13
  asserts the derived value on the PATCH response and on the board instead.
- Served portal files must hold no ticket id, `FEATURE:`/`INVARIANT` anchors or `.py` paths
  (`test_every_served_asset_carries_no_internal_references`), so the two portal edits use plain
  prose comments.

## Review fixes, round 1 (PLANNED)

Four blocking findings from the design review; two describe one defect (history read leaks after a
visibility flip), so there are three fixes.

- F1/F4 (history leak): `metadata_history` returns a `MetadataHistoryPage(events, next_revision,
  benchmark_id, private)` with the DTOs already mapped. The route copies `get_score`: set
  `PRIVATE_CACHE_HEADERS` only when `private`, else `turned_private(benchmark_id)` is the last
  await before the response and a flip answers the plain 404. Tests: a flip between the visibility
  read and the events query answers 404 with the private headers (anonymous and non-owner); an
  identified read of a public board carries no private header.
- F3 (weak test): a store-level test replaces `metadata_store._lock_row` so the row goes stale
  after the read; the conditional `UPDATE ... WHERE metadata_revision` must lose, raise
  `MetadataRevisionConflict` with the current state, write no event, and leave the values.
- F2 (registry edit): the `metadata_history` rows in `EXPECTED_UNGUARDED` shrink to what stays
  true; the `update_metadata` rows stay. Plan gap recorded in plan SB-meta.md section 7.1.
  The remaining registry edit needs the user's approval, which this round does not have. See
  Outcome of this round.
