## Deviations

- tortoise-dev waived by the user for E14 (2026-09-29). This unit has no model and no migration.
- D-1. `edge_client` also passes `run_transport=` (plan 4.2 gives `http_transport` and
  `scoreboard_transport` only). WHY: `Url4CloudTransport` builds its OWN httpx client for the run
  start request (`GET /?q=`), so `Client(http_transport=...)` never reaches it. The run then left
  with no `X-User-Email`, and every model call got `aigateway_http_401` (Step 2 STOP check). The
  engine forwards the header correctly (it is not an engine defect). Fix, in the harness only:
  `identity.py` `_EdgeRunAuth` (an httpx auth that sets the header) passed to
  `Url4CloudTransport(engine_url, auth)`, the seam `tests/test_reconnect_handshake.py` uses. It
  imports two private SDK modules (`screamingface._access.base`, `screamingface._engine.transport`).
  A new public function `edge_run_transport(engine_url, user)` exists for the RED proofs.
- D-2. `CacheSeededGateway` in `cloudflare_headers` mode also sets `AIGATEWAY_ADMIN_PASSWORD` to a
  fixed throwaway value. WHY: an authenticating gateway creates the bootstrap `admin` account at
  first boot and refuses to start without a password (`bootstrap_admin.py`). It is not a provider
  key and not `AIGATEWAY_SECRET_KEY`. The plan does not name it.
- D-3. New helper `e14_candidate(golden, *, name, max_rounds)` in `harness/e14_stack.py`. SC-23,
  RP-21, MD-21 and PB-22 use it instead of `build_candidate(golden)` (plan 4.7). WHY:
  `build_candidate` names the loop `openrouter/...+openrouter/...`, and a submit of that name is
  `422 invalid_system_name` (pattern `a-z0-9._-`). Only the name changes, the model requests are
  the recorded ones (SC-23 and RP-21 pass with all-hit replay, so the snapshot still serves them).
  RP-22 uses the same helper with the plan's `name="e2e-kevins-best"`.
- D-4. RP-22 is SKIPPED (hard rule 1 of the orchestrator, and plan Step 6 STOP). See "Open items".
- D-5. Step 2 scratch run used `limit=50` (not `limit=1`): a one-case run may sample a case that is
  not in the 50-case snapshot. Result: score 0.9184, cost_usd 0, one `model_token_cap` case (same
  as the golden).
- D-6. `GET /v1/benchmarks` has no `redistributable` field (`BenchmarkSchema`), so plan 4.3 step 5
  "assert the board shows redistributable" is replaced by the check of the admin route response
  (`redistributable is true`, 2xx). The route is the WIRING route.
- D-7. PB-22 reads `E14_SANDBOX_APP_INSTALLATION_ID` too: the scoreboard needs App id, installation
