## Recording the lane (the user runs this; the implementer never did)

The lane SKIPS loudly until three fixture files exist. They come from ONE paid run and one free step.

**Prerequisites:** an OpenRouter key; a docker daemon; network (the GSM8K download from Hugging Face
needs no token); a model whose `seed` parameter the gateway publishes and the provider accepts (the
`record` step refuses before any spend otherwise); `uv`.

**Cost:** `limit * samples` short calls: 20 cases x 5 samples = 100 calls, well under $0.10, 5 to 15
minutes. `bless` and the replay are free and keyless.

Commands, from `packages/screamingface`:

```
(cd ../../apps/screamingface-engine && uv sync --extra benchmarks && \
  uv run python -m screamingface_engine.benchmarks.prepare \
    --root ~/.screamingface/benchmark-assets --bundle inspect-gsm8k)
export OPENROUTER_API_KEY=...   SCREAMINGFACE_RECORD_PAID=1
uv run python tests/e2e/fixtures/reducer_lane.py record \
    --model openrouter/<seed-capable-model> --samples 5 --temperature 0.7 --limit 20 \
    --out ~/sf-recordings/gsm8k-vote
uv run python tests/e2e/fixtures/reducer_lane.py bless --recording ~/sf-recordings/gsm8k-vote
SCREAMINGFACE_TEST_E2E=1 SCREAMINGFACE_E2E_ASSETS=~/.screamingface/benchmark-assets \
    uv run pytest tests/e2e/test_reducer_replay.py -rs -v
```

Then commit the three files in a follow-up commit:
`tests/e2e/fixtures/snapshots/inspect-gsm8k-vote.snapshot.gz`,
`tests/e2e/fixtures/snapshots/inspect-gsm8k-vote.manifest.json`,
`tests/e2e/fixtures/goldens/inspect-gsm8k-vote.reducer-golden.json`.

The just recipes `e2e-record-reducer-lane <model> --out <dir>` and `e2e-bless-reducer-lane <dir>` call the
same two steps. `record` is a paid step and asks for a confirmation.

What each step does and refuses:

- `record` refuses without `SCREAMINGFACE_RECORD_PAID=1`, `OPENROUTER_API_KEY` and docker. After the key
  is connected, it refuses before any spend unless `models.get(model).parameters["seed"]` is published,
  enabled and not `unsupported`. It writes `report.json`, `candidate.json` and `cache.sql.gz` into `--out`.
  The key is read from the environment and goes to the gateway only through `client.connect`; it is never
  written to disk, and the engine child gets a scrubbed environment.
- `record` also writes `recording.json` (the requested `limit`). `bless` refuses a recording whose board is not
  `inspect-gsm8k`, whose kind is not `fusion`, or whose limit differs from its case count.
- `bless` replays the recording with NO key and refuses unless the board, the url4, the case statuses, the
  score, the coverage, the failure codes and the combine evidence all equal the saved report, and the golden
  passes its own evidence lock. It refuses a snapshot above 5 MB.
