# e14-simplify — behaviour-preserving cleanup across the E14 stack

## Intent

A `/simplify` pass over the whole E14 stack (#1158–#1181). It covered reuse, simplification,
efficiency and altitude. The pass removes duplicated helpers. It takes CPU and parse work off the
event loop on the freeze, export and publish paths. It removes redundant queries and hashing. No
behaviour, wire contract, schema or message text changes. It was first built as two commits on
top of the stack. The user then chose to fold every change into the stack PR that owns the code.
See "Where each change landed" below.

## Where each change landed

The rule: a change goes into the LAST stack PR that touches its file, so no later PR has to be
rebased over it. A file the stack never touched goes into the FIRST PR that needs it. A PR never
uses a symbol that only a later PR adds.

## Second pass (2026-10-06): the three structural refactors

Each one followed the same flow:
1. An Opus planning agent wrote the spec.
2. A Sonnet implementer built it.
3. An Opus design review gave ACCEPT-WITH-FIXES, with no STRUCTURAL finding.
4. One fix round followed.

- **Gateway chat route.**
  - The stages return one `ChatAnswer`.
  - Capture is recorded ONCE at the route exit, through the pure, total
    `capture_outcome(answered_by, cache_status, write_status)` (`match` plus `assert_never`).
  - All headers come from `_answer_headers`.
  - `_render_answer` is a `match` on `answered_by`.
  - `_stored_answer` serves both hit paths.
  - Removed: `_serve_version_hit`, `record_answer` and `set_global_cache_headers` (no callers).
  - Behaviour changes, both on paths that cannot be reached today:
    - X7d now writes an `unstored` row, where it used to write none.
    - A render failure after capture no longer adds a second `error` row. The rule is one row per
      call.
  - New tests: `test_capture_outcome.py` (73) and `test_chat_exit_table.py` (17). The exit table
    passed on the old code before the refactor, then on the new code.
- **Gateway freeze serialization.**
  - Request, response and metadata are each canonicalised at most once per freeze.
  - The stored prompt is spliced as is, but only when `sha256(prompt) == key_hash`. Otherwise it is
    parsed and rendered.
  - Blob digests and archive lines are composed by `canonical_compose` (internal, in
    `canonical.py`) from canonical member texts.
  - `CanonicalJson` and `CanonicalEntry` are new. Lines are rendered lazily.
  - The exporter passes the stored texts through and never parses them.
  - Archive bytes are byte-identical. This is pinned by a golden uncompressed-lines digest
    recorded on the old code, by blob digests, and by a same-run comparison with a reference
    writer. The gzip digest is not pinned, because it depends on the zlib build.
  - Behaviour change on error paths only: a NaN, an encode failure or an empty stored metadata
    used to crash the freeze. Now the call is counted as missing, or the metadata becomes None.
  - New tests: 5 files, including a Postgres determinism twin, which was not run locally.
- **SDK sync/async twins.**
  - New sans-IO `_core/attempts.py` (`drive_sync`/`drive_async`, `_Again`/`_Done`).
  - New `_scoreboard/calls.py` (`_ScoreboardCall`, `_Resend`, `settle`, `call_sync`/`call_async`).
  - Every Scoreboard twin in `leaderboards.py` (1379 → about 1160 lines) is now one line over a
    pure builder.
  - `_freeze_step` covers the engine freeze. `replay_pin` replaces `prepare_replay_sync/async`.
  - Retry counts, backoff, causes and logs are unchanged. The review checked every method against
    HEAD.
  - New tests: 4 files, about 99 tests.
  - Left out of scope: the `_engine/catalog.py` twin. It predates E14 and has no retry loop.
- **Gates:** ALL GATES GREEN for aigateway and screamingface. The full aigateway unit suite passed
  (5429).
