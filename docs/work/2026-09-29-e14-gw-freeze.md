# e14-gw-freeze — freeze, signed receipt and bucket archive (OME-1307, E14b, wave 2)

## Intent

GW-capture (wave 1) records every traced call. This unit turns one captured trace into an
immutable cache version: `POST /v1/cache-versions` copies the full request and response of each call
into `cache_version_*` rows, returns an EdDSA-signed receipt (contract C3), and an outbox exporter
writes a canonical `entries.jsonl.gz` and `manifest.json` pair to a bucket or a directory (C8a).
The plan is `docs/plan/2026-09-29-e14-reproducible-submission/GW-freeze.md`. Component:
`apps/aigateway` only. No migration (the tables come from GW-capture `0013`).

## Review fixes (blocking findings, 2 reviewers, same defect)

- Finding: `run_once` read the oldest `batch_size` frozen versions, then skipped those in backoff.
  Ten stuck versions (digest mismatch) filled every batch, so no newer version was archived. An
  exception outside `(ArchiveStoreError, OSError)`, or a failing `mkdtemp`, aborted the whole pass.
- Fix: `ExportStore.list_frozen(limit, exclude=())`; the Tortoise adapter adds `id__in` exclusion;
  `run_once` passes the ids whose backoff is still in the future. `_export` opens the spool inside
  the `try` and catches `Exception` per version (counted in `export_failures`, backoff, type-only log).
- RED (before the fix, 3 failed): 11 mismatching versions + 1 good (good stayed `frozen`);
  `load_archive_entries` raising `ValueError` on the oldest version (next version not exported);
  `mkdtemp` failing on a missing spool root (`FileNotFoundError` escaped `run_once`).
  GREEN after the fix. Added an adapter test for `exclude` on a real database.
- Gates after the fix: append-only, ruff check, ruff format, pyright, check_no_enterprise green;
  pytest 5143 passed, coverage 93.2 %. One failure: `tests/unit/auth/test_login.py::
  test_unknown_user_timing_close_to_wrong_password` (a timing test; host load average about 17;
  it does not touch this unit; standing exception (d)). The new exporter tests and all of
  `tests/unit/cache_versions` pass (139).
- Test double change: `_FlakyStore.list_frozen` got the new `exclude` parameter (signature only; its
  assertions are unchanged), because the port signature changed.
