# OME-1177 — strip new LiteLLM 1.100.0 dynamic callback params

## Intent

`packages/screamingface[runtime]` bundles `apps/aigateway`'s source and runs it under its own
(newer) dependency resolution — not aigateway's own pinned lockfile. GitHub PR #858 bumps
litellm 1.98.0 → 1.100.0 in that bundling package. litellm 1.100.0 adds three new dynamic
callback params (`langfuse_environment`, `newrelic_api_key`, `newrelic_region`) to
`initialize_dynamic_callback_params._supported_callback_params`. aigateway's
`_CALLBACK_DYNAMIC_FIELDS` allowlist (in `request_hardening.py`) does not yet strip them, so a
caller could set these fields on a request body/metadata to redirect prompt/response telemetry
to a host/account of their choosing — the same exfiltration class as the existing
langfuse/langsmith/arize/braintrust/datadog fields already stripped there. This blocks PR #858
until fixed.

Near-exact precedent: `docs/work/2026-08-04-OME-735-aigateway-deps-pyjwt.md` — the 1.87→1.95
litellm bump surfaced 4 missing Datadog callback fields via the same mechanism
(`test_litellm_dynamic_callback_parameter_set_is_covered`). This unit follows the same
gate/test/verification flow.

## Root cause

Verified directly (per the Linear issue body): diffed
`litellm.litellm_core_utils.initialize_dynamic_callback_params._supported_callback_params`
between litellm 1.97.0 (26 params) and 1.100.0 (29 params) — exactly
`langfuse_environment`, `newrelic_api_key`, `newrelic_region` added, matching litellm's
changelog ("feat(newrelic): per-team New Relic trace routing via team callbacks").
`test_litellm_dynamic_callback_parameter_set_is_covered` asserts
`litellm's _supported_callback_params <= DISPATCH_CONTROL_FIELDS`, so it fails against the
bumped litellm as written — that is this unit's reproducible RED.
