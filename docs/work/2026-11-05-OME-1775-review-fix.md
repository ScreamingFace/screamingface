# OME-1775 — require evidence before forgiving cancelled calls

## Intent

Fix PR #1616's blocking review: a temporary failure in a data mount or outbound source
must not make an incomplete frozen copy look complete. The user requested the fix and merge.

## Planned changes

- Restrict R1 to failed cases whose failures are positively supported by a stored,
  deterministic model-token-cap response; unknown failures stay strict.
- Require matching case/attempt evidence, keep timeout, ambiguity and retry guards.
- Add a real-executor regression with a recovering data source and optional cancelled model.
- Update the spec, plan and tests that encoded the overly broad rule.
- Resolve current-main conflicts without losing either branch's changes.

## Test plan

First reproduce the reviewer scenario with a failing assertion on capture status.
Test unknown/transient failures, missing proof, other attempts, and deterministic captured
failures. Run the engine and gateway gates; no paid or production execution.

## Acceptance

The recovering-source scenario stays partial. The captured token-cap sibling-cancellation
scenario still completes and replays the failed case. Required CI and review requirements
must pass before merge; no Linear or production-data edits in this work.
