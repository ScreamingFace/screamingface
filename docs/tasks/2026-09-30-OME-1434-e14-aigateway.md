# Capture, freeze and replay E14 cache versions in the AI Gateway

E14 in `apps/aigateway`: call capture, cache versions and replay.

- **Capture (GW-capture):** migration 0013 (5 tables), a thin run index per traced call, and one prompt per cache key, kept forever (Q18).
- **Freeze (GW-freeze):** `POST /v1/cache-versions` makes an immutable, content-addressed version, a signed EdDSA receipt and the bucket archive (canonical gzip).
- **Replay (GW-replay):** the grant verifier and the STAGE 0 version lookup. A miss falls through to the live provider, and `X-AIGW-Cache-Version` is `hit` or `miss`.
- **Chart wiring (from WIRING):** the flag, the bucket, the keys and the Secret templates.

Tests: CV-1..CV-28 and RP-5. The gates are green. One existing migration test is pinned to its own target (an approved append-only exception).

Spec: `docs/spec/2026-09-29-e14-reproducible-submission/`. Plans: `docs/plan/2026-09-29-e14-reproducible-submission/` (decisions D1-D8, Q19-Q30). All E14 units ship in one PR, and each component has its own leaf (CLAUDE.md: one sub-issue for each app or package).
