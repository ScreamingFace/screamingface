# Close the PR #930 review round 2 findings (cache entry metadata)

The second review of PR #930 requested changes with seven findings, reviewed at head `f06e9ec`
against main `c9c6761`. All seven were checked against the code and all seven are real. CI is
green and the tree is mergeable, so these are uncovered edge cases rather than failing tests.

Three high findings: a pre-0011 binary can pair a new response body with the previous body's
cost block (rolling upgrade or rollback); migration 0011's `ADD COLUMN` can queue every cache
read behind a snapshot export holding a conflicting lock for up to 600 s; and a transport retry
whose first attempt was billed reports cost `0` plus a saved cost equal to the money just spent.
Two medium findings cover a count that races with concurrent cache fills and a Decimal
accumulation that rounds under the ambient context. One medium covers the unvalidated `url4`
saved-cost seam, and one low covers a stale generated TypeScript schema.

Finding 3 is the reason this is priority 2: it is the only one that makes the feature state
something false rather than merely incomplete.

Cross-cutting across `aigateway`, `screamingface-engine` and `packages/url4`, filed as one item
following the OME-1155 precedent — the findings share one cause and one acceptance test, so
splitting them would create items that can only close together. Label groups are single-select,
so `aigateway` is the landing label.
