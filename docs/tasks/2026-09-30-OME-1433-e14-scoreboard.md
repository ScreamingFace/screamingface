# Build E14 reproducible submissions in the scoreboard

E14 in `apps/scoreboard`: each leaderboard submission becomes a reproducible research artifact.

- **Schema (SB-schema):** migrations 0017-0019: `ReportedResult`, `System`, `SystemRevision`, `ScoreMetadataEvent` and `CacheVersionPublication`, the `Benchmark.redistributable` column, and a backfill of one original result per score. The FK columns use the native Tortoise names (D8).
- **E14a metadata (SB-meta):** `PATCH /v1/scores/{id}` with If-Match/ETag for authors and `paper_url`, plus the edit history.
- **System registry (SB-registry):** global names, revisions and the url4 fingerprint, plus the `backfill_systems` command.
- **Submit and cluster (SB-submit):** it verifies the gateway receipt, clusters by system revision (the original result ranks), and stores the replay provenance.
- **Replay grants (SB-grants):** pins by result, name, revision or date, and EdDSA grants with a 12 h life.
- **Publish and takedown (SB-publish):** the GitHub release worker (outbox and lease) and the admin withdraw.
- **Wiring (the scoreboard part):** the admin route that sets `redistributable`, and chart values for `cloudflare_headers` in prod (D5).
- **Final-check fixes:** FS-1, X-SEC-1, MRA-1 and MRA-2.

Tests: SR-1, SR-6..SR-20, MD-1..MD-18, MD-20, SC-1..SC-17, SC-22, RP-1..RP-4, RP-6..RP-10 and PB-1..PB-20. The gates are green.
