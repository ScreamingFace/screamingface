# Deliver the recommended URL4 Log capability

Prerequisite: approve [the revised spec](../spec/2026-09-09-OME-934-log-seam.md) and the cross-package issue split. Keep draft PR 876 as design review only. Implementation starts in separate worktrees from updated origin/main after design approval; no old PR commits are imported.

1. **Allocate ownership.** Amend OME-934's current Engine-only factory scope for Engine attribute forwarding and the targeted bridge admission/eviction correction; create a separate URL4 package issue under the agreed cross-cutting parent and set the real dependency. Do not code both landings under one issue. OME-1161/1135/932/699 retain their producer/consumer responsibilities.
2. **URL4 tests first.** Add tests in the observation suite for optional attributes, safe node-scoped emission, direct-log compatibility, validation, immutable snapshots, expiry (including fresh accessor calls in expired child contexts), observed/unobserved nesting, threading, cancellation and observer failures. Pin DEBUG/INFO/WARN/ERROR, strip/uppercase normalization and rejected aliases. Test mutation through both the caller mapping and the observation. Include no-observer and import-isolation cases. No production changes before the package ledger/spec/plan and failing tests.
3. **URL4 implementation.** Extend `observe.py::Log`, add the sink interface/current accessor, and bind it in `dag/executor.py` through an explicit callable from `dag/node.py`. Keep all domain semantics and framework dependencies out. Document the distinction between safe producer emission and existing direct observer failure behavior. Run `uv run .claude/scripts/run_gates.py url4` in its worktree.
4. **Engine forwarding and safe buffering tests first.** Verify structured attributes and the existing span survive `_log_frame`, lifecycle sequencing and serialized wire Logs. Correct Log admission/eviction at either soft or hard capacity, counting all losses and evicting enough buffered Logs for authoritative events. Add paired lifecycle regressions with/without optional Logs, including hard-cap-below-soft-cap configuration: both succeed with identical authoritative outcomes. Separately preserve authoritative-only overflow. Use a small generic endpoint producer rather than a Benchmark adapter; avoid a broader bridge rewrite. Run `uv run .claude/scripts/run_gates.py screamingface-engine` after forwarding and the targeted buffering correction.
5. **Compatibility and downstream delivery.** Verify existing Client wire decoding without SDK changes. If a Client contract change proves necessary, stop and allocate its own landing. OME-1161 separately designs model-activity records with concrete record-size/rate limits before shipping; OME-1135 renders them. OME-932 separately designs evaluation-scoped lifecycle, typed terminal observations and canonical grader/scorer integration: deduplicate terminals, emit cumulative snapshots, recover from dropped updates and reconcile the final result. It chooses its own setup/teardown interface. Exact semantic grouping remains OME-699.
6. **Review and close.** Keep implementation PRs draft until the owner explicitly requests readiness. Review package and Engine changes separately; retain full gates and required approvals before squash merge. Close each implementation issue with its commits, gates, ledger and mirror. Merging these design documents alone closes none of the delivery work.

The scratch probe establishes feasibility only. Its monkeypatches and private-context access must not be copied as production interfaces. Saved-error propagation is excluded from this plan.
