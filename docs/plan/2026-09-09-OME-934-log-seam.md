# Deliver the recommended URL4 Log capability

Prerequisite: approve [the revised spec](../spec/2026-09-09-OME-934-log-seam.md) and the cross-package issue split. Keep draft PR 876 as design review only. Implementation starts in separate worktrees from updated origin/main after design approval; no old PR commits are imported.

1. **Allocate ownership.** Amend OME-934's current Engine-only factory scope for Engine attribute forwarding; create a separate URL4 package issue under the agreed cross-cutting parent and set the real dependency. Do not code both landings under one issue. OME-1161/1135/932/699 retain their producer/consumer responsibilities.
2. **URL4 tests first.** Add tests in the observation suite for optional attributes, safe node-scoped emission, direct-log compatibility, validation, immutable snapshots, expiry, inheritance, threading, cancellation and observer failures. Include no-observer and import-isolation cases. No production changes before the package ledger/spec/plan and failing tests.
3. **URL4 implementation.** Extend `observe.py::Log`, add the sink interface/current accessor, and bind it in `dag/executor.py` through an explicit callable from `dag/node.py`. Keep all domain semantics and framework dependencies out. Document the distinction between safe producer emission and existing direct observer failure behavior. Run `uv run .claude/scripts/run_gates.py url4` in its worktree.
4. **Engine forwarding tests first.** Verify structured attributes and the existing span survive `_log_frame`, actual bridge pressure, lifecycle sequencing and serialized wire Logs. Use a small generic endpoint producer rather than a Benchmark adapter. Pin original default/error/Span/cost behavior. Run `uv run .claude/scripts/run_gates.py screamingface-engine` after the minimal forwarding change.
5. **Compatibility and downstream delivery.** Verify existing Client wire decoding without SDK changes. If a Client contract change proves necessary, stop and allocate its own landing. OME-1161 then adds approved model activity; OME-1135 renders it. Exact semantic grouping and provisional scoring remain separate.
6. **Review and close.** Keep implementation PRs draft until the owner explicitly requests readiness. Review package and Engine changes separately; retain full gates and required approvals before squash merge. Close each implementation issue with its commits, gates, ledger and mirror. Merging these design documents alone closes none of the delivery work.

The scratch probe establishes feasibility only. Its monkeypatches and private-context access must not be copied as production interfaces. Saved-error propagation is excluded from this plan.
