## 2. Steps common to every leaf

1. **Worktree.** `git fetch origin`, then
   `git worktree add .claude/worktrees/<slug> -b <slug> origin/main`. For Python stacks, run
   `uv sync --locked` in the touched project. Nothing is edited in the shared checkout.
2. **Ledger first.** `docs/work/2026-MM-DD-<slug>.md` from `docs/work/TEMPLATE.md` with
   `ticket: unfiled`, Intent, Planned changes, Test plan and Acceptance. L4a and L7 also copy their
   leaf spec and plan into `docs/spec/` and `docs/plan/`. The first leaf to land also carries the
   close-out spec and plan.
3. **Baseline.** The focused suites of the touched area pass on the fresh worktree.
4. **RED.** New or changed tests fail for the stated reason before any production change. A prior
   test changes only when §3 lists it, and it goes into the manifest.
5. **GREEN.** Make the minimal change, then run the full stack suite. Retries are bounded at 10 per
   failing signal; at the 10th, stop with a loop diagnosis.
6. **Comments.** New comments use only the `WHY` / `INVARIANT` / `FEATURE` / `STORY` anchors.
7. **Gates.** From the repo root, run `uv run .claude/scripts/run_gates.py <stack>`:

   | Leaf | Stack |
   |---|---|
   | L2, L11 | `repo` |
   | L4–L7a, L9, L10 | `aigateway` |
   | L9 | `aigateway-ui` |
   | L6b, L8 | `screamingface` |
   | L6c, L7b | `screamingface-engine` |

   `needs_postgres` suites run where §3 says, with the PostgreSQL 16 client first on `PATH`:
   `AIGW_TEST_PG=1 uv run pytest -m needs_postgres` from `apps/aigateway`.
8. **Review.** An independent read-only review of the branch diff. Material findings are fixed or
   reported.
9. **Ledger outcome.** Record actual files, commits, gate results and deviations.
10. **PR-open, on the owner's word for each external step.**
    - Confirm the leaf: title, landing label, `agentic`, `autonomous`, priority, parent `OME-1138`,
      assignee me.
    - File the issue, or one sub-issue per landing for L6 and L7.
    - Rename the branch to `OME-N-<slug>`.
    - Write `.claude/test-change-approvals/OME-N.json` and the `docs/tasks` mirror.
    - Stage only on approval of the exact Markdown paths.
    - Use a conventional commit, a PR body from `pr_template.md` with `Refs: OME-N`, and a
      release-note line where the change is visible. No tool mentions and no attribution lines.
    - Squash-merge on green CI.
11. **Close.** Post the close comment, set Done, and close the mirror and the ledger. Remove the
    worktree.
