**Goal:** Close the seven findings from the second review of PR #930 so the cache-entry-metadata

at the layer where the symptom shows: the stale-pairing hole is closed by a database trigger rather
than a loader check, because the same hole exists on the ordinary cache-fill path.

def _accumulated(total: Decimal | None, amount: Decimal) -> Decimal:
    """``amount`` added to ``total``, an absent total meaning this is the first contribution.

    WHY not `(total or 0) + amount`: a total of `Decimal("0")` is falsy, and collapsing it into
    the absent case would be harmless here only by luck. `None` and zero are different claims
    everywhere else in this module, so they stay different here too.

    under the smaller context would round a value that was deliberately preserved one step
    earlier — and silently, since `Decimal` signals inexactness only if the caller asks.

        ctx.prec = AMOUNT_PRECISION
        return total + amount

### Task 3: Refuse to price a cache hit that followed a transport retry (Finding 3)

`_post_completion` retries transport failures. If attempt 1 was processed and billed but its
response was lost, attempt 2 hits the row attempt 1 populated: the run reports current cost `0`
and a saved cost equal to the money just spent. Before this feature that was a silent
under-report; with it, the run makes an affirmative false claim.

The fix does not pretend to know the true spend. It withdraws the savings claim: the hit is still
a hit, but it is unpriced.

**Files:**
- Modify: `apps/screamingface-engine/src/screamingface_engine/runner/cache_readback.py` (`CacheOutcome`, `read_cache_outcome`)
- Modify: `apps/screamingface-engine/src/screamingface_engine/runner/connector.py:531-563` (`_post_completion`), `:604-634` (`_fetch_completion`), `:400-428` (`_report_response`)
- Modify: `apps/screamingface-engine/src/screamingface_engine/runner/accounting.py` (add `avoided_usd_for_outcome` below `avoided_usd_from_aigw`, ends line 290)
- Test: `apps/screamingface-engine/tests/unit/test_cache_saved_cost.py` (APPEND only)

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `CacheOutcome.retried: bool = False` — whether the round trip that produced this outcome

  - `read_cache_outcome(headers: Mapping[str, str], *, retried: bool = False) -> CacheOutcome`

### Task 4: Make the degraded-row count exact under concurrent fills (Finding 4)

`_DEGRADED_COUNT_SQL` and `_MERGE_SQL` are separate statements in a READ COMMITTED transaction.
Each takes its own snapshot, and `ON CONFLICT DO UPDATE` re-reads the latest committed row, so a
cache fill committed between them is degraded by the merge and missing from the count.

`SHARE ROW EXCLUSIVE` blocks concurrent writers to the table but not readers, for the duration of
the merge transaction only. A snapshot restore is admin-initiated and already disruptive; serving
cache reads throughout is what matters.

lock_timeout = 0 and can hold ACCESS SHARE for its entire 600 s COPY, so a migration landing
during an export took every cache read down with it for as long as the export ran.

A bounded lock_timeout makes the DDL leave the queue instead of leading it, and a small retry
spreads the attempts across the export rather than failing the deploy on first contact. The
migration becomes non-atomic because a failed statement aborts the enclosing transaction and
makes the retry impossible; every operation here is independently idempotent, so the single
transaction bought nothing.

0011 is edited in place rather than superseded: it is new on this branch and has never run
anywhere.

```python
_TRIGGER_FN = "request_cache_entries_clear_stale_metadata"
_TRIGGER = "request_cache_entries_metadata_follows_response"

# WHY a trigger and not a check in the loader: migration 0011 leaves pre-0011 binaries fully
# operational against the widened table, and an old writer updates `response_json` without
# knowing `metadata_json` exists. During pod overlap or a rollback that pairs a NEW response
# with the PREVIOUS response's cost, tokens and latency — a block that is perfectly well-formed
# and simply describes a different answer, which nothing downstream can detect. The loader is
# only where the reviewer found it; the ordinary cache-fill upsert has the same hole. A database
# rule is the only one that binds a binary that has never heard of it.
#
# It degrades to NULL — "unknown" — and never to a wrong number, which is the direction this
# whole feature commits to (PRD I1: unknown is not free).
#
# KNOWN FALSE POSITIVE, deliberately accepted: a writer that replaces the body and computes a
# byte-identical block loses it. The block carries provider latency, so two calls colliding on
# every field is vanishingly rare, and the cost of the collision is one row degraded to unknown
# — the safe direction. A session GUC that new writers set to opt out would be exact, but it
# puts the invariant back in the application, where forgetting it is silent again.
_CREATE_TRIGGER_SQL = f"""
CREATE OR REPLACE FUNCTION {_TRIGGER_FN}() RETURNS trigger AS $$
BEGIN
    NEW.metadata_json := NULL;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER {_TRIGGER}
BEFORE UPDATE ON {_TABLE}
FOR EACH ROW
WHEN (NEW.response_json IS DISTINCT FROM OLD.response_json
      AND NEW.metadata_json IS NOT DISTINCT FROM OLD.metadata_json)
EXECUTE FUNCTION {_TRIGGER_FN}();
"""

# The WHEN clause is evaluated by Postgres without entering the function body, so a
# `hit_count`/`last_hit_at` bump — the hot path — never pays for this.
_DROP_TRIGGER_SQL = f"""
DROP TRIGGER IF EXISTS {_TRIGGER} ON {_TABLE};
DROP FUNCTION IF EXISTS {_TRIGGER_FN}();
"""
```

`_TABLE` is `request_cache_entries`; define it as a module constant if the file has none.
