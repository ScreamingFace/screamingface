# Changelog

## Unreleased

### Breaking changes

* **screamingface:** `evaluate` no longer captures a pinned cache by default. Capture is now
  opt-in: pass `capture=True` to `sf.evaluate`, `Client.evaluate` or `AsyncClient.evaluate` to
  store the run's answers so the score can be reproduced. A run without `capture=True` has no
  `pinned_cache` and no `capture_status`. A replay still never captures.

* `sf.configure(engine_url=...)` with a non-default Engine now requires `scoreboard_url=`, and
  `SCREAMINGFACE_ENGINE_URL` requires `SCREAMINGFACE_SCOREBOARD_URL`. Previously the pair fell
  back to the hosted leaderboard, so a local or preview run could publish there.
  `sf.Client(...)` is unchanged.

* **screamingface:** recipes are a chain of steps joined with `>>`: map, score, narrow, then
  reduce or write (E4b, `OME-1653`). `sf.Fanout(members, signals=, quorum=, name=, prompt=)`
  sends the input to every member, an optional `sf.Judge` scores them, the optional narrow steps
  `sf.Rank`, `sf.Filter` and `sf.Concat` keep some of them, and one reducer or one
  `sf.Synthesize(model, prompt=)` writer ends the block. The SDK is experimental, so the old names
  are gone with no alias, except the `sf.Fusion` shortcut (see "Kept" below). Move a recipe with
  this table:

  | Removed | Use instead |
  |---|---|
  | `sf.Pipeline([sf.Fusion(m, synthesizer=sf.Rank(...)), writer])` (also `sf.Filter`, `sf.Concat`) | `sf.Fanout(m) >> sf.Rank(...) >> sf.Synthesize(writer)` |
  | `recipe.then(next)` | `recipe >> next` |
  | `sf.Pipeline(stages=[...])` | `sf.Pipeline(steps=[...])` (or the list as the first argument); `stages=` raises `TypeError` |
  | `extract=` on `sf.Vote`, `sf.Median`, `sf.Mean` and `sf.Filter` | `over=` (the same rule names, `"field:<path>"`, or `sf.Extract(...)`) |
  | `sf.Filter(where=<signal comparison>, extract=...)` | no replacement: `over=` works only with `sf.matches(...)`, and `over=` with a signal comparison raises `ValueError` |
  | `sf.Pick(field, order="max")` / `order="min"` | `sf.ArgMax("field:<field>")` / `sf.ArgMin("field:<field>")` |
  | `sf.Pick(by_signal=s, order="max")` / `order="min"` | `sf.ArgMax(s)` / `sf.ArgMin(s)` |
  | `sf.Pick(field, equals=v, normalize=n)` | `sf.First(where=sf.field(field, normalize=n) == v)` |
  | `sf.Judge(j, returns="label", rubric=r)` | `sf.JudgePick(j, rubric=r)` |
  | `sf.Judge(j, returns="scores", rubric=r)` as the synthesizer | `sf.Judge(j, rubric=r) >> sf.ArgMax("score:judge")` |
  | `sf.Judge(j, returns="scores", rubric=r, order="min")` | `sf.Judge(j, rubric=r) >> sf.ArgMin("score:judge")` |
  | `sf.Rank(k, by=sf.Judge(...))` | `sf.Judge(...) >> sf.Rank(k, by="score:judge", order=...)` |
  | `sf.Rank(k, by_field=f)` | `sf.Rank(k, by="field:<f>")` |
  | `sf.Rank(k, by_signal=s, order=o)` | `sf.Rank(k, by=s, order=o)` |
  | `sf.Filter(where=sf.signal("score:judge") >= x, judge=sf.Judge(...))` | `sf.Judge(...) >> sf.Filter(where=sf.signal("score:judge") >= x)` |
  | `sf.Vote(weights=sf.signal("score:judge"), judge=sf.Judge(...))` | `sf.Judge(...) >> sf.Vote(weights="score:judge")` |
  | `sf.Vote(gate=sf.Gate(observe, cmp, threshold, otherwise=..., abstain_band=(lo, hi)))` | `sf.Gate(when=<ref> <cmp> threshold, then=sf.Vote(...), otherwise=..., abstain_if=<ref>.between(lo, hi))`, where `<ref>` is `sf.agreement()`, `sf.signal(name).chosen()` or `sf.signal(name).mean()` |
  | gate `otherwise=sf.Judge(..., returns="label")` / `otherwise=sf.Model(...)` | `otherwise=sf.JudgePick(...)` / `otherwise=sf.Synthesize(...)` |
  | `sf.Reduce(op, ...)` (the block forms) | the named steps: `plurality` and `weighted` → `sf.Vote`; `median` → `sf.Median`; `mean` → `sf.Mean`; `argmax` and `pick_field` → `sf.ArgMax`, `sf.ArgMin` or `sf.First`; `top_k` → `sf.Rank`; `filter` → `sf.Filter`; `concat` → `sf.Concat`; `judge` → `sf.Judge` or `sf.JudgePick`; `merge` → `sf.Merge`; `context` → `sf.Synthesize`. A field or regex read goes in `over=`. |
  | `fusion.members`, `fusion.synthesizer`, `pipeline.stages`, `isinstance(x, sf.Fusion)` | `chain.steps` (the `sf.Fanout` step keeps `members`); `sf.Fusion` is now a function, so `isinstance` does not work with it |

  **Kept:** `sf.Fusion(members, synthesizer=..., signals=None, quorum="all", name=None,
  prompt=None, optional=False)` still works as a shortcut. It returns the
  `sf.Fanout(...) >> ...` chain and compiles to the same bytes: a route, an `sf.Model` or a
  recipe as `synthesizer=` becomes `sf.Synthesize(...)`, and a reducer comes as it is. It still
  takes `quorum=`, `name=` and `optional=`. Its canonical forms:

  | Shortcut | Canonical form |
  |---|---|
  | `sf.Fusion(m, synthesizer=<reducer>)` | `sf.Fanout(m) >> <reducer>` |
  | `sf.Fusion(m, synthesizer=<model or recipe>)` | `sf.Fanout(m) >> sf.Synthesize(<model or recipe>)` |
  | `sf.Fusion(m, synthesizer=S, quorum=q, name=n)` | `sf.Fanout(m, quorum=q, name=n) >> S` (`quorum=` and `name=` are on `sf.Fanout`) |
  | `sf.Fusion(m, synthesizer=S, optional=True)` | `sf.Pipeline([sf.Fanout(m) >> S], optional=True)` (`sf.Fanout` has no `optional=`) |

  **Byte changes.** A recipe that has no scoring judge and no field pick keeps its url4 bytes.
  These change one time:

  - The combine spec v1 gets an optional `narrow` key, and the combine evidence v1 an optional
    `narrow` record and the exclude reason `not_selected`, for a narrow step before a reducer. A
    spec or an evidence without a narrow step keeps its bytes, and the schema ids stay `v1`.
  - A `sf.Judge` scores call uses the neutral template `judge-template@2 returns=scores`
    (`judge-template@2 returns=scores input=panel` with a quorum): the rubric alone says which
    way is better. Every recipe with a scoring judge gets a new url4, so its judge call misses
    the gateway cache one time, and its scores can differ from a run with the old template.
    `sf.JudgePick` keeps `judge-template@1 returns=label`. `Url4(...).to_python()` refuses a url4
    with the old `judge-template@1 returns=scores` template ("URL4 Candidate has an unsupported
    judge call"): build the recipe again.
  - A field pick reads a signal: `sf.ArgMax("field:x")`, `sf.ArgMin("field:x")` and
    `sf.Rank(k, by="field:x")` compile to `by_signal@1`, not to `json_field@1` with `by_field@1`
    or `scores@1`. A member whose field is missing or is not a number is left out with the reason
    `no_signal`. `sf.ArgMax("field:confidence", output="answer")` and the old
    `sf.Pick(by_signal=sf.signal("field:confidence"), output="answer")` are now one recipe. A
    url4 with an old max or min field pick, or an old field rank, does not rebuild:
    `Url4(...).to_python()` raises "cannot rebuild".

  **Requires an SF Engine with the narrow step** for a narrow step before a reducer.

* **screamingface:** the frozen copy is called a **pinned cache** in the Python API (`OME-1613`).
  `CandidateResult.frozen_copy_id` and `LeaderboardScore.frozen_copy_id` are renamed to
  `pinned_cache`, with no alias; the constructor keyword changes the same way. The report JSON
  (`to_json()` / `to_dict()`) and the Scoreboard wire keep the key `frozen_copy_id`, so exported
  reports are unchanged.

* **screamingface:** `sf.reproduce`, `Client.reproduce` and `AsyncClient.reproduce` are removed
  (`OME-1613`). Replay a published run with `sf.evaluate(pinned_cache="<id>")`, or a score you
  submitted with `sf.evaluate(score_id="<id>")`; `record=` is now `record_reproduction=`. The
  verdict is on `CandidateResult.reproduction`, and `Reproduction.result` is gone (the result is
  the object that carries the verdict). A replay that cannot start raises `sf.ReproductionError`
  instead of returning a `not_reproducible` or `replay_unsupported` verdict.

### Fixes

* **screamingface:** a median weighted by the confidence of a JSON reply returns the median number (E4b): `sf.Median(over="field:answer", weights="field:confidence", select="value")`. `select="value"` returns the number, and `select="nearest"` (the default of `sf.Median`) returns the text of the nearest member. Before this fix the README recipe for this median returned the nearest member's whole JSON reply. A `select` that is not `nearest` or `value` raises `ValueError`. No Engine change.

* `sf.leaderboards.submit()` can log in to a leaderboard whose Cloudflare Access application covers only `/v1/scores` (`OME-1649`). After a challenge, the browser login now returns to the challenged path instead of the origin root, where Access never handed the token back and the login timed out after 300 s. `Client.login()` is unchanged.

* **screamingface:** `sf.Reduce("median", ...)` and `sf.Reduce("mean", ...)` take `select="nearest"|"value"`, the word of `sf.Median` and `sf.Mean` (E4b). `select="value"` is `mode="compute"` and returns the number; `select="nearest"` is `mode="select"` and returns the text of the nearest member. The defaults do not change: `nearest` for the median block and `value` for the mean block. Before this fix the median block refused `select=`, so the README recipe for a median weighted by the confidence of a JSON reply returned the nearest member's whole JSON reply. Now `sf.Reduce("median", extract=sf.Extract("field", path="answer"), weights=sf.signal("field:confidence"), select="value")` returns the weighted median number. The block keeps only the mode: the url4, the combine evidence and the repr do not change, and `Url4(...).to_python()` writes the block back with `mode="compute"`. A `select` that is not `nearest` or `value`, or a block that gives both `mode=` and `select=`, raises `ValueError`. No Engine change.

* **screamingface:** the `sf.Synthesize` writer after `sf.Rank` or `sf.Filter` now gets the input of the block with the selection: `{"input":...,"selected":[...]}` (E4b). Before, it got only `{"selected":[...]}`, and an empty cut gave it an empty text; now an empty cut gives `{"input":...,"selected":[]}`. **Behavior change:** the operator ids stay `top_k@1` and `kept@1`, so a Candidate from `0.1.3` or `0.1.4` that has a Rank or a Filter before a model stage sends a different prompt to that stage on an Engine with this change. No released Engine had `top_k@1` or `kept@1` before this change. **Requires an SF Engine with this change.**

* Show optional members in the `sf.Fanout` repr so member failure policy is visible (`OME-1557`). Required members retain their compact name-only representation.

* Show optional Model, Pipeline, and Fusion members in `Fusion` repr so member failure policy is visible (`OME-1557`). Required members retain their compact name-only representation.

* Preserve upstream answers across composed quorum panels and reject executable quorum/member policy that disagrees with default-valued Recipe metadata during export and replay (`OME-1557`). Composed quorum Recipes require an Engine containing the patched URL4 runtime; deploy the Engine operation-reporting update as well to retain member outputs and accounting.

* Stream compact accounting attribution and cache saved-run disclosure context lazily, without retaining every Case payload or accounting row. Invalid or stale caches rebuild; public breakdowns and report JSON remain unchanged.

* Stream complete report JSON exports through atomic, fsynced replacement while preserving report.v1 bytes, symlinks and existing permissions. Returning `to_json()` still allocates its full string.

### Features

* **screamingface:** show the combine steps in the report (E4b part 4). The Case pane has a Combine section for every reducer step, with the step facts and one row per member (status and reason, value, weight, score, rank, each signal, chosen). Each Candidate card has a summary per reducer step: how often each member was chosen and excluded, and the mean of each declared signal with its count. Numbers show 4 significant digits, the exact value on hover, and a missing value is an em dash with its reason. `report.export()` adds a `trace` key to each Case with a combine step (the `report.trace_dict()` entries); the schema stays `report.v1`. No new Python API. No Engine change.

* **screamingface:** the README section "Signal sources" gives five recipes for the E4b declared signals (E4b part 3): S12 a vote weighted by the confidence that each member states (`sf.Verbalized`), S13 a vote weighted by token probability (`sf.Logprob("prob")`), S14 the member with the highest mean token log-probability, S15 the member with the lowest mean token entropy (`sf.Entropy`), and S16 a log-probability threshold before a larger writer (the writer still runs; the skip comes with E4c). Each recipe runs offline in the Engine's tests from the url4 that the SDK compiles. Two paid tests check `openrouter/openai/gpt-4o-mini` live, and check that a model that refuses logprobs fails with `logprobs_unsupported`. No API change.

* **screamingface:** gate a majority vote (E4b part 5). `sf.Gate(when=sf.agreement() >= 0.7, then=sf.Vote(), otherwise=...)` keeps the majority answer when the comparison holds; `>=` keeps the majority at equality. The gate reads the agreement (`sf.agreement()`, the winner's share of the votes), a declared signal of the chosen member (`sf.signal(name).chosen()`) or the mean of a declared signal over the members (`sf.signal(name).mean()`). When the comparison is false, the fallback gives the answer: `otherwise="abstain"` (the Case abstains with the new reason `gate_not_met`), an `sf.JudgePick(...)` that names a member, or an `sf.Synthesize(...)` that writes the answer. The fallback call runs on every Case and costs money, also when the gate keeps the majority; a cascade that skips it comes with E4c. If the fallback call fails, the Case fails, also when the gate keeps the majority. The combine evidence has a new optional `gate` record (`sf.report.CombineGate`: the observed number, the comparison, the threshold and the branch), and the Case pane, the run summary and the export show it. `sf.Vote(verify=None)` is a reserved place for a later verifier, and the evidence reserves an optional `verifier` key. See the README section "Gate the majority". **Requires an SF Engine with the E4b part 5 combine gate.**

* **screamingface:** sum declared signals and abstain in a band (E4b part 6). `sf.Sum({"sev_a": 0.5, "sev_b": 0.3})` in `signals=` declares one more signal that gives each member `0.5 × sev_a + 0.3 × sev_b`. Each component is another declared name of the same `sf.Fanout` (not an E4a key and not another sum); a sum has 1 to 7 components, and each coefficient is a finite number that is not zero. When a component is missing, the sum is missing, not zero. `sf.ArgMax`, `sf.ArgMin`, `sf.Rank`, `sf.Filter`, a vote weight and a gate on `sf.signal(name).chosen()` or `sf.signal(name).mean()` read a sum by its name, and the combine evidence records it like any declared signal. A sum that adds `sf.Logprob("mean")`, `sf.Logprob("sum")` or `sf.Entropy` cannot be a vote weight. `sf.Gate(..., abstain_if=<ref>.between(lo, hi))` adds a closed band on the gate's number that the Engine checks before the comparison: when the number is in the band, the Case abstains with the new reason `in_band`, also when `otherwise` is a judge or a writer; outside the band, the gate compares as before. The gate record has the new optional key `abstain_band` and the new branch `band`, and the Case pane, the run summary and the export show the sum and the band. A judge or writer fallback still runs and costs money on every Case, also when the number is in the band. `Url4(...).to_python()` rebuilds a sum and a band. See the README section "Sum signals and the abstain band". **Requires an SF Engine with the E4b part 6 signal sums and abstain band.**

* **screamingface:** measure how often a member repeats its answer (E4b part 7). `signals={"cons": sf.Consistency(n=5)}` makes each member of a `sf.Fanout` answer `n` more times, with distinct fixed seeds at the stated `temperature` (default 1.0); the member's other params do not change. The value of each member is the share of those extra answers that equal its own answer after the step's own extract and normalize (the last line and the `text` normalizer for a step with no extract), over the extra calls that answered. A failed extra call does not fail the Case; when every extra call of a member fails, or the member has no answer to compare, the value is missing, and a rule that reads it leaves the member out. The extra answers never vote. The rules: one `sf.Consistency` per `sf.Fanout`, each member one `sf.Model` or a route, `n` from 1 to 32, at most 1024 extra calls per `sf.Fanout`, and not inside a corrective loop. The free preflight checks that each member's model takes `seed` and `temperature` before any call. A `sf.Fanout` of M members makes M × n extra calls on every Case, and you pay for them. The combine evidence has the new optional record `consistency` (`sf.report.CombineSampleCount`: `member_id`, `matched`, `succeeded`, `failed`), and the Case pane, the run summary and the export show the value and the failed extra calls. `Url4(...).to_python()` rebuilds `sf.Consistency(...)` and leaves out the extra calls. See the README section "Consistency samples". **Requires an SF Engine with the E4b part 7 consistency source.**

* **screamingface:** write a recipe as a chain with `>>` (E4b map, score, narrow, reduce). A
  narrow step can now come before a reducer, in one combine call:
  `sf.Fanout(m) >> sf.Filter(where=sf.signal("field:confidence") > 0.7) >> sf.Mean(over="field:answer")`
  and `sf.Fanout(m) >> sf.Judge(j, rubric=r) >> sf.Rank(3, by="score:judge") >> sf.Vote()`. The
  reducer reads only the kept members; a member that a narrow step leaves out is excluded with
  the new reason `not_selected`, and `CombineEvidence.narrow` holds one `sf.report.CombineNarrow`
  per narrow step (the select operator, the signal, the kept members, and for a Rank the cut,
  the scores and the ranks). The Case pane shows one chip per narrow step. `sf.Gate(when=...,
  then=sf.Vote(...), otherwise=..., abstain_if=...)` reads `sf.agreement()`,
  `sf.signal(name).chosen()` or `sf.signal(name).mean()`. `sf.First(where=sf.field(path) ==
  value)` returns the first member whose JSON field equals a value. Every `by=` and `weights=`
  takes a signal key as a string (`weights="cost_usd"`). The chain checks its rules when you build
  it, before any call: a block ends in one reducer or one `sf.Synthesize`, a narrow step never ends
  a recipe, `sf.Concat` is followed by `sf.Synthesize`, a block has at most one `sf.Judge` and at
  most 4 narrow steps, and a `sf.Judge` needs a step that reads `score:judge`. More stages can
  follow a closed block. `Url4(...).to_python()` writes the chain form. See the README section "How
  a recipe reads". **Requires an SF Engine with the narrow step for a narrow step before a
  reducer.**

* **screamingface:** `sf.Filter` takes `judge=sf.Judge(..., returns="scores")` with `where=sf.signal("score:judge") <op> x` (E4b). One judge call scores every member, and the Filter keeps each member whose score passes, in author order; the next stage gets the Case input and the kept members. `sf.Reduce("filter", where=..., judge=...)` compiles to the same url4, and a url4 is written back as `sf.Filter(...)`. A `score:judge` comparison without a judge, a judge without a `score:judge` comparison, a label judge or an `order="min"` judge raises before any call. **Behavior change:** `sf.Filter(where=sf.signal("score:judge") ...)` with no judge now says to add `judge=` (it said to use `sf.Rank`). No Engine change.

* **screamingface:** add `order="min"` to `sf.Judge(..., returns="scores")` (E4b). The judge is told that a lower number means a better answer (`judge-template@1 returns=scores order=min`), and the answer is the original text of the member with the lowest score; a tie goes to the first member in author order. The combine step is `best_holder@1 {"order":"min"}`, so no Engine change is needed. The default `order="max"` keeps the url4 of every existing judge. `returns="label"` with `order="min"`, and any other order value, raise `ValueError`. `sf.Rank(by=...)`, `sf.Vote(judge=...)` and their block forms refuse a judge with `order="min"`. `sf.Reduce("judge", judge=..., order=...)` overrides the order like `rubric=`. `Url4(...).to_python()` rebuilds the order.

* **screamingface:** add `sf.Mean(extract="last_number", select="value"|"nearest", weights=None)`, the mean and the weighted mean of the members' numeric answers (E4b). `select="value"` (the default) returns the mean as a number. `select="nearest"` returns the original text of the member nearest the mean; on a tie, the first member in author order wins and the evidence sets `tie`. `weights` takes one positive, finite number per member in author order, or `sf.signal(key)`, for example `sf.signal("field:confidence")` for members that reply with JSON. A member with a missing, zero, negative or non-number signal weight is dropped: it is not in the mean, and `select="nearest"` never returns it. When no member is left, the Case abstains with `no_votes`. The sums are exact `Decimal` sums, and the one division is rounded to 34 significant digits (`ROUND_HALF_EVEN`): `1, 1, 2` gives `1.333333333333333333333333333333333`. Ask every member for the same confidence scale: the Engine cannot see that one member writes `80` and another writes `0.8`. A wrong number of weights raises `ValueError` when the Fusion is built, and `weights=sf.signal("score:judge")` raises `ValueError` (a Mean has no judge). The block form `sf.Reduce("mean", mode="compute"|"select", extract=sf.Extract(...), weights=...)` compiles to the same url4, and it also reads a JSON field, for example `sf.Extract("field", path="answer")`. The combine evidence of a mean has `reducer: "mean"`, the new optional field `mean` (the mean as text) and `median: null`. `Url4(...).to_python()` rebuilds both forms. **Requires an SF Engine whose catalog has `mean@1` and `weighted_mean@1`.**

* **screamingface:** add weights to `sf.Median`: `weights=(…) | sf.signal(key)`, with the same weight rules as `sf.Vote`. A weighted Median compiles to `weighted_median@1`: the participants (members with a usable weight) are sorted by value, and the answer is the first value where the running weight reaches half the total, or the mean of that value and the next one at exactly half, so equal weights give the plain median. A member with a missing or non-positive weight is dropped and is never the `nearest` pick; when none is left, the Case abstains with `no_votes`. `sf.signal("score:judge")` raises `ValueError` (a Median has no judge). `sf.Reduce("median", ..., weights=...)` takes the same weights. A Median without weights keeps its url4 bytes. **Requires an SF Engine whose catalog has `weighted_median@1`.**

* **screamingface:** add `output=` to `sf.Pick` and to the `pick_field` and `argmax` blocks. `sf.Pick(field, order=..., output="answer")` and `sf.Pick(by_signal=..., output="answer")` return one top-level field of the winner's JSON reply as the answer: a string as it is, any other value as canonical JSON. When the winner's field is missing, `null` or blank, or its reply is not a JSON object, the Case abstains with the new reason `output_missing` (`Answer.reason`, combine evidence `result.reason`); the next member is never used. A value that is not a field name raises `ValueError` (a non-string raises `TypeError`) before any call. A Pick without `output` compiles to the same url4 as before. `Url4(...).to_python()` rebuilds `output`. **Requires an SF Engine whose catalog has `by_field@1` and `best_holder@1` with the `output` arg (E4b); an older Engine refuses the spec with `combine_spec_invalid` after the member calls.**

* **screamingface:** show a member that a combine step left out (E4b). A member with no value for the signal that the step reads (`sf.Rank(by_signal=...)`, `sf.Pick(by_signal=...)` or `sf.Filter(where=sf.signal(...) ...)`) or with no usable signal weight (a weighted `sf.Vote`, `sf.Median` or `sf.Mean`) now has `status: "excluded"` and the reason `no_signal` or `no_weight` in `CombineEvidence.members`, also when the step abstains. `case.answers()` gives it `sf.Answer(status="excluded", ...)` with the value it read, and the trace `extract` entry shows the same status and reason. A failed member stays `fail` with its own reason. Fixed weights never leave a member out. `dropped` and the quorum count only failed members. The Case answer and the url4 do not change. `sf.Answer.status`, `MemberStatus` and `AnswerReason` get the new words, and `screamingface.answer.v1` keeps its field set. **Requires an SF Engine and an SDK from the same E4b release: an older SDK refuses evidence with an excluded member.**

* **screamingface:** show the rank and the cut of a Rank step (E4b). In the combine evidence of a `top_k@1` step, each member with a score has a `rank` (`CombineAnswerRow.rank`: 1 is the best, and equal scores take author order, so no two members share a rank), and the evidence has a `cut` with `k` and `order` (`CombineEvidence.cut`, a `sf.report.CombineCut`; the default order is written as `"max"`). The chosen members are exactly the members with a `rank` of `cut.k` or less. A member that failed or was left out has no rank. The ranks and the cut are written also when the step abstains with `cut_not_met`. Other steps have neither key, so their evidence keeps its `screamingface.combine-evidence.v1` bytes. The Case answer and the url4 do not change. **Requires an SF Engine and an SDK from the same E4b release: an older SDK refuses evidence with a `rank` or a `cut`.**

* **screamingface:** name the judge in the trace (E4b). The `reduce` entry of `case.trace()` and `report.trace_dict()` has two new keys, `judge_operation_id` and `judge_model`. For a step that reads a judge (`sf.Judge`, `sf.Rank(by=sf.Judge(...))`, or a Vote or a Filter that reads `sf.signal("score:judge")`), they name the judge's own operation and the `model` of its `model_call` entry. They are `None` for any other step, for a Case result with no operation graph, and for a step with no judge operation or more than one. `judge_model` is `None` when the judge call has no accounting. The SDK reads the link from the operation graph, so the combine spec, the combine evidence and the url4 do not change, and a judge url4 compiled before this change rebuilds and links its judge. No Engine change.

* **screamingface:** add `sf.JudgeWriterWarning`, an `sf.EvaluationWarning` (E4b). When a Pipeline stage that reads a judge is followed directly by a model stage (an `sf.Model` or a route string) with the same model as the judge, the SDK warns when it compiles the Pipeline, before any call: the model that scored the members also writes the answer. The warning names the Pipeline, the two stage positions and the route. It never stops the run and never changes the url4. Two spellings of one route count as one model. The SDK sends it once per Pipeline object, and not again when it rebuilds a url4. A writer that is a Fusion or a nested Pipeline is not checked. Silence it with `warnings.filterwarnings("ignore", category=sf.JudgeWriterWarning)`. No Engine change.

A member that is not a JSON object is skipped and the report says `not_json`. A merge field with no usable value abstains the combine step with `no_votes` for the `majority`, `max` and `union` rules only; a `from_member` field that is `null` and a writer's empty text are values. A model-written field adds a projection combine call and one `writer_N` call that sees only that field's values; the writer's system prompt is the fixed `writer-template@1` text (member values are data) and then the author's prompt, which is all that `to_python()` shows; the writer call carries its cost on `op_writer_N` and appears as a synthesis accounting row. `sf.FieldRule` is a hashable value: equal rules are equal and have the same hash, and a `True`, a `1` and a `1.0` in `params` stay three different rules. `Url4(...).to_python()` rebuilds all of them. **Requires an SF Engine whose catalog has `json_field@1`, `json_object@1`, `values@1`, `by_field@1`, `field_rules@1`, `project_field@1` and `built@1`; `sf.ArgMax` and `sf.ArgMin` also need `by_signal@1` and `best_holder@1`.**

* **screamingface:** add `sf.Rank(k, by=..., order="max"|"min")` and `sf.Concat(separator, label)`, the narrow steps that hand a selection to a writer. `Rank` keeps the top `k` original member texts (by a signal key: `score:judge` after a `sf.Judge`, `field:<path>`, an accounting key or a declared name) and `Concat` joins every member text in author order; neither rewrites a text, and `Concat` makes no model call. A selection is a hand-off, not an answer: `sf.Synthesize` (or, after a Rank, a reducer or another narrow step) must follow it, and the writer receives only the selection (`{"input":...,"selected":[{"id":...,"text":...}]}` for `Rank`, where `input` is the input of the block; the joined text for `Concat`). A chain that breaks this raises `ValueError` when you build it. A Rank that finds fewer than `k` members with a usable score abstains the combine step with `cut_not_met` (the writer gets the input and no member: `{"input":...,"selected":[]}`). `k` outside 1 to 256 or above the member count, an empty separator, and a label that is not a bool raise before any call. The two combine steps of a Rank (the scores and `top_k@1`) carry the same `order`; a Concat has no order. `Url4(...).to_python()` rebuilds both. **Requires an SF Engine whose catalog has `scores@1` and `top_k@1` (`Rank` by a judge), `by_signal@1` and `top_k@1` (`Rank` by another signal) or `join@1` and `all@1` (`Concat`).**

* **screamingface:** add `sf.Filter(where=..., over=None)`, the narrow step that keeps the members that pass a test. `where=sf.matches(pattern)` keeps a member whose original text matches a regex (`over=` reads each answer first, and a member whose answer cannot be read is dropped), and `where=sf.signal(key) >= 0.6` keeps a member whose named signal passes the comparison. `sf.signal` now builds a predicate with `>`, `>=`, `<`, `<=` and `==` (a number must be finite; there is no `!=`; `sf.signal(...) == sf.signal(...)` stays a plain bool). `sf.signal("field:x") == True` also passes a numeric `1.0`, because a signal holds a float. A threshold is stored as a float: `1` and `1.0` are one test and equal steps compile to equal bytes (`True` stays a different test, and `-0.0` is `0.0`). A writer after the Filter receives `{"input":...,"selected":[{"id":...,"text":...}]}`: the input of the block and the kept members in author order; a Filter must be followed by `sf.Synthesize`, a reducer or another narrow step, and a Filter that keeps no member abstains (the writer gets the input and no member: `{"input":...,"selected":[]}`). A filter on `sf.signal("score:judge")` needs a `sf.Judge` step before it (see the judge filter bullet above), and an accounting key (`cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`) reads the members' own model calls. **Requires an SF Engine whose catalog has `filter@1` and `kept@1`.**

* **screamingface:** `sf.Fanout(members) >> sf.Synthesize(model)` is the named recipe: Fan-out, then one model writes the answer from the member answers. `sf.Fusion(members, synthesizer=model)` builds the same chain, and its url4 and operation ids are byte for byte those of a Fusion before this change.

* **screamingface:** add `sf.EngineCapabilityError` (a `sf.PlanningError`, code `engine_capability_missing`) for an SF Engine that lacks a capability an Evaluation needs. The operator catalog (`GET /v1/operators`) is fetched once per Client, kept for its `max-age`, then revalidated with `If-None-Match`; it is never served stale when the Engine cannot be reached.

  **Requires an SF Engine that serves `GET /v1/operators`.** Older Engines raise `EngineCapabilityError` for reducer candidates only; candidates without a reducer never request the catalog and are unchanged.

* **screamingface:** check the operator catalog before a raw url4 replay spends. `client.evaluate("<url4>")` (and `AsyncClient.evaluate`) now loads the same cached operator catalog as a Recipe evaluation when the url4 holds a `/ensemble/combine/v1` call, and requires every pinned `name@version` operator of every combine call to exist there in its stage. A missing id raises `ValueError` naming the id and stage before the run starts and before any model is called; an Engine without `GET /v1/operators` raises `EngineCapabilityError`. A bare operator name such as `mode` (no `@version`) in a replayed combine spec also raises `ValueError`, because the compiler always pins. A url4 with no combine call never requests the catalog.

* **screamingface:** report what a combine step decided. `CaseOperation.combine` holds a `sf.report.CombineEvidence` (the reading per member, the tally or scores, the agreement, the tie flag and the chosen member) for each reducer operation of a Case; it never holds the `output` copies (an extractor such as `whole@1` or `json_object@1` puts the extracted value, which can be the whole reply, in `raw` and `value`). The key is omitted from `to_dict()` when absent, and the decoder refuses unknown keys and schema ids. The scoreboard submission is unchanged.

* **screamingface:** add `sf.samples(model, n, *, seeds=None, temperature=None, prompts=None, params=None)`, which builds `n` Models of one route that differ in an integer `seed` (default `0` to `n - 1`), so a vote over them counts `n` real answers. A model whose provider does not accept `seed` fails before the run starts and before any model is called, with `sf.PlanningError` (code `unsupported_model_parameter`), through the existing parameter preflight. Add `sf.DuplicateMembersWarning` (an `sf.EvaluationWarning`): compiling a `sf.Fanout` block that ends in a reducer and whose direct Model members would send the same request warns once per group (the warning points at the caller's line and is not repeated by corrective rounds or url4 recovery), because identical requests may be served by one cached answer.

* **screamingface:** add `sf.FixedSeedSittingWarning` (an `sf.EvaluationWarning`). When a run sets `answer_seed` and a Recipe or a replayed URL4 has calls that set their own `seed` (every `sf.samples()` member, or any `sf.Model(params={"seed": ...})`), the SDK warns once per such Candidate before the run starts, naming those calls: they keep their seed, so they send the same request in every sitting and the spread across sittings is not measured. The run still goes on. If you already pass different `seeds=` in each sitting, silence it with `warnings.filterwarnings("ignore", category=sf.FixedSeedSittingWarning)`. The check covers Recipes and raw URL4 replays (`evaluate("<url4>", answer_seed=...)`), with the same text.

* **screamingface:** read the Answer-row combine evidence. `CombineEvidence.members` now holds `CombineAnswerRow` values (`member_id`, `raw`, `value`, `status` `answered|fail`, `reason`, `signals`, `weight`, `score`), and the evidence gains `signal` (`CombineSignal`), `result` (`CombineResult`: the computed answer or an abstain) and `dropped` (the failed-member count). `CombineMemberReading` and its `member`/`voted` wire keys are gone: this is the shape the E4a combine core writes.

* **screamingface:** add `sf.signal(key)`, a named number on a member Answer that a reducer reads. The E4a keys are `cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`, `score:judge` and `field:<path>`; anything else (a `logprob` key, for example) raises `ValueError` at construction, and `budget.remaining` is refused: it is a request-level Budget value that E4c reads, not an Answer signal.

* **screamingface:** add `sf.Extract(rule, normalize=None, **args)` (how a member's answer is read: `boxed`, `last_number`, `field`, `regex`, `last_line`, `whole`, `json`, `benchmark`, `inspect_number`, `inspect_aime`, then an optional normalizer) and `sf.matches(pattern)` (a filter predicate). A `regex` pattern is checked when the block is built, before any spend: its syntax, its length (1 to 256), its group, and the constructs the Engine's `regex@1` refuses (backreferences, lookarounds, conditional and atomic groups, possessive repeats, repeat counts over 1000, and the ASCII, LOCALE or VERBOSE flags). The Engine runs `regex@1` on RE2, where `\d` and `\w` are ASCII (use `\p{L}` and `\p{N}` for Unicode letters and digits) and `$` is the end of the text (write `\s*$` to allow a trailing newline); the Engine refuses a compiled program over 5000 instructions. The SDK check is a pre-spend filter and the Engine's RE2 compile is authoritative: a pattern the SDK accepts but RE2 rejects fails the Case with `combine_spec_invalid` at run time. The SDK pre-spend check is stricter than RE2 for `\Q…\E`, `\C`, `\x{…}` and POSIX `[[:class:]]`; write `\p{…}`, `\xHH` or explicit escapes instead. `\z` (end of text) is accepted.

* **screamingface:** add `sf.Answer` and `CaseResult.answers(operation_id=None)`. For each combine step of a Case, `answers()` returns one `Answer` per member in author order, then the computed `Answer` of the step: `member_id`, `text` (the member's original output, joined through the Candidate's operations; `None` when the Engine could not attribute it), `raw`, `value`, `status` (`answered`, `abstain` or `fail`), `reason` and `signals`. A Case with no operations or no combine step returns `()`; an unknown `operation_id` raises `ValueError`. `Answer` has `to_dict()`/`from_dict()`. `answers()` is derived: `Report.to_dict()` and the report.v1 bytes do not change.

* **screamingface:** mark a Case the combine step abstained on. `CaseResult.abstained` is `True` for a scored empty answer with score 0.0 that the Engine marked `"abstained": true`, and `CandidateResult.abstained_count` counts them (derived; it is not in `to_dict`). `CaseResult.to_dict()` writes `"abstained": true` as its last key only when true, so every other Case exports the same bytes; a value other than `true`, or the mark on any other kind of Case, is refused. The report card adds ` · N abstained` to its context line when N is above zero. Only the final step of a Candidate can mark a Case: the Engine marks it when the root of the expression is exactly one combine step that abstained, so a combine step that feeds another stage (a Rank or a Filter before `sf.Synthesize`) never does. An abstained Case scores 0.0, also when its grader fails after it returned material (an asset-defect code, `no_positive_points` or `polarity_mismatch`, keeps the Case failed instead, so a broken benchmark asset stays visible). On HealthBench a harmful answer can score below 0, so an abstain can rank above a bad answer; this is intended.

* **screamingface:** derive what every block did for a Case. `CaseResult.trace()` returns `sf.report.TraceEntry` values in operation order: a `model_call` per model operation (provider, model, cache `hit|miss|bypass|unknown`, cost, latency, tokens, and the `member_id` it served), an `extract` per member of each combine step, and one `reduce` per combine step (rule, mode, tally, chosen member, signal values, result, dropped count). `Report.trace_dict()` exports them as `screamingface.report-trace.v1`. The trace never holds member text and is not part of `Report.to_dict()`; a Case with no operations returns `()`. The `budget` entry kind is reserved: E4a writes none, because no E4a request declares a Budget. `report.v1` is unchanged: `Report.to_dict()`, `to_json()` and `export()` write the same bytes, and only `trace_dict()` writes `report-trace.v1`.

* **screamingface:** a cached replay reads each call's original cost, latency and tokens from the cache reference, so it gives the same `Answer.signals` and the same tally as the first run. A fresh live rerun can give a different `latency_ms` (and a different cost, if prices changed), so the same vote can pick another member. The accounting of a cache hit still reports zero cost, because a hit costs nothing now; the signals read the original call. Only `cost_usd` is proven end to end by the paid replay lane. `latency_ms`, `tokens_in` and `tokens_out` are carried by the cache metadata and covered by unit tests only.

* **screamingface:** add `screamingface.budget`, the records of the method-owner Budget (`screamingface.budget.v1`): `Budget(unit, cap)`, `BudgetCharge`, `BudgetRefusal` and `BudgetState` (`spent`, `remaining`, `unpriced_charges`, the charges and the refused calls). They are frozen values with `to_dict()`/`from_dict()` that mirror the Engine's records field for field, and a state must equal the fold of its own charges (`remaining = max(cap - spent, 0)`; an unpriced charge, with `amount=None`, adds nothing to `spent` and one to `unpriced_charges`). The module is not exported from `sf` or `sf.report`. This ships the records only: E4c enforces a cap, there is no request field that declares a Budget, and E4a writes no charge or `budget` trace entry.

* **screamingface:** freeze the wire schemas of the combine work. `combine-spec.v1`, `combine-evidence.v1`, `answer.v1`, `report-trace.v1` and `budget.v1` each have a pinned schema or field-set file under the Engine and SDK tests, and a test fails when one changes without a new schema id: a change needs a `v2`. `report.v1` is unchanged and stays pinned by the existing tests.

* **screamingface:** render completed per-operation accounting and per-Case details across benchmarks. `CandidateResult.accounting` derives immutable stage, operation, member, model and Case summaries from retained records, preserving unknown values and authoritative root totals. Direct model members receive usage only when every Case has a unique observation. Includes an offline Jupyter review notebook (`14_report_accounting.ipynb`).

* **screamingface:** mark Benchmarks scored by refusal rate. `BenchmarkInfo.inverted_grade` is `True` when every Case score is **already** 1 − the eval's grade (a should-refuse safety Benchmark such as `xstest_unsafe`), and report.json states it in the `benchmark` block — `false` for every other Benchmark. It is read from the Benchmark resource on a normal run (cross-checked against the run result) and from the run result on a replay. It is a mark, not an instruction: never flip a score with it. An Engine that predates the mark omits it, which reads as `false` — so deploy the Engine that ships `xstest_unsafe` and the Engine that sends the mark together.

  **Engines that send the mark need this release first.** An older SDK refuses the run result of a flipped Benchmark ("unsupported field `inverted_grade`"); every other Benchmark is unaffected.
* **screamingface:** show the refusal-rate mark where researchers look. `Benchmark.inverted_grade` carries it from the catalogue (absent means `false`); a flipped Benchmark gets an "inverted grade" chip in `sf.benchmarks` listings, a "grading" line on its card, and one line under the notebook report view's header — all saying "each Case scores 1 − the eval's grade, so higher is still better". Every other Benchmark renders exactly as before.

* **screamingface:** preserve Engine-observed caller version as `CandidateResult.client_version` and in report JSON; unavailable provenance remains null.

* **screamingface:** carry the catalogue's two grouping axes on `Benchmark` — `interaction` and the new hand-assigned `difficulty` tier (`easy`/`medium`/`hard`; served values verbatim, any non-blank string; `None` when an older Engine omits the key)
* **screamingface:** render `sf.benchmarks.list()` as a faceted map — clickable chip rows (Difficulty: All/Easy/Medium/Hard · Interaction: All/Single-shot/Multi-turn/Agentic · Origin: All plus the origins present) over a listing grouped easy→hard with interaction lanes; chips and search compose, and a tier-less catalogue from an older Engine keeps the flat list
* **screamingface:** show each benchmark's provenance in the listing and on its card, linked to its source collection (`Benchmark.origin` — any non-blank string, `"screamingface"` when an older Engine omits it; rendered as a per-row chip)
* **screamingface:** report what a submitted run cost is worth. `CandidateResult.run_cost_status` is `complete`, `partial`, or `unavailable`, and rides on the leaderboard submission beside `run_cost_usd`. It is optional on construction and inferred from the cost when omitted, so no existing caller has to supply it; only `partial` must be named explicitly, because it needs cache evidence an amount alone cannot carry. It also serializes into report.json, so an exported report keeps the distinction between `partial` and `unavailable` — both carry a null cost, and a reader rebuilding the status from the amount alone would collapse them.
* **screamingface:** send what the cache saved on a leaderboard submission. `CandidateResult.cache_saved_cost_usd` holds the provider-reported saving summed across the run's spans (a `Decimal`, or `None` when nothing priceable was observed, which is not zero). It is sent as a decimal string beside `run_cost_usd`, never added to it: the Scoreboard sums the two where it needs a total. The key is **omitted** when there is no saving, so an uncached run's submission is unchanged. The archive-matched figure is never carried or sent. It also serializes into report.json, null when absent. On construction, a saving with no cost now infers `run_cost_status="partial"`, and `unavailable` beside a saving is refused, because the Scoreboard refuses that pair.

  **Requires a Scoreboard that accepts the field** (`OME-1325`). A cached run's submission rejects with HTTP 422 against an older Scoreboard; uncached runs are unaffected.
* **screamingface:** `Span` carries `cache_saved_cost_usd` and `cache_saved_cost_archive_usd` — what that span's cache hits would have cost had they not been served from cache. **Never add the two together.** The first is money the provider itself priced for the call that filled the entry; the second is a real measured amount from a *different* call of the same model and kind, so it says nothing provable about this span. They are two fields rather than one amount plus a label precisely so the difference cannot be collapsed. `None` means nothing priceable was observed, which is not zero.
* **screamingface:** declare an answer seed per evaluation and name the sitting in the report (`evaluate(answer_seed=…)` sends `X-Answer-Seed`; `CandidateResult.answer_seed` serializes into report.json, null when unseeded)
* **screamingface:** expose `ModelDetails.execution_access` (`configured`, `missing`, or `None` for older Gateways).

* **screamingface:** expose and render why a published score will not rank

  The payload gains a `models` array carrying `CandidateResult.models` verbatim, alongside the
  existing `ran_with_providers`, which is unchanged. Previously each route was truncated to its
  provider prefix, so a fusion of open-weight models submitted as `["openrouter"]` and was
  published as closed.

  **Requires a Scoreboard that accepts the field.** Submissions reject with HTTP 422 against a

### Bug Fixes

* **screamingface:** keep local Engine result artifacts in the private data directory (respecting `URL4_CLOUD_ARTIFACTS_DIR`) and show the absolute serving directory and size in runtime status, even from another working directory. Incorporates runtime storage improvements from Ionésio's PR #1211. Engine retention is unchanged.

* **screamingface:** remediate runtime logs already on disk (`OME-1048`). Every `screamingface up` now tightens the rotated backups `runtime.log.1`…`.5` to `0600`, as `OME-990` already did for the live log; before this, a backup written `0644` by an earlier version kept that mode until five more rotations pushed it out. The backups' content is left alone. Versions before `OME-990` also wrote prompts into these files, so the new `screamingface logs --purge` deletes every rotated backup and empties the live log (a running stack keeps logging into it). It runs only when you invoke it: nothing is purged automatically.
* **screamingface:** stop publishing a cache replay's $0 as an exact run cost. A response the Gateway served from its cache spends nothing upstream, so a cached run's spend understates its cost, yet the leaderboard showed and ranked it as `complete`. `CandidateResult.cache_hits` now counts the run's cache-served round trips (the Engine's run summary, falling back to hit spans; `0` when none), and serializes into report.json. A leaderboard submission from a run with **any** hit is sent as `run_cost_status="partial"` with no `run_cost_usd`, whether or not its spend was priced. `cache_saved_cost_usd` is still sent when present. **Behavior change:** such a row shows no cost on the board. The local result is unchanged: `usage.cost_usd` and `run_cost_status` still report what the run spent. Uncached runs submit exactly as before. To publish a real cost, rerun with the cache bypassed.
* **screamingface:** redact prompt carriers at the runtime log sink (`OME-1050`).
  `runtime.log` captures the stack's entire stdout and stderr: `print`, warnings,
  unconfigured loggers and tracebacks.
  * Three structural carriers are now redacted, both on every log record and on every
    line written to the file: url4 `q=` query values, litellm's `Messages:` exception
    suffix, and litellm's debug curl `-d` request body.
  * The runtime also pins `litellm.redact_messages_in_exceptions = True`.
  * It forces `LITELLM_LOG=WARNING`. **Behavior change:** `LITELLM_LOG=DEBUG` no longer
    turns the log into a prompt transcript.
  * An already-installed log record factory is wrapped, never replaced.
  * Prompt text with none of those markers is out of scope and is not detected.
* **screamingface:** one failed Candidate no longer stops its healthy siblings (`OME-1071`, `OME-1067`). In a multi-Candidate `evaluate(...)`, a Candidate whose stream is lost, whose start the Engine never admits, or that fails in any other ordinary way no longer stops every Run of the Client: the other Candidates run to their end, and the progress output marks the failed row at once. When one or more Candidates failed, `evaluate` then raises `ExecutionError(code="candidates_failed")` from the first failure. `details["failed"]` maps each failed Candidate's name to its code (`unexpected_error` for an exception without one), and the new `ExecutionError.partial_report` holds a `Report` of the Candidates that succeeded (`None` when none did). **Behavior change:** in a multi-Candidate Evaluation, errors such as `EngineUnavailableError` or `AuthenticationError` from a Candidate now arrive as the `__cause__` of `candidates_failed`, not directly. A one-Candidate Evaluation raises the failure itself, as before. Ctrl-C, task cancellation and an exception from your own `on_event` callback still stop every Run and re-raise that exception unchanged; the Runs the SDK stopped then read `stopped` (panel row and terminal `run stopped`), not `run failed`. The error's hint points to `error.partial_report`, because IPython shows only the message, hint and code.
* **screamingface:** refuse a seeded evaluation before any spend when a Candidate Model's provider does not accept `seed`. The parameter preflight read the gateway's policy (`gateway_status`) and never the provider's evidence (`provider_support`) on the same contract row, so a fusion containing such a model passed the check, went to the wire, and died mid-run with `provider_error` — score `null`, coverage `0.0`, after the members that worked were already billed. It now raises `PlanningError` naming the Model and the parameter and saying the run cannot be reproducible, and likewise for **any** declared parameter the provider denies — `temperature`, `top_k` or anything else — not just `seed`. Only an explicit `unsupported` refuses: `conditional` and `unknown` pass through unchanged, and an unseeded run is unaffected. Declaring a seed per-Model only on the Models that accept it remains allowed, which is how a deliberately partial sitting is expressed.
* **screamingface:** accept `answer_seed` on the module-level `evaluate(...)`, not only on `Client.evaluate`. The one-line call every example notebook uses raised `TypeError: evaluate() got an unexpected keyword argument 'answer_seed'`, so seeded runs were unreachable for notebook users even though the feature above had shipped. Both branches forward it now — Recipes and a complete URL4 — and omitting it still declares no seed.
* **screamingface:** check every required Candidate Model before evaluation dispatch and raise `ProviderConnectionError` for Gateway-reported missing access. Sync and async Clients reuse model admission details; older Gateways preserve existing behavior.
