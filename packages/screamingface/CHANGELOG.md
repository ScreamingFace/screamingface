# Changelog

## Unreleased

### Fixes

* Show optional Model, Pipeline, and Fusion members in `Fusion` repr so member failure policy is visible (`OME-1557`). Required members retain their compact name-only representation.

* Preserve upstream answers across composed quorum panels and reject executable quorum/member policy that disagrees with default-valued Recipe metadata during export and replay (`OME-1557`). Composed quorum Recipes require an Engine containing the patched URL4 runtime; deploy the Engine operation-reporting update as well to retain member outputs and accounting.

* Stream compact accounting attribution and cache saved-run disclosure context lazily, without retaining every Case payload or accounting row. Invalid or stale caches rebuild; public breakdowns and report JSON remain unchanged.

* Stream complete report JSON exports through atomic, fsynced replacement while preserving report.v1 bytes, symlinks and existing permissions. Returning `to_json()` still allocates its full string.

### Features

* **screamingface:** a Fusion with `quorum` or optional members may end in a reducer (`OME-1289`, `OME-1557`). The members reach the combine call as a broadcast panel with one row per member that answered; url4 checks the quorum and the required members first. A failed optional member is a failed Answer with the reason `missing`, never a vote. A judge on such a Fusion gets a panel form of its template (`judge-template@1 returns=<r> input=panel`) and scores only the members that answered. The block form `Pipeline([Fusion(m, Reduce("context"), quorum=…), Model])` keeps its quorum and optional members. A Fusion with no quorum and no optional member keeps its url4 bytes. **Needs an Engine from the same E4a release**: an older Engine refuses the `panel` context permanently.

* **screamingface:** add `Fusion(..., quorum=N)` and per-member `optional=True` on Model, Pipeline, and Fusion Recipes (`OME-1557`). Optional complete members can fail without stopping synthesis when enough members succeed; required members must still succeed. Defaults require every member, `all` includes optional members, and zero allows an empty panel when all members are optional. Quorum is checked after members finish. Gated Fusions pass ordered successful `member_N: answer` sections in the synthesizer JSON's `outputs` string. Optional policy is only valid in Fusion member positions. Quorum and optional settings survive editable Python and replay, which validates the executable policy against recipe metadata.

* Track saved-report evaluation, display and JSON export lifecycles, and show notebook recovery guidance when the previous local owner process exited unexpectedly. Explicit recovery preserves interruption metadata across destination stores; healthy and legacy reports remain quiet.

* **screamingface:** read Benchmarks that ask each Case several times (`OME-1458`). Such a Benchmark marks a Check met if any Attempt met it; `CaseResult.attempts` keeps every Attempt's own answer, finish reason, failures, grade and cost records (`CaseAttempt`), in order, and is `None` for every other Benchmark. The Case Result's `output` and `grade` stay the shown answer and the folded grade. The report pane says "any of 2 Attempts" (and how many failed) and lists each Attempt's answer and score (and a failed Attempt's failure); an inspect-log export keeps the folded score, marks it folded, and lists every Attempt in the sample's metadata; `CandidateResult.accounting` bills each Attempt's calls once. `Benchmark.attempts` carries the catalogue's count (absent means 1), shown as "any of N Attempts · N Candidate Invocations per Case". Failure code `attempt_grade_not_pass_fail` is declared.

  **Engines that send Attempts need this release first.** An older SDK refuses the run result of an Attempts Benchmark ("unsupported field `attempts`"); every other Benchmark is unaffected.

* Browse completed reports in live notebooks 25 Case results at a time, with Candidate filtering, exact Case-ID navigation and streamed full-report downloads. Static HTML shows a bounded first-page preview; install the notebook extra for live controls.

* Retain completed evaluation results on disk before decoding and reopen them with `sf.reports.list()`, `get()`, `get_async()`, and explicit `delete()`. Public Clients save results by default; `save_results=False` retains in-memory collection. Verified incremental indexing preserves full Case data and provenance, while fusion-member totals retain nullable values with bounded auxiliary memory.

### Features

* **screamingface:** carry each Benchmark's provenance and saturation verdict from the Engine catalogue. `Benchmark.provenance` is a `BenchmarkProvenance` (paper, authors, citation, inspect porters as GitHub handles, website, harness pinned to a commit or tag, licence with any note, content warning, a `PublishedScore` human baseline and frontier score, the SDK notebook that runs it) and `Benchmark.saturation` is the Engine's derived verdict (`saturated` / `open` / `unknown`). An Engine that predates them serves neither: `provenance` reads `None` and `saturation` reads `unknown`. The local Scoreboard seed emits the same keys, so a local board shows what a deployed one shows.

* **screamingface:** publish a cached run's full cost when every cache hit is priced (`OME-1463`, decision D7 on `OME-1251`). `CandidateResult.cache_saved_cost_archive_usd` carries what the hits served from archive-matched cache entries would have cost, and `CandidateResult.cache_unpriced_hits` the Engine's count of hits with no price at all (`None` when the Engine sent no run summary). Both serialize into report.json. A leaderboard submission now sends the archive saving as `cache_saved_cost_archive_usd`, beside `run_cost_usd` and `cache_saved_cost_usd` and never added to either; the Scoreboard sums the three. **Behavior change:** a run with cache hits is sent as `complete`, with its spend as `run_cost_usd`, when the Engine's summary shows no unpriced hit and the spend is priced. Any unpriced hit, a missing summary, or an unpriced spend still sends `partial` with no amount. **Requires a Scoreboard that accepts the field** (`OME-1382`); against an older one, an archive-priced run's submission rejects with HTTP 422.

* **screamingface:** add `sf.Vote` and `sf.Median`, the first named deterministic Fusion synthesizers. `sf.Vote(extract="last_line", normalize="text")` returns the text of the first member that holds the most common answer, byte for byte; `sf.Median(extract="last_number", select="nearest"|"value")` returns the nearest member's text or the median number, with the normalizer fixed to `numeric`. Each one compiles to the same combine call as its `sf.Reduce("plurality", ...)` or `sf.Reduce("median", ...)` block. A member with no usable value does not vote. When no member votes, the Case abstains: its output is `""`, its score is 0.0 and `case.abstained` is true. It does not fail. Engine operator ids are pinned at compile time. `to_python()` writes only `extract`, `normalize` and Median's `select`, so a recompile re-pins the other operators to the newest version the Engine serves.

* **screamingface:** add weights to `sf.Vote`: `weights=[2, 1, 1] | sf.signal(key)`. A list gives one positive, finite number per member in author order. A `sf.signal` (for example `field:confidence`, or an accounting key: `cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`) weighs each member by a named number on its Answer. Each answer scores the sum of its holders' weights, and the highest-weight holder of the winning answer is returned (the first in author order on equal weights). A voter with a missing signal does not vote. When no voter is left, the Case abstains. `sf.Reduce("weighted", extract=..., weights=...)` takes the same weights and compiles to the same Candidate. A bad weight value (zero, negative, not finite, or above `sys.float_info.max / 256`) raises `ValueError` at `sf.Vote(...)`, a weight that is not a number raises `TypeError`, and a wrong weight count raises `ValueError` when the Fusion is built; all before any call. `sf.Median(weights=...)` raises `TypeError`. `sf.signal("score:judge")` raises `ValueError` until the judge arrives. An accounting key adds `sources` to the combine context (the model calls each member made), and only an accounting key does: no other Candidate changes its url4. A member gets no accounting value when one of its model calls (the same route and params) also appears elsewhere in the Candidate, or in a later corrective round. The weights are part of the combine spec, so they are part of the url4 text, and `Url4(...).to_python()` rebuilds them (a weighted `sf.Reduce` block with a plain rule comes back as `sf.Vote(weights=...)`). The Engine sums the weights as `Decimal` values, so the score does not depend on the order of the sum.

* **screamingface:** add `sf.Judge(model, returns='label'|'scores', rubric=..., params=...)` as a Fusion synthesizer. It compiles to one judge model call (`judge_N`, with the template `judge-template@1` at the head of its system prompt) and a strict combine step that copies the chosen member's text byte for byte. A reply that is not exactly one member id (label) or one JSON object with one finite score per member (scores) fails the case with `judge_reply_invalid`, and the judge's prose is never the answer. Members are shown to the judge in author order, so a judge can favor a position. The judge call carries its cost on `op_judge_N` and appears as a synthesis accounting row. `sf.Judge` is a hashable value. `sf.Reduce("judge", judge=sf.Judge(...)[, rubric=...])` is its block form and compiles to the same url4; `rubric=` replaces the rubric of that judge and is not stored. `Url4(...).to_python()` rebuilds the Judge from its model call. Model params now reserve the name `binding`. **Requires an SF Engine whose catalog has `label@1`/`scores@1`.**

* **screamingface:** add `judge=sf.Judge(..., returns='scores')` to `sf.Vote`, and the same `judge=` option to `sf.Reduce("weighted", ...)`. Paired with `weights=sf.signal('score:judge')`, the judge scores every member in one call and the vote weighs each answer by its member's score; the scores appear in the report as `members[].signals["score:judge"]` and `weight`. The two must be used together: `score:judge` weights without a judge, a judge without those weights, a judge that returns labels, or a `judge` that is not an `sf.Judge` raises `ValueError` or `TypeError` when the reducer is built, before any call is paid (the Engine reads `score:judge` strictly). `Url4(...).to_python()` writes the vote back as `sf.Vote(..., judge=sf.Judge(...))`, or as `sf.Reduce(...)` when the extract rule has arguments.

* **screamingface:** add `sf.Vote(extract="benchmark")`. The vote reads each answer with the selected benchmark's own grading rule (for `inspect-gsm8k`, its numeric match), so it groups answers the way the grade does. The SDK reads the rule from the benchmark resource it already fetches, before any spend, so the check adds no request. The Candidate url4 pins the rule's operator ids. It is therefore specific to that rule, and a replay of the url4 does not look the rule up again. `extract="benchmark"` takes no `normalize` (the benchmark brings its own), and `sf.Median(extract="benchmark")` raises `ValueError` (a Median needs the `numeric` normalizer). The SDK raises `ValueError` before any spend when the benchmark declares no answer rule. It raises `sf.EngineCapabilityError` (code `engine_capability_missing`) when the SF Engine does not serve the operators of the rule. For a rule with arguments, use `sf.Reduce("plurality", extract=sf.Extract("regex", pattern=...))`.

* **screamingface:** `Url4(...).to_python()` now writes `sf.Vote(...)` or `sf.Median(...)` when the combine spec is exactly that named form, and `sf.Reduce(...)` for every other spec (operator arguments). The generated Python recompiles to the same url4 in both cases.

* **screamingface:** add the reducer slot of `sf.Fusion`. `sf.Fusion(members, synthesizer=<reducer>)` now accepts a deterministic reducer and compiles it to ONE `/ensemble/combine/v1` url4 call whose intent is the canonical combine spec, with operator names pinned to exact `name@version` ids against the Engine's operator catalog. A reducer is valid only as a Fusion synthesizer (anywhere else raises `TypeError`). The base type, `screamingface.reducer.Reducer`, is internal groundwork and not a supported public base class. The reducer you build is `sf.Reduce(...)` (below); the named forms are `sf.Vote`, `sf.Median`, `sf.Judge`, `sf.Pick`, `sf.Merge`, `sf.Rank`, `sf.Concat` and `sf.Filter`, and a url4 with a reducer rebuilds with `Url4(...).to_python()` into the named form when it matches exactly, else `sf.Reduce(...)`.

* **screamingface:** add `sf.Pick`, `sf.Merge` and `sf.FieldRule` for members that reply with JSON. `sf.Pick(field, order='max'|'min')` or `sf.Pick(field, equals=value, normalize=None|'text'|'numeric')` returns the member whose field is the largest, the smallest or equal to a value, as that member's own text byte for byte. A field path longer than 256 characters raises `ValueError` before any call, because the Engine refuses it after the member calls are paid. `sf.Pick(by_signal=sf.signal(key), order='max'|'min')` (argmax) returns the member whose named signal is the highest or the lowest, as that member's own text. `order` is `'max'` when left out. A member with no value for the signal is skipped, and the Case abstains when no member has one. The same `order` goes into both steps of the combine spec (`by_signal@1` and `best_holder@1`). `sf.Pick(by_signal=sf.signal('score:judge'))` raises `ValueError`: there is no judge, so use `sf.Judge(..., returns='scores')`. An accounting key (`cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`) adds `sources` to the combine context, as for a weighted `sf.Vote`. `sf.Merge(fields={name: sf.FieldRule...})` builds one canonical JSON object with exactly the declared fields; each field has a rule: `majority`, `max`, `from_member(n)` (1-based author position, checked when the Fusion is built), `union` or `model`. A member that is not a JSON object is skipped and the report says `not_json`. A model-written field adds a projection combine call and one `writer_N` call that sees only that field's values; the writer's system prompt is the fixed `writer-template@1` text (member values are data) and then the author's prompt, which is all that `to_python()` shows; the writer call carries its cost on `op_writer_N` and appears as a synthesis accounting row. `sf.FieldRule` is a hashable value: equal rules are equal and have the same hash, and a `True`, a `1` and a `1.0` in `params` stay three different rules. Block forms: `sf.Reduce('pick_field', field=..., order=... | equals=..., normalize=...)`, `sf.Reduce('merge', fields={...})` and `sf.Reduce('argmax', by_signal=..., order=...)` compile to the same url4 as the named class and are written back as the named class. A `pick_field` block stores `equals` as its text, so `equals=7` and `equals='7'` are one block; the Pick errors keep their text and gain the `sf.Reduce('pick_field'):` prefix. `Url4(...).to_python()` rebuilds all three. **Requires an SF Engine whose catalog has `json_field@1`, `json_object@1`, `values@1`, `by_field@1`, `field_rules@1`, `project_field@1` and `built@1`; argmax also needs `by_signal@1` and `best_holder@1`.**

* **screamingface:** add `sf.Rank(k, by=sf.Judge(..., returns='scores') | by_field=...)` and `sf.Concat(separator, label)`, the selection synthesizers. `Rank` keeps the top `k` original member texts (scored by a judge, or by a number in each member's JSON reply) and `Concat` joins every member text in author order; neither rewrites a text, and `Concat` makes no model call. A selection is a hand-off, not an answer: it must be followed by another stage of a `sf.Pipeline`, and the next stage receives only the selection (`{"selected":[{"id":...,"text":...}]}` for `Rank`, the joined text for `Concat`). A Fusion with a selection that ends a candidate, is a Fusion member (directly or through a Pipeline that ends in one) or feeds a corrective loop raises `ValueError` at compile time. `k` outside 1 to 256 or above the member count, both or neither of `by` and `by_field`, an empty separator, and a label that is not a bool raise before any call. `Url4(...).to_python()` rebuilds both. **Requires an SF Engine whose catalog has `scores@1` and `top_k@1` (`Rank`, both forms) or `join@1` and `all@1` (`Concat`).**

* **screamingface:** add `by_signal=` and `order=` to `sf.Rank`. `sf.Rank(k, by_signal=sf.signal(key), order="max"|"min")` keeps the `k` members with the highest (or, for `order="min"`, the lowest) value of a named number on each Answer (`field:<path>`, or an accounting key such as `cost_usd`), as `by_signal@1` plus `top_k@1`; both steps carry the same `order`. `order=` also applies to `by=` and `by_field=` (the default `"max"` keeps the bytes `sf.Rank` wrote before). Give exactly one of `by`, `by_field` and `by_signal`; `sf.signal("score:judge")` is refused, because a Rank with no judge has no judge score (use `by=sf.Judge(..., returns="scores")`). `sf.Reduce("top_k", k=..., by=... | by_field=... | by_signal=..., order=...)` compiles to the same url4 as the matching `sf.Rank`. **Requires an SF Engine whose catalog has `by_signal@1` and `top_k@1` (`by_signal`).**

* **screamingface:** add `sf.Filter(where=..., extract=None)`, the selection that keeps the members that pass a test. `where=sf.matches(pattern)` keeps a member whose original text matches a regex (`extract=` reads each answer first, and a member whose answer cannot be read is dropped), and `where=sf.signal(key) >= 0.6` keeps a member whose named signal passes the comparison. `sf.signal` now builds a predicate with `>`, `>=`, `<`, `<=` and `==` (a number must be finite; there is no `!=`; `sf.signal(...) == sf.signal(...)` stays a plain bool). `sf.signal("field:x") == True` also passes a numeric `1.0`, because a signal holds a float. The next stage receives `{"selected":[{"id":...,"text":...}]}` with the kept members in author order; a Filter must be followed by another stage of a `sf.Pipeline` (a Filter that ends a candidate, is a Fusion member or feeds a loop raises `ValueError` at compile time), and a Filter that keeps no member abstains (the next stage gets an empty text). `sf.Reduce("filter", where=..., extract=...)` compiles to the same url4. A filter on `sf.signal("score:judge")` is refused (use `sf.Rank(k, by=sf.Judge(...))`), and an accounting key (`cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`) reads the members' own model calls. **Requires an SF Engine whose catalog has `filter@1` and `kept@1`.**

* **screamingface:** add the block forms of the selections: `sf.Reduce("top_k", k=..., by=... | by_field=... | by_signal=..., order=...)`, `sf.Reduce("concat", separator=..., label=...)` and `sf.Reduce("filter", where=..., extract=...)` compile to the same url4 as `sf.Rank`, `sf.Concat` and `sf.Filter`, and `Url4(...).to_python()` writes the named class back. The default `order="max"`, the default separator and `label=True` are not stored, so each block has one canonical form.

* **screamingface:** `sf.Fusion(members, synthesizer=sf.Model(p))` is now documented as the named recipe Fan-out, `Reduce.compute(context)`, Model. The block form `sf.Pipeline([sf.Fusion(members, synthesizer=sf.Reduce("context")), S, *rest])` is rewritten to `sf.Pipeline([sf.Fusion(members, synthesizer=S), *rest])` (or to `sf.Fusion(members, synthesizer=S)` for an unnamed Pipeline with no more stages) before the compile, so its url4 and its operation ids are byte for byte those of the Fusion form. A candidate is named from the rewritten value (`a+b`, not `a+b->s`), so `report.candidates[...]` uses that name and two block forms that get the same name raise `ValueError` (give each one `name=`), and the `context` block needs no operator catalog and has no member limit. `sf.Reduce("context")` anywhere else (the last stage, a Fusion or loop member, before another `context` Fusion) raises `ValueError` before any call. A multi-stage synthesizer in the block form needs a **named** `sf.Pipeline` (or a Fusion), because an unnamed nested Pipeline is made flat. No url4 of an existing Fusion changes.

* **screamingface:** add `sf.EngineCapabilityError` (a `sf.PlanningError`, code `engine_capability_missing`) for an SF Engine that lacks a capability an Evaluation needs. The operator catalog (`GET /v1/operators`) is fetched once per Client, kept for its `max-age`, then revalidated with `If-None-Match`; it is never served stale when the Engine cannot be reached.

  **Requires an SF Engine that serves `GET /v1/operators`.** Older Engines raise `EngineCapabilityError` for reducer candidates only; candidates without a reducer never request the catalog and are unchanged.

* **screamingface:** check the operator catalog before a raw url4 replay spends. `client.evaluate("<url4>")` (and `AsyncClient.evaluate`) now loads the same cached operator catalog as a Recipe evaluation when the url4 holds a `/ensemble/combine/v1` call, and requires every pinned `name@version` operator of every combine call to exist there in its stage. A missing id raises `ValueError` naming the id and stage before the run starts and before any model is called; an Engine without `GET /v1/operators` raises `EngineCapabilityError`. A bare operator name such as `mode` (no `@version`) in a replayed combine spec also raises `ValueError`, because the compiler always pins. A url4 with no combine call never requests the catalog.

* **screamingface:** report what a combine step decided. `CaseOperation.combine` holds a `sf.report.CombineEvidence` (the reading per member, the tally or scores, the agreement, the tie flag and the chosen member) for each reducer operation of a Case; it never holds member text. The key is omitted from `to_dict()` when absent, and the decoder refuses unknown keys and schema ids. The scoreboard submission is unchanged.

* **screamingface:** add `sf.samples(model, n, *, seeds=None, temperature=None, prompts=None, params=None)`, which builds `n` Models of one route that differ in an integer `seed` (default `0` to `n - 1`), so a vote over them counts `n` real answers. A model whose provider does not accept `seed` fails before the run starts and before any model is called, with `sf.PlanningError` (code `unsupported_model_parameter`), through the existing parameter preflight. Add `sf.DuplicateMembersWarning` (an `sf.EvaluationWarning`): compiling a reducer `sf.Fusion` (a named reducer and an `sf.Reduce` block alike) whose direct Model members would send the same request warns once per group (the warning points at the caller's line and is not repeated by corrective rounds or url4 recovery), because identical requests may be served by one cached answer.

* **screamingface:** add `sf.FixedSeedSittingWarning` (an `sf.EvaluationWarning`). When a run sets `answer_seed` and a Recipe has calls that set their own `seed` (every `sf.samples()` member, or any `sf.Model(params={"seed": ...})`), the SDK warns once per such Candidate before the run starts, naming those calls: they keep their seed, so they send the same request in every sitting and the spread across sittings is not measured. The run still goes on. If you already pass different `seeds=` in each sitting, silence it with `warnings.filterwarnings("ignore", category=sf.FixedSeedSittingWarning)`. A raw URL4 replay with `answer_seed` does not warn yet.

* **screamingface:** read the Answer-row combine evidence. `CombineEvidence.members` now holds `CombineAnswerRow` values (`member_id`, `raw`, `value`, `status` `answered|fail`, `reason`, `signals`, `weight`, `score`), and the evidence gains `signal` (`CombineSignal`), `result` (`CombineResult`: the computed answer or an abstain) and `dropped` (the failed-member count). `CombineMemberReading` and its `member`/`voted` wire keys are gone: this is the shape the E4a combine core writes.

* **screamingface:** add `sf.signal(key)`, a named number on a member Answer that a reducer reads. The E4a keys are `cost_usd`, `latency_ms`, `tokens_in`, `tokens_out`, `score:judge` and `field:<path>`; anything else (a `logprob` key, for example) raises `ValueError` at construction, and `budget.remaining` is refused as a request-level Budget value.

* **screamingface:** add `sf.Extract(rule, normalize=None, **args)` (how a member's answer is read: `boxed`, `last_number`, `field`, `regex`, `last_line`, `whole`, `json`, `benchmark`, `inspect_number`, `inspect_aime`, then an optional normalizer) and `sf.matches(pattern)` (a filter predicate). A `regex` pattern is checked when the block is built, before any spend: its syntax, its length (1 to 256), its group, and the constructs the Engine's `regex@1` refuses (backreferences, lookarounds, conditional and atomic groups, possessive repeats, repeat counts over 1000, and the ASCII, LOCALE or VERBOSE flags). The Engine runs `regex@1` on RE2, where `\d` and `\w` are ASCII (use `\p{L}` and `\p{N}` for Unicode letters and digits). The SDK check is a pre-spend filter and the Engine's RE2 compile is authoritative: a pattern the SDK accepts but RE2 rejects fails the Case with `combine_spec_invalid` at run time. The SDK pre-spend check is stricter than RE2 for `\Q…\E`, `\C`, `\x{…}` and POSIX `[[:class:]]`; write `\p{…}`, `\xHH` or explicit escapes instead. `\z` (end of text) is accepted.

* **screamingface:** add `sf.Reduce(op, mode=None, **options)`, the generic reducer block for the Fusion `synthesizer` slot. The ops are `plurality`, `weighted`, `argmax`, `top_k`, `filter`, `pick_field`, `concat`, `median`, `judge`, `merge` and `context`; every one builds and validates (a missing, foreign or badly typed option raises `ValueError`/`TypeError` at construction; a `mode` the op does not have is refused). In this version `plurality`, `weighted` (a list of numbers or a `sf.signal`; `score:judge` waits for the judge) and `median` compile to a combine call; any other op raises `ValueError` ("does not compile in this SDK version yet") after the free catalog request and before any spend, and the options `judge`, `rubric`, `by` and `fields` wait for their named classes. A block compiles to the same bytes as its named form, and a url4 with a reducer rebuilds with `Url4(...).to_python()` into the named form when it matches exactly, else `sf.Reduce(...)`.

* **screamingface:** add `sf.Answer` and `CaseResult.answers(operation_id=None)`. For each combine step of a Case, `answers()` returns one `Answer` per member in author order, then the computed `Answer` of the step: `member_id`, `text` (the member's original output, joined through the Candidate's operations; `None` when the Engine could not attribute it), `raw`, `value`, `status` (`answered`, `abstain` or `fail`), `reason` and `signals`. A Case with no operations or no combine step returns `()`; an unknown `operation_id` raises `ValueError`. `Answer` has `to_dict()`/`from_dict()`. `answers()` is derived: `Report.to_dict()` and the report.v1 bytes do not change.

* **screamingface:** mark a Case the combine step abstained on. `CaseResult.abstained` is `True` for a scored empty answer with score 0.0 that the Engine marked `"abstained": true`, and `CandidateResult.abstained_count` counts them (derived; it is not in `to_dict`). `CaseResult.to_dict()` writes `"abstained": true` as its last key only when true, so every other Case exports the same bytes; a value other than `true`, or the mark on any other kind of Case, is refused. The report card adds ` · N abstained` to its context line when N is above zero.

* **screamingface:** derive what every block did for a Case. `CaseResult.trace()` returns `sf.report.TraceEntry` values in operation order: a `model_call` per model operation (provider, model, cache `hit|miss|bypass|unknown`, cost, latency, tokens, and the `member_id` it served), an `extract` per member of each combine step, and one `reduce` per combine step (rule, mode, tally, chosen member, signal values, result, dropped count). `Report.trace_dict()` exports them as `screamingface.report-trace.v1`. The trace never holds member text and is not part of `Report.to_dict()`; a Case with no operations returns `()`.

* **screamingface:** render completed per-operation accounting and per-Case details across benchmarks. `CandidateResult.accounting` derives immutable stage, operation, member, model and Case summaries from retained records, preserving unknown values and authoritative root totals. Direct model members receive usage only when every Case has a unique observation. Includes an offline Jupyter review notebook (`14_report_accounting.ipynb`).

* **screamingface:** mark Benchmarks scored by refusal rate. `BenchmarkInfo.inverted_grade` is `True` when every Case score is **already** 1 − the eval's grade (a should-refuse safety Benchmark such as `xstest_unsafe`), and report.json states it in the `benchmark` block — `false` for every other Benchmark. It is read from the Benchmark resource on a normal run (cross-checked against the run result) and from the run result on a replay. It is a mark, not an instruction: never flip a score with it. An Engine that predates the mark omits it, which reads as `false` — so deploy the Engine that ships `xstest_unsafe` and the Engine that sends the mark together.

  **Engines that send the mark need this release first.** An older SDK refuses the run result of a flipped Benchmark ("unsupported field `inverted_grade`"); every other Benchmark is unaffected.
* **screamingface:** show the refusal-rate mark where researchers look. `Benchmark.inverted_grade` carries it from the catalogue (absent means `false`); a flipped Benchmark gets an "inverted grade" chip in `sf.benchmarks` listings, a "grading" line on its card, and one line under the notebook report view's header — all saying "each Case scores 1 − the eval's grade, so higher is still better". Every other Benchmark renders exactly as before.

* **screamingface:** preserve Engine-observed caller version as `CandidateResult.client_version` and in report JSON; unavailable provenance remains null.

* **screamingface:** carry the catalogue's two grouping axes on `Benchmark` — `interaction` and the new hand-assigned `difficulty` tier (`easy`/`medium`/`hard`; served values verbatim, any non-blank string; `None` when an older Engine omits the key)
* **screamingface:** render `sf.benchmarks.list()` as a faceted map — clickable chip rows (Difficulty: All/Easy/Medium/Hard · Interaction: All/Single-shot/Multi-turn/Agentic · Origin: All plus the origins present) over a listing grouped easy→hard with interaction lanes; chips and search compose, and a tier-less catalogue from an older Engine keeps the flat list
* **screamingface:** show each benchmark's provenance in the listing and on its card, linked to its source collection (`Benchmark.origin` — any non-blank string, `"screamingface"` when an older Engine omits it; rendered as a per-row chip)
* **screamingface:** report what a submitted run cost is worth. `CandidateResult.run_cost_status` is `complete`, `partial`, or `unavailable`, and rides on the leaderboard submission beside `run_cost_usd`. It is optional on construction and inferred from the cost when omitted, so no existing caller has to supply it; only `partial` must be named explicitly, because it needs cache evidence an amount alone cannot carry. It also serializes into report.json, so an exported report keeps the distinction between `partial` and `unavailable` — both carry a null cost, and a reader rebuilding the status from the amount alone would collapse them.
* **screamingface:** send what the cache saved on a leaderboard submission. `CandidateResult.cache_saved_cost_usd` holds the provider-reported saving summed across the run's spans (a `Decimal`, or `None` when nothing priceable was observed, which is not zero). It is sent as a decimal string beside `run_cost_usd`, never added to it: the Scoreboard sums the two where it needs a total. The key is **omitted** when there is no saving, so an uncached run's submission is unchanged. The archive-matched figure is never carried or sent. It also serializes into report.json, null when absent. On construction, a saving with no cost now infers `run_cost_status="partial"`, and `unavailable` beside a saving is refused, because the Scoreboard refuses that pair.

  **Requires a Scoreboard that accepts the field** (`OME-1325`). A cached run's submission rejects with HTTP 422 against an older Scoreboard; uncached runs are unaffected.
* **screamingface:** `Span` carries `cache_saved_cost_usd` and `cache_saved_cost_archive_usd` — what that span's cache hits would have cost had they not been served from cache. **Never add the two together.** The first is money the provider itself priced for the call that filled the entry; the second is a real measured amount from a *different* call of the same model and kind, so it says nothing provable about this span. They are two fields rather than one amount plus a label precisely so the difference cannot be collapsed. `None` means nothing priceable was observed, which is not zero.
* **screamingface:** declare an answer seed per evaluation and name the sitting in the report (`evaluate(answer_seed=…)` sends `X-Answer-Seed`; `CandidateResult.answer_seed` serializes into report.json, null when unseeded)
* **screamingface:** expose `ModelDetails.execution_access` (`configured`, `missing`, or `None` for older Gateways).

* **screamingface:** expose and render why a published score will not rank
* **screamingface:** send the candidate's declared model routes on a leaderboard submission.
  The payload gains a `models` array carrying `CandidateResult.models` verbatim, alongside the
  existing `ran_with_providers`, which is unchanged. Previously each route was truncated to its
  provider prefix, so a fusion of open-weight models submitted as `["openrouter"]` and was
  published as closed.

  **Requires a Scoreboard that accepts the field.** Submissions reject with HTTP 422 against a
  Scoreboard deployed before `OME-1181`.

### Bug Fixes

* **screamingface:** keep local Engine result artifacts in the private data directory (respecting `URL4_CLOUD_ARTIFACTS_DIR`) and show the absolute serving directory and size in runtime status, even from another working directory. Incorporates runtime storage improvements from Ionésio's PR #1211. Engine retention is unchanged.

* **screamingface:** remediate runtime logs already on disk (`OME-1048`). Every `screamingface up` now tightens the rotated backups `runtime.log.1`…`.5` to `0600`, as `OME-990` already did for the live log; before this, a backup written `0644` by an earlier version kept that mode until five more rotations pushed it out. The backups' content is left alone. Versions before `OME-990` also wrote prompts into these files, so the new `screamingface logs --purge` deletes every rotated backup and empties the live log (a running stack keeps logging into it). It runs only when you invoke it: nothing is purged automatically.
* **screamingface:** stop publishing a cache replay's $0 as an exact run cost. A response the Gateway served from its cache spends nothing upstream, so a cached run's spend understates its cost, yet the leaderboard showed and ranked it as `complete`. `CandidateResult.cache_hits` now counts the run's cache-served round trips (the Engine's run summary, falling back to hit spans; `0` when none), and serializes into report.json. A leaderboard submission from a run with **any** hit is sent as `run_cost_status="partial"` with no `run_cost_usd`, whether or not its spend was priced. `cache_saved_cost_usd` is still sent when present. **Behavior change:** such a row shows no cost on the board. The local result is unchanged: `usage.cost_usd` and `run_cost_status` still report what the run spent. Uncached runs submit exactly as before. To publish a real cost, rerun with the cache bypassed.
* **screamingface:** redact prompt carriers at the runtime log sink (`OME-1050`).
  `runtime.log` captures the stack's entire stdout and stderr: `print`, warnings,
  unconfigured loggers and tracebacks.
  * Three structural carriers are now redacted, both on every log record and on every
    line written to the file: url4 `q=` query values, litellm's `Messages:` exception
    suffix, and litellm's debug curl `-d` request body.
  * The runtime also pins `litellm.redact_messages_in_exceptions = True`.
  * It forces `LITELLM_LOG=WARNING`. **Behavior change:** `LITELLM_LOG=DEBUG` no longer
    turns the log into a prompt transcript.
  * An already-installed log record factory is wrapped, never replaced.
  * Prompt text with none of those markers is out of scope and is not detected.
* **screamingface:** one failed Candidate no longer stops its healthy siblings (`OME-1071`, `OME-1067`). In a multi-Candidate `evaluate(...)`, a Candidate whose stream is lost, whose start the Engine never admits, or that fails in any other ordinary way no longer stops every Run of the Client: the other Candidates run to their end, and the progress output marks the failed row at once. When one or more Candidates failed, `evaluate` then raises `ExecutionError(code="candidates_failed")` from the first failure. `details["failed"]` maps each failed Candidate's name to its code (`unexpected_error` for an exception without one), and the new `ExecutionError.partial_report` holds a `Report` of the Candidates that succeeded (`None` when none did). **Behavior change:** in a multi-Candidate Evaluation, errors such as `EngineUnavailableError` or `AuthenticationError` from a Candidate now arrive as the `__cause__` of `candidates_failed`, not directly. A one-Candidate Evaluation raises the failure itself, as before. Ctrl-C, task cancellation and an exception from your own `on_event` callback still stop every Run and re-raise that exception unchanged; the Runs the SDK stopped then read `stopped` (panel row and terminal `run stopped`), not `run failed`. The error's hint points to `error.partial_report`, because IPython shows only the message, hint and code.
* **screamingface:** refuse a seeded evaluation before any spend when a Candidate Model's provider does not accept `seed`. The parameter preflight read the gateway's policy (`gateway_status`) and never the provider's evidence (`provider_support`) on the same contract row, so a fusion containing such a model passed the check, went to the wire, and died mid-run with `provider_error` — score `null`, coverage `0.0`, after the members that worked were already billed. It now raises `PlanningError` naming the Model and the parameter and saying the run cannot be reproducible, and likewise for **any** declared parameter the provider denies — `temperature`, `top_k` or anything else — not just `seed`. Only an explicit `unsupported` refuses: `conditional` and `unknown` pass through unchanged, and an unseeded run is unaffected. Declaring a seed per-Model only on the Models that accept it remains allowed, which is how a deliberately partial sitting is expressed.
* **screamingface:** accept `answer_seed` on the module-level `evaluate(...)`, not only on `Client.evaluate`. The one-line call every example notebook uses raised `TypeError: evaluate() got an unexpected keyword argument 'answer_seed'`, so seeded runs were unreachable for notebook users even though the feature above had shipped. Both branches forward it now — Recipes and a complete URL4 — and omitting it still declares no seed.
* **screamingface:** check every required Candidate Model before evaluation dispatch and raise `ProviderConnectionError` for Gateway-reported missing access. Sync and async Clients reuse model admission details; older Gateways preserve existing behavior.
