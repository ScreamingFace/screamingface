# ARC-Easy — Fidelity Record

## Verdict

**`comparable-to-inspect`.** Our headline is plain accuracy over the 2,376 ARC-Easy test questions. It can sit beside a run of [inspect_evals v0.20.0 `arc_easy`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/arc): zero-shot default `multiple_choice()` prompt, the `choice()` scorer, the `accuracy` metric, no generation settings. Against inspect_evals there is nothing to bound. All 2,376 Cases are the same Hub rows in the same order with the same key and options, and the same prompt bytes in one user message. Our real served Benchmark and inspect's own solver plus scorer gave the same mark on all 40,392 sheet marks. The roll-up equals to four decimals on eight vectors. Nothing is declared and nothing undeclared differs.

`sum of bounds against inspect_evals = 0/2376 = 0.0000 ≤ COMPARABLE_TOLERANCE (0.005)`

It is **not** comparable to the paper's Table 2 numbers ([Clark et al. 2018](https://arxiv.org/abs/1803.05457v1): DGEM 58.97, IR 62.55 on the Easy set). Those come from a different process by design. The [ARC-Solvers](https://github.com/allenai/ARC-Solvers/tree/8f21cb821b3a457f25535ccd1b5cddb01ed1bc4e) baselines retrieve corpus sentences and score each option. They get no prompt, write no reply, and earn 1/k for a k-way tie. The data and the marking rubric agree with ours. The authors' own file matches our 2,376 Cases row for row. Their `calculate_scores.py` gives our headline on every single-answer mark vector, and gives the paper's Guess-all 25.02 on our Cases. But the examiner being marked is a different kind of thing, so the gap cannot be bounded:

`inspect_evals vs original harness = unbounded > COMPARABLE_TOLERANCE (0.005)` (Upstream notes) → `comparable-to-inspect`

## Upstream notes

- **inspect_evals vs the original harness: a different process by design, `unbounded`.** The paper's numbers come from [ARC-Solvers@8f21cb82](https://github.com/allenai/ARC-Solvers/tree/8f21cb821b3a457f25535ccd1b5cddb01ed1bc4e) and sibling AI2 solvers (IR, TupleInference, TableILP, DGEM, DecompAttn, BiDAF). Each retrieves sentences from the ARC Corpus and gives every option a number (`fork:scripts/evaluate_solver.sh:31-75`). The highest-scored option wins, and a tie of k options that includes the key earns 1/k (`fork:arc_solvers/processing/calculate_scores.py:44-59`). [inspect_evals v0.20.0 `arc`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/arc) instead sends a zero-shot `ANSWER: $LETTER` prompt to a generative model and reads one letter (`inspect_ai:solver/_multiple_choice.py:17-23`, `:82-152`). On marks the two rules agree wherever a reply selects exactly one option: all eight roll-up vectors give the same headline under both scorers (Checks run 9). They part in two places. (1) **Ties.** A multi-letter reply such as `ANSWER: A,B` is 0 under inspect (Checks run 7 probe), where the paper's rubric gives 1/2 when the key is one of them. (2) **No answer.** An unparsed reply is 0 under inspect. The harness has no "no answer": an all-equal score vector is a k-way tie worth 1/k, which reproduces the paper's Guess-all 25.02 on our 2,376 Cases (`Exam Score:25.02`, `arxiv-src:ASQ.tex:626`). The bigger gap is the examiner itself. The harness has no prompt, no sampling and no reply, so how a generative Candidate would fare under it is undefined, and there is no Candidate run that could bound it. Hence `comparable-to-inspect`, not `comparable-to-paper`.
- **Harness vs paper.** The two agree on the rubric (`arxiv-src:ASQ.tex:573` = `fork:…/calculate_scores.py:50-51`) and on the data: the harness's own ARC-V1-Feb2018 Easy test file equals the Hub revision row for row (Checks run 9). The paper credits this repository only for DecompAttn, DGEM-OpenIE and BiDAF (`arxiv-src:ASQ.tex:634`). The repository at `8f21cb82` (2018-08-17) also downloads `ARC-V1-Models-Aug2018` (`fork:scripts/download_data.sh:15`), later than the paper (2018-03-14), so rerunning it need not reproduce Table 2 to the decimal. The harness wins, and this is recorded, not counted. No mark of ours depends on it.
- **inspect_evals artefacts, shared by ours, cosmetic.** `record_to_sample` turns the 97 rows labelled `1`–`4` into `A`–`D` by position (`inspect_evals:arc/arc.py:72-73`). The Candidate never sees the dataset's numeric labels, and `ANSWER: 2` would be 0 (probe: `'ANSWER: 1' -> 0.0`). The harness marks native labels. This changes no mark of a letter reply, and both of our sides share it (prompt row: 0 Cases differ). Bound 0.
- **No published inspect_evals number.** The eval's README has no evaluation-report section (`inspect_evals:arc/README.md:88-90`, scoring only), so "comparable-to-inspect" means comparable to a run of the pinned eval, not to a number inspect_evals printed.
