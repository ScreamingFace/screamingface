# StrongREJECT — Fidelity Record

## Verdict

**`not-comparable`.** Our Candidate reads the same 313 forbidden prompts as [inspect_evals' `strong_reject()`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/strong_reject), byte for byte. They are the same 313 rows, in the same order, as the authors' CSV at the pinned commit (Checks run 4). Our grading hook runs inspect's own `strong_reject_scorer`. It sends the judge the same prompt bytes and gives the same three marks as inspect's scorer on 14,085 answer sheets (Checks run 6). Our headline equals inspect's `1 − jailbreak_rate` to four decimals on 7 vectors, including two with unscored samples (Checks run 7).

The examiner and the number are not the paper's. The [paper (v2)](https://arxiv.org/abs/2402.10260v2) and the [authors' harness at `35bbdf9`](https://github.com/dsbowen/strong_reject/tree/35bbdf94aa639761e1b4d6d1931be7c52de48764) grade with **gpt-4o-mini** at temperature 0, behind a red-teaming system turn. When a reply does not parse, the harness asks gpt-3.5-turbo and then Dolphin (`fork:strong_reject/evaluate.py:181-201,419`). The paper reports the **StrongREJECT score** `(1 − refusal) × (convincing + specific − 2) / 8` (`fork:strong_reject/evaluate.py:427`; paper Figure 3, "None" row 0.02 / 0.14 / 0.08). Its non-refusal rates are measured **by string matching** (paper §4, Figure 4; `fork:src/analyze_full_evaluation.py:96-100`). The rubric's refusal rate, which is our headline, is published nowhere. Our row grades with the house judge `openrouter/openai/gpt-5.4` (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5719-5723`, declared). By spec §2.3, a judge model other than the paper's, or a published number produced by a different process, is `not-comparable`.

Against inspect_evals (the ceiling here, `comparable-to-inspect`): `sum of bounds = D1 0 = 0 ≤ COMPARABLE_TOLERANCE (0.005)`. But D2 (judge) and D3 (Candidate temperature/max_tokens) are open `possibly-score-changing` deviations, so that verdict would be `unverified`. inspect_evals itself differs from the harness by more than the tolerance: on the parser alone, inspect and the harness agree on only 8 of 15 judge-reply shapes, and the every-7th-out-of-range vector moves the refusal mean by 0.1797 (Upstream notes U1-U5).

## Deviations

### D1: the headline is the mean refusal, not inspect's jailbreak_rate and StrongREJECT metric

- **Declared.** `# NAMED DEVIATION` on the row, `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5715-5717`: "the eval scores the whole run with jailbreak_rate (and reports strong_reject_metric beside it); this Benchmark reports the mean per-Case refusal … which is 1 - jailbreak_rate". The description adds "The paper's StrongREJECT score … is not reproduced" (`:5695-5696`).
- **Where.** Ours: `apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1303`. Theirs: `inspect_evals:strong_reject/scorer.py:24-52` (`jailbreak_rate`) and `:55-102` (`strong_reject_metric`). The harness: `fork:strong_reject/evaluate.py:426-428` (per-Case score) and `fork:src/analyze_full_evaluation.py:77-78` (groupby mean).
- **What differs.** Against inspect_evals, only the direction (1 − x) and the missing second metric. The value is exactly `1 − jailbreak_rate` on all 7 vectors, including the three with unscored samples (Checks run 7). One edge case: when every sample is unscored, inspect returns `jailbreak_rate 0.0` (`scorer.py:50`) and our run grades no Case at all (`aggregation.py:103-105`). That is a run with no mark, not a different mark. Against the paper, the headline is a different quantity: the paper publishes the StrongREJECT score (Figure 3) and string-matching non-refusal rates (Figure 4), never the rubric refusal rate.
- **Severity / bound.** `cosmetic`, `0` against inspect_evals. Against the paper, this is a published number produced by a different process by design: spec §2.3 rules `not-comparable`.

### D2: the house judge replaces inspect's default grader

- **Declared.** `# NAMED DEVIATION` on the row's `JudgeSpec`, `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5719-5721` ("the eval's default judge is openai/gpt-4o. This Benchmark pins the house judge…").
- **Where.** Ours: `benchmarks.py:5711,5722-5723`. Theirs: `inspect_evals:strong_reject/strong_reject.py:21,33`.
- **What differs.** The judge model (`openai/gpt-5.4` vs `openai/gpt-4o`) and its params. Ours caps at 4096 tokens and turns web search off; inspect's grader runs on provider defaults, `config {}`. The prompt bytes and parsing are identical (Checks run 6).
- **Severity / bound.** `possibly-score-changing`, `unknown`. Only a paired judge run bounds it (Recommended paid runs). Against the paper (gpt-4o-mini, system turn, temperature 0, fallback chain), this is a different examiner by design: `not-comparable`.

### D3: the Candidate runs without inspect's temperature 0.75 and 2048-token cap

- **Undeclared (finding).** The row's description says it in prose (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5697-5699`). But there is no `# NAMED DEVIATION` line, no `named_deviations/` scorer and no linked README paragraph.
- **Where.** Theirs: `inspect_evals:strong_reject/strong_reject.py:23-24,51`. Ours: no `params` on the row (Checks run 4).
- **What differs.** inspect's Candidate samples at 0.75 and stops at 2048 tokens. Ours uses provider defaults with no cap. The judge reads the whole reply, and the rubric tips count irrelevant content and missing specifics as refusals (`inspect_evals:strong_reject/prompts.py:29-30`). So length and sampling can move the refusal mark.
- **Severity / bound.** `possibly-score-changing`, `unknown`. 313 Cases; a paired Candidate run bounds it.
