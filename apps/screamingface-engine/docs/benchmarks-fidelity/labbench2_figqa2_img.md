# LABBench2 FigQA2 (image) — Fidelity Record

## Verdict

**`not-comparable`.** Our headline is the mean mark over the 101 FigQA2 image Cases, with a failed Case counted 0. It cannot sit beside the paper's 0.614 for GPT 5.2 Pro. That number is the authors' own report, `fork:assets/reports_paper/figqa2-img/file/gpt-5-2-pro.json`: 62/101 = 0.6139, published at [`a1a36b8`](https://github.com/EdisonScientific/labbench2/tree/a1a36b8fd5f56f7bbeae7353b77278dad1858651). The authors' README says those reports "are the reports used in the paper" and were produced "using native SDK runners" (`fork:README.md:208`). **Against the harness the row pins, [`0cabab27`](https://github.com/EdisonScientific/labbench2/tree/0cabab27f6a23a5bc060a4699205709f1be7e93f), our Benchmark matches on every free check.** The sealed Case Digest reproduced. The text and picture bytes the Candidate is sent equal the authors' file-mode Cases on 101/101. Judge-prompt bytes and marks agree on 1,818 answer sheets × 2 judge-reply shapes. The roll-up equals theirs on 16 mark vectors, the paper's own 10 included. **But 0cabab27 did not produce the published number.** The February run (D2) sent the Candidate a different prompt on all 101 Cases: an older instruction sentence, a picture with a hash file name, and the picture before the text for OpenAI models. Its judge also read a different exact-match prompt (D3). The prompt change is declared, but it is `score-changing` with bound `unbounded` (Candidate behaviour), so the rule gives `not-comparable`: `sum of bounds against the original harness = unbounded (D2) + 11/101 (D1) > COMPARABLE_TOLERANCE (0.005)`. Two `possibly-score-changing` items stay open behind it: the judge path (D3) and the Candidate token cap (D4). The 101-call re-judge in Recommended paid runs would bound D3. Nothing free can bound D2.

## Deviations

### D1 — the February paper runs read an earlier dataset revision (whitespace)

- **Undeclared.** The row and README declare the pin `3678e7e3` (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/lab_bench_2/lab_bench_2.py:61-63`). Neither says the paper's GPT and Gemini runs read other bytes.
- **Where.** Ours: the pinned rows. Theirs: `load_dataset(LABBENCH2_HF_DATASET, config, split="train")` with no revision (`fork:evals/loader.py:150`). The 2026-02-03 runs therefore read the dataset's HEAD of that day.
- **What differs.** Whitespace only, verified with `re.sub(r"\s+"," ",…)` equality. Questions differ on Cases 14, 22, 44, 48, 52, 72, 78, 79 and 95 (a trailing space or a double space) and on Case 25 (a narrow no-break space, U+202F, before `dva`). The gold of Case 85 is `'NifK '` in the paper run, `'NifK'` ours. The 4 March runs (Claude) match ours on 101/101.
- **Severity / bound.** `score-changing`, `11/101` — Cases 14, 22, 25, 44, 48, 52, 72, 78, 79, 85, 95. The Candidate and the judge both read these bytes and neither strips them. A reviewer may argue `cosmetic`; the verdict does not depend on it.
- **Evidence.** Checks run 10-11.

### D2 — the Candidate prompt follows the authors' October 2026 file mode, not the one that produced the paper's number

- **Declared in part.** README `apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/lab_bench_2/README.md:71-75` and the row description (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:7424-7425`) both say we follow the authors' current harness where the inspect port's older copy differs. The README names the old sentence. Neither says the paper's runs used that old sentence. The picture's file name and the native OpenAI part order are undeclared.
- **Where.** Ours: `apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/lab_bench_2/vendor/labbench2.py:76-85`, `lab_bench_2.py:151-161`. Paper run: `fork@a1a36b8:evals/loader.py:91` (sentence), `fork@a1a36b8:evals/runners/openai.py:90,110` (image first, Files API upload). The change landed in `8d50928` (2026-10-15, "Add file prompt filenames").
- **What differs.** It differs on every Case (a, b and c are described in the prompt row). For example, Case 1 paper run: `"For L1 Layer M1 neurons, … dark condition?\n\nIn your answer, refer to files using only their base names (not full paths)."` with a picture the model called `cdb83df38aac2b286d7a8fb2eea6a403.png`. Ours: `"… dark condition?\n\nAttached files:\n- figure.png\n\nUse only the exact base filenames above. Copy them exactly, including case and extension. Do not rename them or use full paths."` then `figure.png`.
- **Severity / bound.** `score-changing`, `unbounded`. Whether the new wording, file name and part order move a Candidate's marks depends on that Candidate's behaviour, which no free check can bound.
- **Evidence.** Checks run 10, 12.

### D3 — the judge path differs from the paper run's: no schema, OpenRouter, the October 2026 exact-match prompt

- **Declared in part.** No response schema: `# NAMED DEVIATION` at `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:7493` and README `:65-67`. Following the authors' current template rather than the port's: README `:71-75`. Undeclared: the paper run's judge also read the older template, and the route is OpenRouter rather than Anthropic's API.
- **Where.** Ours: `apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/lab_bench_2/lab_bench_2.py:265-272` with the row's `JudgeSpec` (`benchmarks.py:7487-7495`). Paper run: `LLMJudgeEvaluator` with `output_type=EvaluationResult` (`fork@a1a36b8:evals/evaluators.py`, same as `fork:evals/evaluators.py:45-49`) and the pre-`4ef83d3` template (`fork@a1a36b8:evals/prompts.py:37`). That template has no "If the ground truth answer is not a number…" lines. Its `{question}` is the old question text (D2).
- **What differs.** The same model and temperature receive different prompt bytes on all 101 Cases, return their verdict in free text instead of a tool-call schema, and are reached through a different provider route. With the same verdict word, the mark is the same: 0 mark differences on 1,818 sheets in both reply shapes. What is unknown is whether the judge gives the same verdict.
- **Severity / bound.** `possibly-score-changing`, `unknown`, see Recommended paid runs. The template's new rule mainly bears on the 26 Cases whose ideal is not a plain number: 1, 4, 5, 6, 9, 12, 13, 17, 21, 22, 23, 25, 27, 39, 62, 63, 65, 68, 69, 72, 73, 82, 84, 85, 87, 100.
- **Evidence.** Checks run 5, 13, 15.

### D4 — the Candidate's sampling is left to the run, where the harness fixes a cap and retries

- **Undeclared.**
- **Where.** Ours: no Candidate params on the row (Checks run 2) or in the Task. Theirs: `fork:evals/runners/anthropic.py:10-15,122` (64,000 for Opus/Sonnet), `fork:evals/llm_configs.py:36` (64,000 on the pydantic-ai path), `fork:evals/run_evals.py:154-158` (5 task attempts). The native OpenAI path, which produced the 0.614 headline, sets no cap (`fork:evals/runners/openai.py:114-124`).
- **What differs.** A run whose Candidate cap is below what the paper's model would write truncates answers the paper run kept. A transient Candidate failure counts 0 for us and is retried by them.
- **Severity / bound.** `possibly-score-changing`, `unknown`. It depends on the run's Candidate config. A run with no cap below the provider's default (OpenAI) or 64,000 (Claude), and no failed Candidate calls (coverage 101/101), has no gap here.
- **Evidence.** Checks run 2, 15.

## Upstream notes

- **The pinned harness is not the code that produced the paper's numbers.** `0cabab27` changed both the Candidate's file-mode prompt (`8d50928`, 2026-10-15) and the judge's exact-match template (`4ef83d3`, 2026-10-07) after the paper's runs (2026-02-03 to 2026-03-23). The authors kept the paper reports unchanged in `assets/reports_paper/`. So a run of the current harness is not comparable to the paper either. Bound: `unbounded`, as D2.
- **The paper's native runners could leak uploaded files across concurrent questions.** Fixed in `4477bd5` (2026-10-07, "leaking uploaded files across concurrent questions"). In the paper-era OpenAI runner, `upload_files` reset a shared `self.file_refs` and returned it (`fork@4477bd5^:evals/runners/openai.py:46,60,73`). Under `--parallel` (default 30, `fork:evals/run_evals.py`), a question could therefore be sent another question's figure, or several. Whether the paper's runs hit this is not recorded. Bound on the published number: `unknown`.
- **The authors load the dataset unpinned** (`fork:evals/loader.py:150`, no `revision`). Their February and March runs read different bytes (D1), and a current run of their harness reads whatever HEAD is.
- **Two accuracies.** The authors print "Accuracy (overall)", which counts failures as incorrect, and "Attempted Accuracy" (`fork:evals/run_evals.py:188,192`). The paper's reports have 0 failures, so both equal the published number. Our `withhold` is the overall one.

Its register points to the [Generality-Labs port at `081864a`](https://github.com/Generality-Labs/lab-bench/tree/081864af494b180ecf6aae3f7333e384c0d227af/src/lab_bench_2).
