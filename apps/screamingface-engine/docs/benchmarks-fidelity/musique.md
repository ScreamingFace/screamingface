## Verdict

**`not-comparable`.** Our headline, mean answer F1 over the 2,417 MuSiQue-Ans dev questions, is computed by the authors' own scoring code (vendored byte for byte below our header, sha256-pinned) over the authors' own dev file (sha256 `15fa6379…`, identical on the Hub mirror and in the authors' Google Drive zip), and the marks agree with the harness on 19,336 of 19,336 structured answer sheets and to four decimals on five whole-run vectors. The row already says so in its own words ("our runs sit beside it rather than on the same scale", `benchmarks.py:4209`). Nothing undeclared was found.

## Deviations

### D1 — our own prompt wording; the paper has none

- **Declared.** `README.md:29` ("The paper's models were fine-tuned, so there is no official prompt to copy; the wording is ours."), `musique.py:33-36` (`WHY no official prompt`), and `test_a_row_renders_to_the_pinned_prompt_bytes` (`test_local_task_musique.py:179`) pins the bytes as Benchmark identity.
- **Where.** Ours: `CASE_TEMPLATE` / `PARAGRAPH_TEMPLATE` (`musique.py:74-85`), rendered by `_record_to_sample` (`:108-124`). Theirs: `fork:allennlp_lib/data/dataset_readers/transformer_rc.py:38-396` builds Longformer token sequences for training and inference; `fork:experiment_configs/end2end_model_for_musique_ans_dataset.jsonnet:8`.
- **What differs.** The Candidate reads an instruction, `[idx] Title` + text paragraphs and a two-line answer format; the paper's models read tokenised paragraph/question pairs through fine-tuned weights. There is no reference prompt to diff against.
- **Severity / bound.** `score-changing`, `unbounded`: the wording can move any Case's mark and no comparison can enumerate which.

### D2 — a reply reader where the harness reads structured predictions

- **Declared.** `README.md:46-48`, the row's description (`benchmarks.py:4207`), `test_the_reply_reader_takes_the_last_committed_lines` (`test_local_task_musique.py:169`).
- **Where.** Ours: `_committed_value` / `extract_answer` / `extract_support` (`musique.py:133-156`). Theirs: `fork:evaluate_v1.0.py:43-53` reads `predicted_answer` and `predicted_support_idxs` fields; `fork:raw_predictions_to_official_format.py:34-36` fills them from the model's span prediction.
- **What differs.** We turn free text into the two fields the harness expects (last label wins, label-less reply graded whole, support empty). Given the same two fields, both sides mark identically (19,336/19,336); given a labelled free-form reply, a harness with no reader would mark it differently on every Case (Checks run 14), which is why the reader exists.
- **Severity / bound.** `score-changing`, `unbounded`: which replies a Candidate writes is not enumerable without a run.
