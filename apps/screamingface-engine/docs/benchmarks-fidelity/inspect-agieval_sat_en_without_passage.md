### D1 — inspect_evals' temperature 0, 2048-token cap and top_p 1 are not applied, and the row does not say so

- **Undeclared.** The row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:2437-2497`) has no `# NAMED DEVIATION` / `Named Deviation:` line, no `params`, and its description (`:2441-2449`) does not name the dropped settings. Other rows follow it, for example `benchmarks.py:5772` ("inspect_evals runs the model at temperature 0 with 512 max tokens; this benchmark …"), and the MATH row carries the comment form (`benchmarks.py:4189-4191`). This row has neither, so this is a **finding**. The eight sibling AGIEval rows share the same Task template (`utils.py:196`) and were not audited here.
- **Where.** Theirs: `inspect_evals:agieval/utils.py:196` (comment `:195` "from source paper 4.2.4: Implementation Details"). Ours: no setting exists. The importer never reads `task.config` (`benchmarks.py:4190`; `grep` for `task.config` over `src/screamingface_engine_inspect/` finds only that comment, Checks run 4).
- **What differs.** An inspect_evals run asks the model for greedy decoding (temperature 0, top_p 1) and cuts the reply at 2,048 tokens. Our Candidate answers with its provider's defaults and no token cap from the Benchmark. A reasoning reply longer than 2,048 tokens loses its final `ANSWER:` line under inspect but keeps it here. A sampled reply can pick a different letter.
- **Severity / bound.** `possibly-score-changing`, `unknown`. It changes what the Candidate writes, not how a given reply is marked (the 3,090 marks are identical). Only a paid run can measure it.
- **Evidence.** The source lines above, and Checks run 6 (`task.config 0.0 2048 1.0`).

## Upstream notes

- **inspect_evals vs the original harness: a different examiner, `unbounded`.** [inspect_evals v0.20.0 `agieval`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/agieval) says its prompts are "based on" the original (`inspect_evals:agieval/README.md:205-207`). It departs from [ruixiangcui/AGIEval@84ab72d9](https://github.com/ruixiangcui/AGIEval/tree/84ab72d94318290aad2e4ec820d535a95a1f7552) in two ways. (1) **Prompt.** inspect sends an instruction template asking for `'ANSWER: $LETTER'` with `A) option` lines (`utils.py:68-76`). The harness's zero-shot prompt is a completion stub, `Q: <question> Answer Choices: (A)… (B)…\nA: Among A through D, the answer is`. It runs in two chat stages: first the free reply, then a second turn ending `Therefore, among A through E, the answer is` (`fork:src/dataset_loader.py:25-35`, `:250-277`; `fork:run_prediction.py:163-166`). Its few-shot prompt is 3 chat-mode demonstrations taken from `sat-en` with their passages stripped, answered `The answer is therefore X` (`fork:src/dataset_loader.py:87-118`; Checks run 7 rendered Case 1: 7 messages, 3 shots). inspect's own `fewshot=N` draws N rows from the test set itself (`utils.py:175-181`), not the harness's demonstrations. (2) **Answer extraction.** inspect reads the `ANSWER:` line (`inspect_ai:solver/_multiple_choice.py:98-121`). The harness takes the first capital A-F in zero-shot (`fork:src/post_process.py:72-78`, `:187-189`). In few-shot it uses `answer is .*?([A-G])` and then that same fallback (`:29-43`, `:64-69`). On the sheets (Checks run 7), a reply in inspect's own format, `ANSWER: C`, is credited by the harness only when the key is A, because it reads the `A` of `ANSWER` (disagree 142/206). Replies in the harness's formats (` C`, `(C)`, `The answer is C.`) are credited by the harness and failed by inspect on 206/206. The gap depends on how a Candidate formats its replies, so it cannot be bounded without a run: `unbounded`. This is why `comparable-to-paper` is out.
