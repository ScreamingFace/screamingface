# RACE-H — Fidelity Record

## Verdict

**`unverified`.** Our headline is plain accuracy over the 3,498 questions of the RACE high-school test split. On every grading dimension it is the same examiner as [inspect_evals v0.20.0 `race_h`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/race_h): zero-shot, the eval's own `ANSWER: $LETTER` template, the `choice()` scorer and the `accuracy` metric. All 3,498 Candidate inputs equal inspect's own solver prompt byte for byte; our 55,968 answer-sheet marks, taken from the real served Benchmark's aggregate route, equal inspect's solver plus scorer on every sheet; and the roll-up equals to four decimals on seven vectors. D1, the forced row-shuffle seed, is declared and cosmetic. D2 is open and undeclared: inspect_evals pins `GenerateConfig(temperature=0.0)` on the Task and our Benchmark applies no generation settings. It changes what the Candidate writes, not how a reply is marked, so only a paid run can bound it:

`bounds vs inspect_evals = 0/3498 (D1, cosmetic) + unknown (D2, sampling, undeclared, possibly-score-changing) → an open possibly-score-changing deviation → unverified`

The paper's numbers are out of reach in any case. [Lai et al. 2017 v5](https://arxiv.org/abs/1704.04683v5) Table 5 reports RACE-H test accuracy for neural readers trained on the RACE train split (Stanford AR 43.0, GA 44.2), Mechanical Turk workers 69.4 on a 250-question sample, and a ceiling of 94.2 (the share of questions the authors judged valid). The [authors' code](https://github.com/BinbinBian/RACE_AR_baselines/tree/ae5f5fb3c8e8866845a03e57a8209655fcb26423) picks the argmax of the model's four option scores, so it reads no text and the sheets cannot be sent through it. The row's frontier number (Claude 3 Opus 0.929, 5-shot) is vendor-graded from a model card. Both are different examiners by design: `inspect_evals vs original harness = unbounded` (Upstream notes). D2 can be closed by a paid run, or by an owner ruling declared on the row as other rows already do (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:3335`, `:4189`); the verdict would then be `comparable-to-inspect`.

### D1 — row order forced by a declared shuffle seed

- **Declared.** `apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:1025` ("Fold: same Cases; order forced by shuffle_seed through inspect's shuffle (D1)") on the spec `prepare.py:1029-1040`, `shuffle_seed=20260917` at `:1037`; the mechanism in `docs/spec/2026-10-02-ome-1460-one-fetch-path.md:281` (D1 row), and race_h listed under "our row shuffle, upstream unseeded" at `:365`; the row description says "Cases are served in a fixed seeded shuffle" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:876`).
- **Where.** Ours: `fetch_pins_of(spec)` (`apps/screamingface-engine/src/screamingface_engine_inspect/task_replay.py:404-411`) hands the seed to the recorder, which forces it onto the eval's `hf_dataset(shuffle=True)` call. Theirs: `inspect_evals:race_h/race_h.py:47`, `:54` (`shuffle=shuffle`, default `True`, no seed) → `inspect_ai:dataset/_sources/hf.py:264-265`.
- **What differs.** Case numbering only: ours is one fixed permutation of the Hub order; inspect_evals' is a fresh random one per run. `filter_duplicate_ids` runs after the shuffle and keeps the first occurrence, so order could choose between duplicates, but the pinned revision has none (`hub exact duplicate rows 0`). Text, options and keys are identical (dataset row).
- **Severity / bound.** `cosmetic`, `0`: a Case's mark does not depend on its position (all 55,968 marks identical).

### D2 — inspect_evals' temperature 0 is not applied

- **Undeclared.** The row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:866-924`) has no `# NAMED DEVIATION` / `Named Deviation:` line and no `params`; its description (`:870-882`) says nothing about generation settings; it names no `dropped_scorers` or `excluded_sample_ids` and links no README. The catalogue has a convention for this: the MATH row carries `Named Deviation: the Task's config=GenerateConfig(temperature=0.5) is not applied` (`benchmarks.py:4189-4190`), following decision D10 (`docs/plan/2026-10-05-OME-1268-multi-score-benchmarks.md:70`, "the importer never reads `task.config`"). This row does not follow it, so it is a finding.
- **Where.** Theirs: `inspect_evals:race_h/race_h.py:68`. Ours: no setting; Case Preparation's stub `generate` accepts the generation config and ignores it (`apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:243-247`), and the row carries no `params`.
- **What differs.** An `inspect eval` run asks the model for greedy decoding (temperature 0). Our Candidate answers with its provider's default temperature. Some reasoning models reject or ignore temperature anyway.
- **Severity / bound.** `possibly-score-changing`, `unknown`. It changes what the Candidate writes, not how a reply is marked (every sheet mark is identical). Only a paid run can measure the gap.
- **Evidence.** The two source locations above; `task config 0.0 None None` (Checks run 4); the row `awk` with no hits (Checks run 3).

## Upstream notes

- **inspect_evals vs the original harness: a different examiner by design, `unbounded`.** [inspect_evals v0.20.0 `race_h`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/race_h) asks a generative model zero-shot with a [simple-evals](https://github.com/openai/simple-evals/blob/main/mmlu_eval.py)-style template (`README.md:7`) for an `ANSWER: $LETTER` line, then marks the letter. The authors' code ([RACE_AR_baselines, surviving copy at `ae5f5fb3`](https://github.com/BinbinBian/RACE_AR_baselines/tree/ae5f5fb3c8e8866845a03e57a8209655fcb26423)) trains a Stanford Attentive Reader or Gated-Attention reader on the whole RACE train split (middle and high, 87,866 questions per the paper's Table 2; `fork:src/train_GA.sh:1` passes `../data/data/train`, and `fork:src/utils.py:21-24` walks both `middle` and `high`), lower-cases and tokenises the text (`fork:src/preprocess.py:6-11`), and marks the argmax of four option scores (`fork:src/main.py:150`). There is no prompt and no text to extract, so no sheet passes through it; the published RACE-H numbers (Stanford AR 43.0, GA 44.2) are trained-model numbers. The human row (Turkers 69.4) covers a 250-question sample, not the 3,498-question split; the ceiling (94.2) is the share of questions the authors judged valid ("unambiguous and has a correct answer") on a manual check, not a measured reader. Both examiners take a plain mean (`fork:src/main.py:175-187` vs `inspect_ai:scorer/_metrics/accuracy.py:37`), which the roll-up row confirms.
