# AIME 2024 — Fidelity Record

## Verdict

**`unverified`.** Our headline is plain accuracy over the 30 problems of [AIME 2024](https://artofproblemsolving.com/wiki/index.php/2024_AIME_I) I and II, as served by [inspect_evals v0.20.0 `aime2024`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/aime2024). Against inspect_evals, the Cases are the same 30 rows of [`Maxwell-Jia/AIME_2024@8d88b287`](https://huggingface.co/datasets/Maxwell-Jia/AIME_2024/tree/8d88b2876a82a080e2f172cc9b25d0d9d2cb4792) in the same order. The prompt bytes match inspect's own solver on 30/30 Cases. The roll-up matches to four decimals on 11/11 vectors. The marks match on every finished reply. **The one difference is declared, and its size depends on the run.** D1, the cut-off guard adopted from [inspect_evals issue #2701](https://github.com/UKGovernmentBEIS/inspect_evals/issues/2701) (still open), marks a reply wrong when it stopped at `max_tokens` and its last substantive line has no `ANSWER:`. inspect_evals v0.20.0 credits such a reply when its last line ends in the key. On the answer sheets it flips 4 of 16 sheet kinds on all 30 Cases. On a real run it touches every Case whose reply was cut off with a lucky last line, which depends on the Candidate and its token limit, so its bound is `unknown` until a run's Report is read: `sum of enumerable bounds against inspect_evals = 0/30 = 0.0000`, plus D1 `unknown` (open, `possibly-score-changing`) → `unverified`. With 30 Cases one moved Case is already `1/30 = 0.0333 > COMPARABLE_TOLERANCE (0.005)`, so a run whose Report shows zero affected Cases is `comparable-to-inspect` for that run, and any other count is `not-comparable` against v0.20.0. D1 only ever turns a credit into a miss, so on the same replies our score is never higher than inspect_evals v0.20.0's. Against a paper there is nothing to compare: AIME has no paper and no authors' harness. The row's Frontier Score (o4-mini 0.934, OpenAI) came from an unpublished vendor harness, a different process by design (Upstream notes), so `comparable-to-paper` is out of reach.

## Deviations

### D1 — a reply cut off before its `ANSWER:` line is marked wrong

- **Declared.** It has a `# NAMED DEVIATION` line on the row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:953-957`) and a scorer under `named_deviations/` (`benchmarks.py:958`, `scorer="screamingface_engine_inspect.named_deviations.aime.aime:aime_cut_off_scorer"`, and the `answer_rule` grader `:989-993`). The Benchmark description says it too ("A reply the token limit cut off before its 'ANSWER:' line is wrong … This is inspect_evals' proposed fix (issue #2701), adopted here"). The source is [inspect_evals issue #2701](https://github.com/UKGovernmentBEIS/inspect_evals/issues/2701): `state open`, created `2026-10-15`, `closed_at None` (Checks run 7).
- **Where.** Ours: `apps/screamingface-engine/src/screamingface_engine_inspect/named_deviations/aime/aime.py:49-71`. Stage 1 is `:57` (an empty reply falls through), stage 2 the guard at `:61`, stage 3 the fall-through to the eval's scorer at `:69`. The stop reason comes from the Candidate's finish reason through `stop_reason=_stop_reason(request.finish_reason)` (`apps/screamingface-engine/src/screamingface_engine_inspect/scorer_adapter.py:641`, `:745-778`), which calls inspect's `as_stop_reason`: `"length"` → `"max_tokens"`, `None` / anything unlisted → `"unknown"` (`inspect_ai:model/_model_output.py:426-438`). The field is `GradeRequest.finish_reason` (`apps/screamingface-engine/src/screamingface_engine/benchmarks/shared_grading/benchmark_aggregation.py:139`). Theirs: `inspect_evals:utils/aime_common.py:70-100`, which never reads the stop reason.
- **What differs.** A reply whose stop reason is `max_tokens` and whose last substantive line holds no `ANSWER:` gets INCORRECT with `answer=None`. inspect_evals v0.20.0 de-boxes that line and credits it if it ends in the key. This covers a cut-off `\boxed{N}` line, a `$$ \boxed{N} $$` block and `The answer is N.`, not only #2701's mid-reasoning reproduction (Checks run 5). It never turns a miss into a credit: ours sum ≤ inspect sum on every sheet. Three edges, all faithful to #2701 and pinned by the parity test: a reply cut off inside or right after its `ANSWER:` line keeps its credit (`test_named_deviation_aime.py:76`, `:88`). A reply whose finish reason never reached the grader (`None` → `"unknown"`) grades as v0.20.0 (`:113`), and so does a provider's `model_length`, because `as_stop_reason` passes it through unchanged (`inspect_ai:model/_model_output.py:435-436`) and the guard tests for `"max_tokens"` only.
- **Severity / bound.** `possibly-score-changing`, `unknown` (a Report read settles it per run). It moves the marks of exactly the Cases whose reply was cut at the token limit with a non-`ANSWER:` last line that v0.20.0 would credit. That set depends on the Candidate and its token limit, so no Case list exists before a run. On the sheets it is 120 of 1,440 marks (4 sheet kinds × 30 Cases). On a given run's records it is countable for free, since the Case record keeps the provider's finish reason (`scorer_adapter.py:745-778` docstring). It is 0 on any run where no Case finished with `length`.
- **Evidence.** Checks run 5 (sheets) and 6 (`test_tripwire_a_cut_off_reply_inspect_evals_credits_is_wrong_under_ours`, `test_named_deviation_aime.py:61`, asserts v0.20.0 gives CORRECT and ours INCORRECT on #2701's reproduction).

## Upstream notes

- **No paper and no original harness.** [AIME 2024](https://artofproblemsolving.com/wiki/index.php/2024_AIME_I) is a human competition run by the [Mathematical Association of America](https://maa.org/); its answer key is an integer per problem.
