# PubMedQA — Fidelity Record

## Verdict

**`comparable-to-paper`.** Our headline, plain accuracy over the 500 PQA-L test questions in the reasoning-required setting (question + abstract context, no long answer), can sit beside the numbers of [Jin et al. 2019, arXiv 1909.06146v1](https://arxiv.org/abs/1909.06146v1) (single human 78.0%, BioBERT 68.1%) and the [PubMedQA leaderboard](https://pubmedqa.github.io/), all of which are accuracy as computed by the authors' [`evaluation.py`](https://github.com/pubmedqa/pubmedqa/tree/1cbae8e92f72f20c8d3747cbb3bf5bc53554d997) (`sklearn.accuracy_score` over the same 500 PMIDs). The examiner is the same on every dimension the harness defines: the same 500 PMIDs with the same gold labels (our Grading Material, the Hub `final_decision` and the harness's `data/test_ground_truth.json` agree on all 500), the same question and context text as the harness's `data/ori_pqal.json`, the same per-Case rule (predicted label == gold) and the same pooled accuracy (equal to four decimals on 18 vectors through ours, inspect's `accuracy()` and the harness's `evaluation.py` itself). The harness defines no LLM prompt and no answer extraction (it reads a `{PMID: "yes"|"no"|"maybe"}` file); those two layers are inspect_evals' (`ANSWER: $LETTER` template and `parse_answers`), and ours is byte- and mark-identical to inspect_evals on them (500/500 prompts, 7,000/7,000 marks). One undeclared, cosmetic deviation exists (D1: the harness also prints macro-F1, the paper's second main metric; we, like inspect_evals, serve accuracy only): `sum of bounds against the original harness = 0/500 = 0.0000 ≤ COMPARABLE_TOLERANCE (0.005)` → `comparable-to-paper`. Caveat in Upstream notes: the row's `frontier_score` (GPT-4 Medprompt 0.82) is a self-reported leaderboard entry whose prompting and answer extraction were the vendor's own.

## Deviations

### D1 — macro-F1 not served

- **Undeclared.** No `# NAMED DEVIATION` line, `named_deviations/` scorer, `dropped_scorers` or `excluded_sample_ids` on the row (`grep -rln pubmedqa src/screamingface_engine_inspect/named_deviations/` → exit 1; `awk` over `benchmarks.py:1927-1982` for `NAMED DEVIATION|dropped_scorers` → no line). The row's description says "Benchmark score = plain accuracy over the cases run" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:1931-1939`), which states the choice but is not one of the declaration forms.
- **Where.** Ours: `_accuracy` publishes one headline (`apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1275-1303`), as inspect_evals' `choice()` declares one metric (`inspect_ai:scorer/_choice.py:61`). Theirs: `fork:evaluation.py:18-22` prints `Accuracy` and `Macro-F1`; the paper names both as "the main metrics of PubMedQA" (§3.3 Evaluation Settings) and reports both in Table 5.
- **What differs.** A second whole-run number (macro-F1 over yes/no/maybe) the authors print and we do not. The headline accuracy, the only column the [leaderboard](https://pubmedqa.github.io/) ranks by and fills for every entry (its LLM entries show macro-F1 `NA`), is unchanged.
- **Severity / bound.** `cosmetic`, `0`: no Case's mark and not the headline can change (Checks run 8: harness `Accuracy` equals ours on all 18 vectors).

- **The harness defines no prompt and no answer extraction; inspect_evals supplies both, and the harness leaves them open.** [pubmedqa/pubmedqa@1cbae8e9](https://github.com/pubmedqa/pubmedqa/tree/1cbae8e92f72f20c8d3747cbb3bf5bc53554d997) scores a `{PMID: "yes"|"no"|"maybe"}` file (`fork:README.md:22`, `fork:evaluation.py:10-18`); the paper's systems are fine-tuned classifiers. [inspect_evals v0.20.0 `pubmedqa`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/pubmedqa) adds a zero-shot `ANSWER: $LETTER` template with yes/no/maybe as `A) B) C)` (`pubmedqa.py:22-30`, `:69-83`) and inspect's `ANSWER:` regex. Consequence on the sheets: a reply that names the label in words (`yes`, `ANSWER: yes`) scores 0 under inspect and ours, though a person preparing the harness's label file would read it as `yes`. This is not counted as a gap: on every dimension the harness defines (ids, gold, input content, per-item rule, aggregate) inspect_evals equals it (dataset, metric and roll-up rows), and the reply format is a Candidate-facing instruction the authors left open ("There isn't an official prompt template", `inspect_evals:pubmedqa/README.md:120`). It does mean a Candidate that ignores the instructed format loses marks here that it might not lose in a vendor's own pipeline.
- **Leaderboard frontier numbers are self-reported.** The row's `frontier_score` (GPT-4 Medprompt, 0.82, `benchmarks.py:1975`) and Med-PaLM 2 (0.818) appear on the leaderboard with macro-F1 `NA`, i.e. reported by their authors with their own prompting and answer extraction (Medprompt: few-shot, chain-of-thought and choice-shuffle ensembling), not as label files through `evaluation.py`. They grade the same 500 PMIDs by the same accuracy, so the examiner matches, but a single-prompt run under our template is a different Candidate protocol. The human baseline (0.78, `benchmarks.py:1973`) is `get_human_performance.py` over the annotators' `reasoning_required_pred` (`fork:get_human_performance.py:10-33`): the same metric.
- **Macro-F1.** The paper names accuracy and macro-F1 as the two main metrics (§3.3) and `evaluation.py:19` prints both; inspect_evals and ours serve accuracy only (D1, bound 0). The leaderboard ranks by accuracy.
