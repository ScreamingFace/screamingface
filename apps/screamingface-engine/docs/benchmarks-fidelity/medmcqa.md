# MedMCQA — Fidelity Record

## Verdict

**`not-comparable`.** Our Cases are the paper's dev split exactly. The [Hub file](https://huggingface.co/datasets/openlifescienceai/medmcqa/tree/91c6572c454088bf71b679ad90aa8dffcd0d5868) at the pin matches the authors' own `dev.json` (their Google Drive `data.zip`, linked from `fork:README.md:89`) on all 4,183 rows: same ids, same order, equal text on all nine text fields, and the key equals `cop - 1` on every row. Per-Case marks equal the harness's mark rule on 33,464 of 33,464 index-level answer sheets, and the whole-run accuracy equals the harness's `correct/n` to four decimals on eight vectors. Even so, the number the paper publishes ([Table 4](https://arxiv.org/abs/2203.14371v1): PubMedBERT 0.40 on dev without context, 0.43 with PubMed retrieval) came from a different process by design. The harness fine-tunes encoders on `question + ' ' + option` pairs and takes the argmax of four logits, so it has no prompt and no reply reader. Our two dimensions that replace them are declared deviations with nothing to bound against: `bounds against the original harness = D1 (prompt) unbounded + D2 (answer extraction) unbounded → not-comparable`, by the rule's "any score-changing deviation with bound unbounded" and "a published number produced by a different process by design". The row's own description says our score is "comparable with papers that report on the validation (dev) split" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6568-6569`). This record does not support that sentence for the paper. The LLM dev numbers the row cites (Frontier Score 0.839, [Nori et al. 2024](https://arxiv.org/abs/2411.03590)) used that paper's own prompt and reader, which this audit did not compare (Upstream notes). Nothing undeclared was found.

## Deviations

### D1 — a prompted Candidate under inspect's multiple-choice template; the harness has no prompt

- **Declared.** The package README's "Asking and scoring" paragraph (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/medmcqa/README.md:19-23`) and the module's WHY note (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/medmcqa/medmcqa.py:30-33`, "inspect's standard template, no chain of thought … owner decision, OME-1696"). The README presents this as our design and does not call it a deviation from the harness. Being written there is what makes it declared.
- **Where.** Ours: `medmcqa.py:110` (`solver=multiple_choice()`), template `inspect_ai:solver/_multiple_choice.py:17-23`. Theirs: `fork:model.py:139,147`, which builds four `question + ' ' + option` strings truncated to 192 tokens for a fine-tuned BERT-family encoder (`fork:run.sh:1-5`: PubMedBERT, SciBERT, BERT-base).
- **What differs.** Our Candidate reads the instruction, the question and the lettered options as one message. The paper's models were trained on 182,822 questions and never read an instruction.
- **Severity / bound.** `score-changing`, `unbounded`: the harness has no prompt to compare bytes against, so no set of affected Cases can be listed.
- **Evidence.** Our 4,183 inputs equal the template over the authors' rows byte for byte (Checks run 6). A `grep` of the harness finds no prompt, template or instruction string (Checks run 2).

### D2 — the reply is read by inspect's `ANSWER:` parser; the harness takes an argmax

- **Declared.** `README.md:21-22`; the row's `scorer="inspect_ai.scorer:choice"` (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6583`).
- **Where.** Ours: `inspect_ai:solver/_multiple_choice.py:98,107,113,115`. Theirs: `fork:model.py:85`, `fork:train.py:103`.
- **What differs.** A reply that names the right option without an `ANSWER:` line scores 0 with us (bare `C`, `(C)`, `The answer is C.`, the option's text: 0/4183 each, Checks run 4). The harness's model always yields exactly one option, so it can never "fail to answer".
- **Severity / bound.** `score-changing`, `unbounded`: how often it bites depends on how the Candidate formats its reply, which no free check can list.
