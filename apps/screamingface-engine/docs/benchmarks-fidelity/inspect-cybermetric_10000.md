# CyberMetric-10000 — Fidelity Record

## Verdict

**`unverified`.** Our headline is plain accuracy over the 10,180 CyberMetric-10000 questions the pinned file holds (the name says 10,000; the eval's `eval.yaml` says 10,000; the file has 10,180). It is built to sit beside a run of [inspect_evals v0.20.0 `cybermetric_10000`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/cybermetric), which uses a system message, the default `multiple_choice()` template, the `choice()` scorer and the `accuracy` metric. inspect_evals publishes no number for this eval. Our headline is **not** comparable to the paper's Table III (GPT-4o 88.89% on 10k Q; [Tihanyi et al. 2024, v2](https://arxiv.org/abs/2402.07688v2)), which is also the row's Frontier Score. inspect_evals marks a different exam from the authors' harness ([cybermetric/CyberMetric@7c565c65](https://github.com/cybermetric/CyberMetric/tree/7c565c65c03ac5bb06b1f94da410cd3f9b91dafe)): it pins the December 2024 data file, while the paper's June 2024 numbers came from the February 2024 file, and 123 of the 10,180 pinned Cases differ from it (`123/10180 = 0.0121`, plus 92 paper-time questions the pin dropped); it asks with a different prompt; and it extracts the answer differently (the harness takes the first case-insensitive `ANSWER:?\s*[A-D]` anywhere and re-asks up to five times). Together these are `unbounded` (Upstream notes). Against inspect_evals: (1) every Case is served with inspect's exact text, key and options; (2) our 173,060 sheet marks equal inspect's own solver chain and scorer on every sheet; (3) the roll-up equals inspect's to four decimals on ten vectors. One deviation remains, undeclared: D1, the system message delivered as leading user text, `possibly-score-changing`, bound `unknown`. Arithmetic: `bounds against inspect_evals = unknown (D1)`; a `possibly-score-changing` deviation is open, so the rule gives `unverified`. Once D1 is bounded at ≤ 0.005, the rule gives `comparable-to-inspect`, because inspect_evals vs the original harness is `unbounded` (with a lower bound of 123/10180 = 0.0121 from the data alone, above tolerance).

## Deviations

### D1 — the eval's system message rides inside the user prompt

- **Undeclared on the row.** The row carries no `# NAMED DEVIATION` line (`awk` over `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:3043-3102` and `grep -n -i deviation` over `prepare.py:413-428` found none, Checks run 7). It has no `named_deviations/` scorer (`ls named_deviations/ | grep -i cyber` empty), no `dropped_scorers`, `excluded_sample_ids=None` (Checks run 2), and no linked README. `grep -n cybermetric docs/spec/2026-10-02-ome-1460-one-fetch-path.md` → no line. Two things come close: the row's description says the questions are "asked with the eval's own system message" (`benchmarks.py:3048-3049`) without saying it arrives as user text; and the plugin-wide comment at `capture.py:76-77` calls the fold a "Named deviation (contracteval pattern)", which the glossary lists as an example (`CONTEXT.md:323-326`). Neither is a declaration form the rule accepts, so this is a finding; a row-level line would make it declared and it would still be counted the same way.
- **Where.** Ours: `SYSTEM_MESSAGE + "\n\n" + user prompt` as one user text (`apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:79`, `:530-538`); the grader gets that single user message (`scorer_adapter.py:635`). Theirs: `system_message(SYSTEM_MESSAGE)` inserts a `ChatMessageSystem` before the user turn (`inspect_evals:cybermetric/cybermetric.py:35`, `:77`; `inspect_ai:solver/_prompt.py:46`, `:67-71`). The original harness also sends `{"role": "system"}` then user (`fork:CyberMetric_evaluator.py:31-34`).
- **What differs.** Every byte of text is equal on all 10,180 Cases (Checks run 4). The Candidate receives "You are a security expert who answers questions." as the opening of the user turn, not as a system turn. The scorer never reads it: `choice()` reads only the reply and the choices.
- **Severity / bound.** `possibly-score-changing`, `unknown`. A Candidate may follow a system instruction differently from user text. Needs a paired Candidate run (Recommended paid runs).

## Recommended paid runs

- **D1, system turn vs folded text (bounds the open deviation).** One Candidate, no judge (the scorer is deterministic).
  - **Arm A:** inspect's own `eval()` of `cybermetric_10000()` (system message as a system turn).
  - **Arm B:** our served Case input as one user message.
  - **Noise floor:** run each arm twice, or fix `temperature=0` where the Candidate allows it; the paper reports 3–4 pp run-to-run variation at temperature 1.0.
  - **Readout:** per-Case marks and the headline difference. If |A − B| ≤ 0.005 beyond the noise floor (at most 50 net Cases of 10,180), D1's bound is that difference and the rule gives `comparable-to-inspect`.
  - **Cost:** Candidate tokens only, about 150 input tokens and a few output tokens per Case per sitting, so roughly 4 × 10,180 short calls. A cheaper first look: run the paired arms on cybermetric_500 (whose record has the same open D1) and only extend to the 10k set if that bound is near tolerance; the 10k bound still needs its own run.

## Upstream notes

- **inspect_evals vs the original harness: a different examiner, `unbounded`.** [inspect_evals v0.20.0 `cybermetric`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/cybermetric) keeps the harness's system message and its `Question: …\nOptions: A) …, B) …` rendering (`inspect_evals:cybermetric/cybermetric.py:35`, `:115-116`; `fork:CyberMetric_evaluator.py:25-26`, `:32`). It changes the rest of the exam [cybermetric/CyberMetric@7c565c65](https://github.com/cybermetric/CyberMetric/tree/7c565c65c03ac5bb06b1f94da410cd3f9b91dafe) gave.
  1. **Data, 123/10180 = 0.0121.** inspect_evals pins `205262cd` (2024-12-18, `cybermetric.py:32`), after the December 2024 dataset fixes. The paper's v2 (3 Jun 2024) numbers came from the file at `7c565c65` (2024-02-25, unchanged until December). Matching by exact question text: 61 pin questions are new, 48 have changed options and 14 a changed key, so 123 pinned Cases differ from the paper's; 92 paper-time questions are gone (10,211 → 10,180 rows). Keys moved from A 2448 / B 2572 / C 2604 / D 2587 to A 2435 / B 2567 / C 2599 / D 2579.
  2. **Prompt.** The harness's user turn ends `Choose the correct answer (A, B, C, or D) only. Always return in this format: 'ANSWER: X' ` (`fork:CyberMetric_evaluator.py:26`). inspect wraps the same question in `SINGLE_ANSWER_TEMPLATE` (`inspect_ai:solver/_multiple_choice.py:17-23`), and because `record_to_sample` sets `choices` to the option *letters* (`cybermetric.py:119`), appends a second option list reading `A) A`, `B) B`, `C) C`, `D) D` (`inspect_ai:solver/_multiple_choice.py:57-68`). The real option texts appear only in the comma-joined `Options:` line (Case 1, Checks run 4).
  3. **Answer extraction.** The harness takes the **first** case-insensitive `ANSWER:?\s*([A-D])` anywhere (`fork:CyberMetric_evaluator.py:19`): the colon is optional and it reads the first letter of a following word ("answer depends" → D). inspect takes the **last** `ANSWER\s*:` line and requires the colon and a lone allowed letter (`inspect_ai:solver/_multiple_choice.py:98-121`, `:147`). On the sheets they disagree on 10,180/10,180 Cases for four reply shapes and on 7,601/10,180 for a fifth (Checks run 4).
  4. **Retries.** The harness re-asks up to five times when no letter parses (`fork:CyberMetric_evaluator.py:24`, `:27-45`); inspect asks once and marks an unparseable reply wrong.

  Items 2–4 depend on how a Candidate writes, so they cannot be bounded without a run; item 1 alone exceeds tolerance. Hence at best `comparable-to-inspect`, never `comparable-to-paper`.
- **Harness vs paper: sampling settings.** The paper states "temperature of 1.0, top_p at 0.9, and top_k at 50" (§IV-A) for its AWS-hosted models; the published evaluator hard-codes `model="gpt-3.5-turbo-0125"` with no sampling arguments (`fork:CyberMetric_evaluator.py:29-35`). The harness wins; recorded, not counted.
- **Harness vs paper: size and validation.** The paper calls the set "10,000 questions" and says only the 80 and 500 sets are "fully validated by human experts"; the paper-time file holds 10,211 rows and the pinned one 10,180. inspect_evals' `eval.yaml:16-17` still says `dataset_samples: 10000`; our row records the real count (`benchmarks.py:3101`) and leaves `inspect_evals_case_count` unset. No mark changes.
- **The data file moved again after inspect's pin.** `f58b09d` (2026-05-27) changed 11 of the 10,180 rows relative to `205262cd` (positions 12, 25, 67, 105, 2433, 2839, 3644, 3678, 5360, 5369, 9425; 4 with a new key).
