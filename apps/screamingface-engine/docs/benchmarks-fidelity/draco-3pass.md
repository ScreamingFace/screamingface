# DRACO 3-Pass — Fidelity Record

## Verdict

**`not-comparable`.** The published number this row cites is the paper's headline: Perplexity Deep Research (Opus 4.6) at 70.5 ± 0.3 normalized score ([Zhong et al., 2026, Table 8 p.10](https://arxiv.org/abs/2602.11685v1)). It was produced as "averaged across 100 tasks, each evaluated over 5 independent LLM-as-a-judge grading runs", with Gemini-3-Pro as judge (§5.1 p.9; Table 16 p.16: reasoning low, temperature 0.2). Our row grades with `openrouter/google/gemini-3.1-pro-preview` and three passes (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4656,4661`). Spec §2.3 makes a judge model other than the paper's `not-comparable` by rule (**D1**). The pass count differs by design too (**D5**): the row's description says its scores "are not compared against five-pass results" (`benchmarks.py:4641`). The paper's Appendix A (Table 15 p.16) shows how far a judge swap moves this exam: the same Perplexity reports score 70.5 under Gemini-3-Pro, 50.4 under GPT-5.2 and 75.5 under Sonnet-4.5. Everything checkable without a model matches the authors' grading library [`The-LLM-Data-Company/rubric@eb0755a`](https://github.com/The-LLM-Data-Company/rubric/tree/eb0755a1c4682cd20c490550bd6260ccea8bafe0), the protocol the paper cites in footnote 1 (p.8) and whose system prompt is the one the paper prints in Appendix C.5:

- the Candidate's question bytes and the private rubrics, on 100/100 Cases;
- the judge instruction text, once our U+2028 line separators are mapped back to newlines;
- the per-pass normalized score and pass rate, on 1,400/1,400 verdict sheets to four decimals;
- the whole-run mean, on 6/6 mark vectors.

The bounded deviations sum to `0.0001 (D6, rounding) ≤ COMPARABLE_TOLERANCE (0.005)`. That sum does not decide the verdict. D1 decides it by rule. Separately, D2, D3, D4, D5, D7 and D8 are `possibly-score-changing` with bound `unknown`, and two of them (D2, D3) are undeclared. If D1 were removed, the verdict would still read `unverified`.

## Deviations

### D1 — the judge is Gemini-3.1-Pro Preview, not the paper's Gemini-3-Pro

- **Declared.** Row comment `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4659-4661`, README `apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/draco/README.md:56`, `draco.py:73`.
- **Where.** Ours: `benchmarks.py:4661` (`model="openrouter/google/gemini-3.1-pro-preview"`). Theirs: paper §5.1 p.9 ("we selected Gemini-3-Pro as our primary judge model"); the library's default generate function calls `model="gemini-3-pro-preview"` (`fork:src/rubric/utils.py:24`).
- **What differs.** A different examiner. The row says Google shut down Gemini-3-Pro Preview on 2026-03-09, so the paper's judge can no longer be called.
- **Severity / bound.** `score-changing` by design, `unbounded`. This is `not-comparable` by rule (spec §2.3). Paper Table 15 (p.16) sizes the effect of a judge swap on the same reports: 70.5 / 50.4 / 75.5 for Gemini-3-Pro / GPT-5.2 / Sonnet-4.5.

### D2 — the judge's user message uses U+2028 where the library uses newlines

- **Undeclared** under the rule. The quirk is documented only in `local_tasks/draco/prompts.py:10-13` (module docstring) and pinned by `test_each_judge_call_is_the_hand_built_one`. The README the row's package carries says the judge gets "the paper's Appendix C.5 instructions" (`README.md:31`), and `prompts.py:16` says "byte-for-byte aligned with the reference DRACO harness".
- **Where.** Ours: `prompts.py:127-145` joins the twelve pieces (`<criterion_type>`, type, `</criterion_type>`, `<criterion>`, …, `</response>`) with `"\u2028"` (`:130`). `judge_system_text` folds every newline of the instructions to U+2028 (`:155-156`). Theirs: `fork:src/rubric/autograders/per_criterion_grader.py:148-161` uses `\n` inside each block, a blank line between blocks, and `<query>{query}</query>` on one line. This is the template the paper prints in Appendix C.5 (pp.37-38).
- **What differs.** Separators only. The fields are identical: the library's template filled with our criterion type, requirement, question and answer reproduces the library's prompt on 7,868/7,868 renders. The instruction text is identical once U+2028 is mapped back to `\n`. Example start, ours `'<criterion_type>\u2028positive\u2028</criterion_type>\u2028<criterion>\u2028States TWFE…'`, theirs `'<criterion_type>\npositive\n</criterion_type>\n\n<criterion>\nStates TWFE…'` (Checks run 9).
- **Severity / bound.** `possibly-score-changing`, `unknown`: whether the judge reads a U+2028-separated prompt as it reads newlines needs a paid run.

### D3 — no response schema, and the verdict is read leniently

- **Undeclared.** The README says the reply "must be JSON with a `criterion_status` of exactly `MET` or `UNMET`" (`README.md:38`). It does not say that the authors' library expects schema-constrained output or that we accept wrapped JSON.
- **Where.** Ours: the judge call sends only the four pinned params plus the seed (`benchmarks.py:4669-4675`; `test_each_judge_call_is_the_hand_built_one`). `parse_verdict` recovers the JSON object from fenced or prose-wrapped replies (`draco.py:181-196`). Theirs: `response_mime_type="application/json", response_schema=PerCriterionOutput` (`fork:src/rubric/utils.py:30`). The README tells production users to use structured outputs and to validate with `PerCriterionOutput.model_validate_json` (`fork:README.md:61,281,300`).
- **What differs.** On the 11,802 recorded judge replies, 25 (0.21%) are fenced JSON. We take their verdict. The library's strict validation rejects them and leaves the retry to the caller. The DRACO run's own `generate_fn` is not published.
- **Severity / bound.** `possibly-score-changing`, `unknown`: constrained decoding may change the judge's verdicts, not just their wrapping.

### D4 — a line with no verdict drops out of its pass, after two redraws

- **Declared.** `local_tasks/draco/README.md:38-40,60` ("Two deliberate differences from the hand-built grader").
- **Where.** Ours: `draco.py:335-337` marks the pass `valid: False` after `MAX_JUDGE_REDRAWS`. `_restrict` removes the line from that pass's numerator and denominator (`scoring.py:114,186`). An empty final pass drops out (`draco.py:274`). A Case with no verdict at all fails as `judge_reply_invalid` (`draco.py:277`). Theirs: no drop-out. `generate_fn` must return a valid `PerCriterionOutput`, or Pydantic raises and the Case has no score (`fork:README.md:278,281`; `fork:src/rubric/autograders/base.py:67-68`).
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts only when the judge fails to give a verdict three times. On the recorded run, our parser accepted 11,802/11,802 judge replies (3,934 criteria × 3 passes), so nothing dropped (Checks run 10).

### D5 — three judge passes, not the paper's five

- **Declared.** The row description (`benchmarks.py:4636-4641`, "only the judge-pass count differs … not compared against five-pass results"), `"judge_passes": 3` (`:4656`), `draco.py:75-77,358-364`.
- **What differs.** The Case score is the mean over 3 seeded passes (`scoring.py:169`) instead of 5 (paper Table 8 caption p.10). The per-pass formula matches (metric row).
- **Severity / bound.** `possibly-score-changing`, `unknown`. Paper Table 8 reports a run-to-run SD of 0.2-0.4 points across grading runs, which suggests the effect of the pass count on the mean is small, but it is not bounded without a run.

### D6 — Case score rounded to four places before the run mean

- **Declared.** README `:42-44` ("to 4 places").
- **Where.** `scoring.py:169` rounds the Case score, and `single_shot.py:1303` rounds the headline. The library and the paper keep full precision.
- **Severity / bound.** `score-changing`, bound `0.0001` of the headline: each Case moves by at most 0.00005 (the measured maximum is `0.000050`, Checks run 11), and the headline rounding adds at most 0.00005. Arithmetic: `0.00005 + 0.00005 = 0.0001 ≤ 0.005`.

### D7 — a failed Case is left out of the run mean

- **Declared.** README `:43-44`, `failure_policy="coverage_declare"` (`benchmarks.py:4648`).
- **What differs.** Ours averages over graded Cases and publishes coverage. The paper averages "across 100 tasks" and states no rule for a task without a score. Equal on full coverage (6/6 vectors, Checks run 12). Example: 5 failed Cases give `0.4028` here, against `0.3827` if they counted 0.
- **Severity / bound.** `possibly-score-changing`, `unknown` before a run: 0 when a run grades 100/100, as the recorded golden does (`"gradeable_count": 100`).

### D8 — the Candidate's retrieval policy

- **Declared.** README `:22-26`, `retrieval_policy` (`benchmarks.py:4683`).
- **What differs.** Search is on, with 7 hosts banned (arxiv.org, huggingface.co, openrouter.ai, paperswithcode.com, alphaxiv.org, semanticscholar.org, research.perplexity.ai). The paper ran production deep-research systems with their own retrieval, and the bare Claude rows with Anthropic's `web_search` and `code_execution` tools (§5.1 p.9). Our Candidates get no code-execution tool. The paper v1 text describes no blocklist, so the README's "the paper's page-shaped blocklist" (`:26`) has no source in the paper. It may come from the non-public repo the row's `license_note` mentions.
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts on the Candidate's answer, not on the marking, and only a run can show its size.
