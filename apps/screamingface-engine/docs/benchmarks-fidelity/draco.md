# DRACO — Fidelity Record

## Verdict

**`not-comparable`.** The published number this row cites is the paper's headline: Perplexity Deep Research (Opus 4.6) at 70.5 ± 0.3 normalized score ([Zhong et al., 2026, Table 8 p.10](https://arxiv.org/abs/2602.11685v1)). The paper produced it as "averaged across 100 tasks, each evaluated over 5 independent LLM-as-a-judge grading runs", with Gemini-3-Pro as the judge (§5.1 p.9; Table 16 p.16: reasoning low, temperature 0.2). This row grades with `openrouter/google/gemini-3.1-pro-preview` (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4562`). Spec §2.3 makes a judge model other than the paper's `not-comparable` by rule (**D1**). The row's description says so too: "its scores are not paper-identical" (`benchmarks.py:4540-4542`). The paper's Appendix A (Table 15 p.16) shows how far a judge swap moves this exam: the same Perplexity reports score 70.5 under Gemini-3-Pro, 50.4 under GPT-5.2 and 75.5 under Sonnet-4.5. Unlike the sibling `draco-3pass`, this row keeps the paper's five passes: `"judge_passes": 5` (`benchmarks.py:4557`), and the row's own scorer sent seeds 1-5, 3,934 calls each, on one sheet (Checks run 7). Everything checkable without a model matches the authors' grading library [`The-LLM-Data-Company/rubric@eb0755a`](https://github.com/The-LLM-Data-Company/rubric/tree/eb0755a1c4682cd20c490550bd6260ccea8bafe0), the protocol the paper cites in footnote 1 (p.8), wrapped in the paper's five-pass mean:

- the Candidate's question bytes and the private rubrics, on 100/100 Cases;
- the judge instruction text, once our U+2028 line separators are mapped back to newlines;
- the five-pass normalized score and pass rate, on 1,200/1,200 verdict sheets to four decimals;
- the whole-run mean, on 6/6 mark vectors.

The bounded deviations sum to `0.0001 (D6, rounding) ≤ COMPARABLE_TOLERANCE (0.005)`. That sum does not decide the verdict: D1 decides it by rule. D2, D3, D4, D5, D7, D8 and D9 are `possibly-score-changing` with bound `unknown`, and four of them (D2, D3, D5, D9) are undeclared. Even without D1, the verdict would read `unverified`.

## Deviations

### D1 — the judge is Gemini-3.1-Pro Preview, not the paper's Gemini-3-Pro

- **Declared.** Row comment `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4560-4562`, README `apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/draco/README.md:56`, `draco.py:73`.
- **Where.** Ours: `benchmarks.py:4562`. Theirs: paper §5.1 p.9 ("we selected Gemini-3-Pro as our primary judge", PDF text line 370); the library's quick-test generate function calls `model="gemini-3-pro-preview"` (`fork:src/rubric/utils.py:24`).
- **What differs.** A different examiner. The row says Google shut down Gemini-3-Pro Preview on 2026-03-09, so the paper's judge can no longer be called.
- **Severity / bound.** `score-changing` by design, `unbounded`. `not-comparable` by rule (spec §2.3). Paper Table 15 (p.16) sizes a judge swap on the same reports: 70.5 / 50.4 / 75.5 for Gemini-3-Pro / GPT-5.2 / Sonnet-4.5.

### D2 — the judge's user message uses U+2028 where the library uses newlines

- **Undeclared** under the rule. The quirk is documented only in the `prompts.py` module docstring (`local_tasks/draco/prompts.py:10-13`) and pinned by `test_each_judge_call_is_the_hand_built_one` (`apps/screamingface-engine/tests/unit/inspect/test_local_task_draco.py:441`). The README says the judge gets "the paper's Appendix C.5 instructions" (`README.md:31`), and `prompts.py:16` says "byte-for-byte aligned with the reference DRACO harness".
- **Where.** Ours: `prompts.py:127,130` joins the twelve pieces with `"\u2028"`; `judge_system_text` folds every newline of the instructions to U+2028 (`:156`). Theirs: `fork:src/rubric/autograders/per_criterion_grader.py:148-161` uses `\n` inside each block, a blank line between blocks, and `<query>{query}</query>` on one line.
- **What differs.** Separators only. The library's template filled with our criterion type, requirement, question and answer reproduces the library's prompt on 7,868/7,868 renders (3,934 criteria × 2 answers: a multi-line answer with a tab, and the empty answer). Example start, ours `'<criterion_type>\u2028positive\u2028</criterion_type>\u2028<criterion>\u2028States TWFE co'`, theirs `'<criterion_type>\npositive\n</criterion_type>\n\n<criterion>\nStates TWFE c'` (Checks run 8). No Case question itself holds U+2028.
- **Severity / bound.** `possibly-score-changing`, `unknown`: whether the judge reads U+2028 as it reads newlines needs a paid run.

### D3 — no response schema, and the verdict is read leniently

- **Undeclared.** The README says the reply "must be JSON with a `criterion_status` of exactly `MET` or `UNMET`" (`README.md:38`). It does not say that the library expects schema-constrained output, or that we accept wrapped JSON.
- **Where.** Ours: the judge call carries the four pinned params plus `seed=k` (`benchmarks.py:4569-4572`; `judge_redraw.py:180,229`). `parse_verdict` recovers the JSON object from fenced or prose-wrapped replies (`draco.py:181,189`). Theirs: `response_mime_type="application/json", response_schema=PerCriterionOutput` (`fork:src/rubric/utils.py:29-30`). The README tells production users to use structured outputs and return a validated model (`fork:README.md:61,277,279,281`).
- **What differs.** On the 11,802 recorded judge replies, 25 (0.21%) are fenced JSON. We take their verdict. The library's strict validation rejects them and leaves the retry to the caller. Both sides accept an extra key, a reordered object and an empty explanation, and both reject lower-case `met`, padded `" MET "`, a missing or non-string explanation, `PARTIAL`, a JSON list, bare `MET`, empty and plain text (Checks run 6). The DRACO run's own `generate_fn` is not published.
- **Severity / bound.** `possibly-score-changing`, `unknown`: constrained decoding may change the judge's verdicts, not just their wrapping. Of the recorded replies, 11,667 are backfilled verdicts from an earlier run and 135 are live (Checks run 6).

### D4 — a line with no verdict drops out of its pass, after two redraws

- **Declared.** `local_tasks/draco/README.md:38-40,60`.
- **Where.** Ours: `draco.py:336-337` marks the pass `valid: False` after `MAX_JUDGE_REDRAWS` (= 2, `judge_redraw.py:38`). `_restrict` removes the line from that pass's numerator and denominator (`scoring.py:114,186`). A Case with no verdict at all fails (`draco.py:277`). Theirs: no drop-out. `generate_fn` must return a valid `PerCriterionOutput`, or Pydantic raises (`fork:README.md:281`).
- **What differs.** On a sheet with ~10% of verdicts scattered invalid, the row's scorer scored 100/100 Cases ("mean over 5 judge passes") and the library raised `ValidationError` on 100/100 (Checks run 8).
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts only when the judge fails three times on a line. Our parser read 11,802/11,802 recorded replies, so on the recorded passes nothing would drop (Checks run 6). Passes 4 and 5 have no recorded replies.

### D5 — a pass with no verdict at all scores 0 unless it is the last

- **Undeclared.** The behaviour lives in a code comment (`draco.py:272-274`) and a test whose docstring calls it "an open owner call" (`test_an_empty_middle_pass_scores_zero_but_an_empty_last_pass_drops_out`, `tests/unit/inspect/test_local_task_draco.py:356`). The README says only that a line with no verdict "is left out of that pass" (`README.md:40`).
- **Where.** Ours: trailing empty passes are popped (`draco.py:274`); an empty pass between valid ones stays, and `normalized_score` returns `0.0` for an empty restricted rubric (`scoring.py:44`). Theirs: the library raises; the paper averages 5 passes and states no rule.
- **What differs.** On a sheet where passes 3 and 5 got no verdict at all, the row's scorer returns "mean over 4 judge passes", with pass 3 counted as 0. Case 1: `value 0.3703`, `verdicts_accepted 159` of `265`. Leaving pass 3 out as well would give ≈ `0.4937` (= 0.3703 × 4 / 3). The library raised on 100/100 (Checks run 8). With five passes there are three middle positions where this can act, against one in draco-3pass.
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts only when the judge fails every line of a pass three times.

### D6 — Case score rounded to four places before the run mean

- **Declared.** README `:42` ("to 4 places").
- **Where.** `scoring.py:169` rounds the Case score; `single_shot.py:1303` rounds the headline. The library and the paper keep full precision.
- **Severity / bound.** `score-changing`, bound `0.0001` of the headline: each Case moves by at most 0.00005 (measured maximum `0.000050` over 1,200 sheets, Checks run 8), and the headline rounding adds at most 0.00005. `0.00005 + 0.00005 = 0.0001 ≤ 0.005`.

### D7 — a failed Case is left out of the run mean

- **Declared.** README `:43-44`, `failure_policy="coverage_declare"` (`benchmarks.py:4549`).
- **What differs.** Ours averages over graded Cases and publishes coverage. The paper averages "across 100 tasks" and states no rule for a task without a score. Equal on full coverage (6/6 vectors). Example: 5 failed Cases give `0.3906` here, against `0.3711` if they counted 0 (Checks run 9).
- **Severity / bound.** `possibly-score-changing`, `unknown` before a run; 0 when a run grades 100/100.

### D8 — the Candidate's retrieval policy

- **Declared.** README `:22-26`, `retrieval_policy` (`benchmarks.py:4584`); the row description names "mixed native/Tavily retrieval, and a host-only approximation of the reference blocklist" (`benchmarks.py:4540`).
- **What differs.** Search is on, with 7 hosts banned (alphaxiv.org, arxiv.org, huggingface.co, openrouter.ai, paperswithcode.com, research.perplexity.ai, semanticscholar.org). The paper ran production deep-research systems with their own retrieval, and the bare Claude rows with Anthropic's web search and code execution tools (§5.1 p.9). Our Candidates get no code-execution tool. The paper v1 describes no blocklist, so the README's "the paper's page-shaped blocklist" (`:26`) has no source in the paper.
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts on the Candidate's answer, not on the marking.

### D9 — an abstained Candidate's Case is held at 0, whatever the judge said

- **Undeclared** on the row and in the README. It is an Engine-wide rule (OME-1289), at `apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1514,1529`, pinned for this package by `test_an_abstained_case_costs_one_case_at_zero_whatever_the_judge_said` (`tests/unit/inspect/test_local_task_draco.py:402`).
- **What differs.** When a Fusion abstains, the judge still grades its empty answer, and the Case is then set to `0.0` (in the test, a judged 0.3333 becomes 0.0, and an unjudged abstain is kept at 0.0 where an answered Case would fail). The library would mark the empty answer as the judge said, and the paper had no abstaining systems. Ours ≤ the library on every such Case.
- **Severity / bound.** `possibly-score-changing`, `unknown`: it acts only on abstained Cases, which only Fusion recipes produce.
