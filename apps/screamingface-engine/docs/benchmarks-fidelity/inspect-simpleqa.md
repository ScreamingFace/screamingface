## Deviations

### D1 — a Case that cannot be graded leaves the denominator

- **Not a Named Deviation.** It follows the row's `failure_policy="coverage_declare"` (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5177`), and the Report states coverage beside the headline (`apps/screamingface-engine/src/screamingface_engine/benchmarks/definition.py:39,153`). None of the declared forms in the rules covers it. The withhold guard keeps every whole-run-metric row on `coverage_declare` (`single_shot.py:520`).
- **Where.** Ours: `policy_cases` hands the tally only the graded Cases (`apps/screamingface-engine/src/screamingface_engine/benchmarks/aggregation.py:94,106`). This covers a Candidate call that errors and a judge that gives no verdict (D2). Theirs: the harness sampler retries any exception with exponential backoff and never gives up (`fork:sampler/chat_completion_sampler.py:72-79`), so every row is graded. Under inspect_evals a sample error fails the eval, unless the runner tolerates errors.
- **Severity / bound.** `score-changing`. The bound is `k/4326` for a run with k failed Cases, which that run's Report lists; it is 0 at full coverage. Each dropped Case would have scored correct = 0 on the other side, so the headline can only rise: by `c·k/(4326·(4326−k))` for a correct share of `c/4326`.

### D2 — a blank judge reply fails the Case, where inspect_evals and the harness mark it not attempted

- **Undeclared.** A finding. The row does not mention it; the blank refusal is Engine-wide (`judge_provider.py:132`).
- **Where.** Ours: `if not completion.strip():` raises `JudgeReplyBlank` (`apps/screamingface-engine/src/screamingface_engine_inspect/judge_provider.py:308`). `simpleqa_scorer` calls the grader once with no redraw (`inspect_evals:simpleqa/scorer.py:117`), so the Case fails as `scorer_error`. The output was `JudgeReplyBlank: the gateway judge at 'openrouter/google/gemini-3.1-pro-preview' returned an empty reply`, `coverage 0.0` on 2 Cases with 2 judge calls (Checks run 10). Theirs: no match → `"C"` (`inspect_evals:simpleqa/scorer.py:124`; `fork:simpleqa_eval.py:128`). Per D1, the Case then counts in the denominator as not attempted, where ours drops it.
- **What differs.** A blank reply (`''`, `' '`, `'\n'`) adds a not-attempted Case on their side and a failed Case on ours. That changes the headline through D1, and it changes `attempted`, `correct_given_attempted` and `f_score`. One mitigating detail: the harness's own sampler raises and retries on an empty completion, so with OpenAI models the harness redraws instead of grading a blank. inspect_evals grades it `C`.
- **Severity / bound.** `possibly-score-changing`, `unknown`. How often the pinned Gemini judge sends a blank can only be counted in a paid run. Each such Case appears in that run's failures as `scorer_error`, so the per-run count can be read off the Report.

### D3 — a Fusion's abstained Case is zeroed in every column, including `not_attempted`

- **Undeclared on the row.** It is the Engine-wide abstain rule (OME-1289), documented at `apps/screamingface-engine/src/screamingface_engine_inspect/scorer_metrics.py:157-187`, but not on this row.
- **Where.** `_metric_sample` → `zero_sample_score` (`single_shot.py:1529-1530`) rewrites the kept dict to `{correct: 0, incorrect: 0, not_attempted: 0}` (`scorer_metrics.py:183`). inspect_evals' metric counts that as attempted and not incorrect (`inspect_evals:simpleqa/scorer.py:49-55`).
- **What differs.** Take 3 Cases [A, B, abstained]. If the judge said C on the abstained reply, ours gives correct 0.3333, attempted 1.0000, f_score 0.4000, and theirs gives correct 0.3333, attempted 0.6667, f_score 0.4000. If the judge said A, ours gives correct 0.3333 and f_score 0.4000, and theirs gives 0.6667 and 0.6667 (Checks run 13). An abstained Case whose grader also failed gets a bare 0.0 Score. inspect_evals' metric then raises `ValueError This score is not a dictionary` (`inspect_ai:scorer/_metric.py:209-214`), and the whole tally fails by the metric's name rather than publish a number.
- **Severity / bound.** `score-changing` for Fusion Candidates only: the headline moves by one Case per abstain that the judge marked A, and `attempted` moves by one Case per abstain that the judge marked C. Bound `0` for a single-model Candidate, which never abstains. A Fusion run's abstains are listed per Case (`abstained: true`).

### D4 — the headline is the correct share, with the paper's F-score beside it

- **Declared.** `# NAMED DEVIATION` at `benchmarks.py:5308-5313` (owner decision on OME-1602): `whole_run_headline="correct"` (`:5315`). `f_score`, `correct_given_attempted`, `attempted`, `incorrect` and `not_attempted` are published as run metrics.
- **Where.** inspect_evals' `simpleqa_metric` returns all six keys and names no headline (`inspect_evals:simpleqa/scorer.py:49-70`). The harness's returned `score` is the correct share and prints F1 beside it (`fork:simpleqa_eval.py:143,183-192`). The paper calls the F-score the single-number metric and reports both in its Table 3.
- **Severity / bound.** `cosmetic`, `0`. No mark changes; every number the paper reports is published; the headline equals the harness's `score` on all six vectors (Checks run 9).

## Upstream notes

- **inspect_evals' judge prompt is not the harness's byte for byte.** The paper's Appendix A and the harness both say "Simply reply with either CORRECT, INCORRECT, NOT ATTEMPTED." (`fork:simpleqa_eval.py:80`). inspect_evals says "Simply grade it as CORRECT, INCORRECT, or NOT_ATTEMPTED." (`inspect_evals:simpleqa/grader_templates.py:67`) and strips trailing spaces from 4 lines. The rendered prompts are 5,947 bytes against 5,954 (Checks run 3). The final instruction block is identical: "Just return the letters "A", "B", or "C"" (`grader_templates.py:195-202` vs `fork:simpleqa_eval.py:87-92`). Bound: `unknown`. It is a judge's reading of one sentence, and the harness wins. Ours equals inspect_evals.
- **inspect_evals' default parse is stricter than the harness's.** `strict` takes the first standalone `A|B|C` (`inspect_evals:simpleqa/scorer.py:123`); the harness takes the first capital A, B or C anywhere (`fork:simpleqa_eval.py:127`). They differ on 2 of 14 reply shapes: `Answer: B` is B under strict and A under the harness, and `NOT_ATTEMPTED` is C under strict and A under the harness. `grade_parse="paper"` equals the harness on 42/42 sheets (Checks run 9). Bound: `unknown`; it is 0 for a judge that obeys "with no text around it". Our row pins `strict` (`benchmarks.py:5184`). That equals inspect_evals' default, and the row does not mark it as a deviation from the harness.
- **inspect_evals' default scorer is not the paper's.** `simpleqa()` defaults to `scorer="tool"`, a tool-calling grader (`inspect_evals:simpleqa/simpleqa.py:28`). Our row passes `scorer="original"`, inspect_evals' paper-faithful option (`prepare.py:1527`; README `:94-95`), so the reference here is that path.
- **inspect_evals pins no grader.** With no `grader` role bound, the evaluated model grades itself (`inspect_evals:simpleqa/README.md:118`). Its paper-faithful `gpt-4o` at temperature 0.5 is opt-in (`paper_config/simpleqa.yaml:21-25`). A default inspect_evals run is therefore a different examiner from the paper's.
- **The harness's grader moved after the paper.** It was `gpt-4o` with no system message and `max_tokens` 1024 at `586490e` (`fork:demo.py:62`, `fork:sampler/chat_completion_sampler.py:25-27`). By `652c89d` it is `gpt-4.1-2025-04-14` with system message `"You are a helpful assistant."` and `max_tokens=2048` (`fork@652c89d:simple_evals.py:333-337`). The harness README's later results were produced by that later grader, the paper's by `gpt-4o`.
- **Candidate sampling and system message are runner choices in the harness.** For example `gpt-4o_assistant` sends `"You are a helpful assistant."`, `max_tokens=2048` and temperature 0.5 (`fork:demo.py:41-45`; `fork:sampler/chat_completion_sampler.py:25-27,56`). The eval itself sends one user turn (`fork:simpleqa_eval.py:133`). inspect_evals and our row impose none.
- **The harness's F1 is printed, not returned.** `SimpleQAEval.__call__` returns `common.aggregate_results(results)`, whose `score` is the mean of `is_correct`, with means of `is_correct`, `is_incorrect` and `is_not_attempted` (`fork:simpleqa_eval.py:194`; `fork:common.py:188,198`). `accuracy_given_attempted` and `f1` only reach stdout (`:181-192`). The paper's Table 3 reports all five numbers. Our headline (D4) is the harness's `score`, and we publish the F-score beside it.
