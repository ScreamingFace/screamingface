# LAB-Bench SeqQA — Fidelity Record

## Verdict

**`comparable-to-inspect`.** Our headline, plain accuracy over the 600 public SeqQA questions, can sit beside a run of [inspect_evals v0.20.0 `lab_bench_seqqa`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/lab_bench) (its `accuracy` metric). Against inspect_evals:

- **Cases:** every Case is the Sample inspect_evals' own loader builds with seed 7, at the same position.
- **Prompts:** all 600 Candidate inputs equal the prompt inspect_evals' own solver builds, byte for byte.
- **Marks:** all 10,200 answer-sheet marks equal inspect's solver plus `precision_choice` scorer.
- **Roll-up:** the headline equals inspect's `accuracy()` to four decimals on nine vectors.

Two deviations exist, both cosmetic. D1 is declared: the row and option order is forced by seed 7. D2 is undeclared: `precision` and `coverage` are not published. `sum of bounds against inspect_evals = 0/600 + 0/600 = 0.0000 ≤ COMPARABLE_TOLERANCE (0.005)`.

Our headline is **not** comparable to the [paper's](https://arxiv.org/abs/2407.10362v3) numbers, because inspect_evals and the authors' harness ([Future-House/LAB-Bench@998a8e0a](https://github.com/Future-House/LAB-Bench/tree/998a8e0a40cf116c80e1b0e7a805ebb5fb9fa838)) are different examiners:

- **Answer format:** the harness asks for `[ANSWER]X[/ANSWER]` with options written `(A) …`; inspect_evals asks for `ANSWER: X` with options written `A) …`. Each extractor rejects the other's format. On the same answer sheets the two disagree on every one of the 600 Cases, for 8 of the 17 reply shapes. So the inspect-vs-harness bound for answer extraction alone is `600/600 = 1.0000 > 0.005` (Upstream notes).
- **Paper rows and extraction:** the paper's tables average three runs over the public **and private** splits (Table 2 caption). Its extraction fell back to Claude 2 when the regex failed (§D.3).

## Deviations

### D1 — row and option order forced by a declared seed

- **Declared.** The row comment `apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:1234` reads "Fold: row and answer-option order forced by both seeds through inspect's shuffles (D1)". The seeds are `shuffle_seed=7` and `choice_shuffle_seed=7` (`prepare.py:1249-1250`). The mechanism is in `docs/spec/2026-10-02-ome-1460-one-fetch-path.md:281` (D1 row), and LAB-Bench is listed as "our row and choice shuffle" at `:367`. The Benchmark description says "Serving order and choice order are pinned by policy seeds" (`benchmarks.py:1668-1669`).
- **Where.** Ours: the fetch-pin enforcer forces seed 7 onto the eval's own shuffles. Theirs: `inspect_evals:lab_bench/lab_bench.py:75-76` (`shuffle=True`, `shuffle_choices=True`, no seed) → `inspect_ai:dataset/_sources/hf.py:264-265` (`dataset.shuffle(seed=seed)` with `seed=None`) and `:285` (`shuffle_choices_if_requested`).
- **What differs.** Ours is one fixed permutation of rows and of each Case's options, made by inspect's own algorithm. inspect_evals draws a fresh one every run. The question text, option set and keyed answer are identical (dataset row; Checks 6).
- **Severity / bound.** `cosmetic`, `0`. For a fixed reply, the mark does not depend on position: all 10,200 marks were identical. inspect_evals has no fixed order to compare against, so each inspect run is another draw from the same shuffle. The record_to_sample puts the ideal answer first (`record_to_sample_helpers.py:21-22`), so an unshuffled sitting would key `A` on every Case. The seed keeps the shuffle rather than dropping it.

### D2 — `precision`, `coverage` and `stderr` are not published

- **Undeclared.** No `# NAMED DEVIATION`, `dropped_scorers` or README paragraph covers it. The row's description says "Benchmark score = plain accuracy over the cases run" (`benchmarks.py:1669`), but a description is not a declaration form.
- **Where.** Ours: `_accuracy` publishes `score`, `correct`, `scored_cases` and verdict counts (`single_shot.py:1302-1309`), because `whole_run_metric` is unset. Theirs: `@scorer(metrics=[accuracy(), precision(), coverage(), stderr()])` (`inspect_evals:lab_bench/scorer.py:17`). Precision drops opt-outs from the denominator (`inspect_evals:lab_bench/metrics.py:80-88`, N → −1 at `:52-53`), and coverage is answered/total (`:111-116`).
- **What differs.** The headline is identical: `accuracy` equals our score on every vector (Checks 5). The two selective metrics, which the paper also reports (Tables 3-4, and the SeqQA heatmaps in Figure 4 are precision), are not published. Related wording issue: the row description says "opting out counts as no answer, not wrong" (`benchmarks.py:1667`). That is true only of precision. In the published accuracy an opt-out scores 0, exactly like a wrong answer (sheet `ANSWER: opt-out`: ours sum 0, inspect NOANSWER 600, accuracy 0.0000).
- **Severity / bound.** `cosmetic`, `0`. No Case's mark and no headline digit changes.
