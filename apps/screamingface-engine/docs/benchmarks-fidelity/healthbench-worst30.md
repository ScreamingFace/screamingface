# HealthBench Worst-30% Challenge — Fidelity Record

## Verdict

**`not-comparable`.** No published number exists for this Case set: the 157 Cases are our own frozen selection out of [HealthBench Professional](https://arxiv.org/abs/2604.27470v1)'s 525, and the row says so (`human_baseline` and `frontier_score` are both `NotPublished`, "the worst-30% selection is ours", `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4812-4819`). The paper still fixes how a subset is scored: "we take the mean of the per-example length-adjusted scores and clip that mean to the range [0, 1]. For subset analyses, we use the same scoring rule and aggregate only over the relevant subset" (p.9 §4.1). Our headline departs from that rule twice, and both departures are unbounded. D1 (undeclared): the per-Case score is not length-adjusted. That moves each Case by −2.94×10⁻⁵ × (answer chars − 2,000), and the adjusted score differed from ours on 157 of 157 Cases in the answer sheets. On the recorded worst-30 Fusion run, whose 124 scored answers average 2,211.0 characters, it would move the headline by −0.0062, already above the tolerance alone. D2 (declared): the headline is the plain mean with negatives kept, where the paper and [simple-evals](https://github.com/openai/simple-evals/tree/652c89d0ca9df547706735883097e9537d40dc47) clip the mean to [0, 1]. The two agree whenever a run's mean is in [0, 1] and differ by |mean| when it is negative: on the recorded run, ours is −0.091 and the clipped mean is 0.0. Everything else that can be checked for free matches simple-evals at `652c89d`. The Candidate gets the Hub conversation byte for byte on all 157 Cases. All 7,968 judge prompts match by sha256. The unadjusted per-Case score matches on all 3,768 answer sheets. The judge is a floating `openrouter/openai/gpt-5.4` sent without the paper's `reasoning_effort="low"` (D3), and the judge-reply parser differs on 7 of 20 synthetic shapes (D4). Both stay open for the paid run below, but neither can lift the verdict. `bounds vs original harness: D1 = unbounded, D2 = unbounded → not-comparable` (D5 = k/157 per run; D3 and D4 = unknown).

## Deviations

### D1 — no length adjustment on the per-Case score

- **Undeclared.** Nothing in the package, its README or the row mentions length adjustment. The row's description says only that the official score "floors negative averages at 0" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4737-4739`), which is D2.
- **Where.** Ours: the per-Case score is `case_score`, earned over winnable points (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/healthbench/scoring.py:22-76`), and nothing else (`healthbench.py:328-343`). Theirs: `calculate_length_adjusted_score` (`fork:healthbench_eval.py:157-164`) fills `overall_score_length_adjusted` whenever the adjustment is configured (`fork:healthbench_eval.py:438-445`). `--healthbench-professional-mode` refuses to run without both adjustment flags (`fork:simple_evals.py:135-142`). The paper calls it "the primary score we report" (p.8 §4.1), with 2.94×10⁻⁵ per character centred on 2,000, and applies "the same scoring rule" to subset analyses (p.9 §4.1).
- **What differs.** Each Case's mark moves by −2.94×10⁻⁵ × (len(answer) − 2,000), so the headline moves by −2.94×10⁻⁵ × (mean answer length − 2,000). It differed on 157 of 157 Cases in the answer sheets. One more fact for whoever fixes it: our grade contract refuses a Case score above 1.0 (`score: float | None = Field(le=1.0)`, `apps/screamingface-engine/src/screamingface_engine/benchmarks/contract.py:253`), and an adjusted score can exceed 1: 852 of the 3,768 harness sheets did, e.g. Case 1's empty answer with only its positive lines met scores 1.0588. Feeding the harness's adjusted sheet vectors through `_accuracy` failed on that validator (Checks run 10-11).
- **Severity / bound.** `score-changing`, `unbounded`: the size depends on the Candidate's answer lengths. The shift stays within 0.005 only while a run's mean answer length is 1,830–2,170 characters. The physicians' answers on these 157 average 1,967.9 characters (+0.0009). The recorded worst-30 Fusion run's 124 scored answers average 2,211.0 characters, median 1,897, max 23,929 (−0.0062).
- **Evidence.** Checks run 6-10, 12. No paid run is needed to measure it: the adjustment depends only on answer lengths, which every recorded run already holds.

### D2 — the headline is the plain mean, negatives kept, never clipped

- **Declared.** The row's description: "Challenge score = plain average of the 157 case scores, negatives kept (the official HealthBench score floors negative averages at 0, which would flatten this hard subset to all-zeros)" (`benchmarks.py:4737-4739`). The row comment: "the challenge metric, so no whole-run metric" (`benchmarks.py:4751-4752`). The README table (`local_tasks/healthbench/README.md:14`) and Scoring list (`README.md:50`). `scoring.py:11-14`: "It DIVERGES from the reference deliberately … Never present an unclipped score as an official HealthBench score". Pinned by `test_only_professional_takes_the_official_clip` (`tests/unit/inspect/test_local_task_healthbench.py:676`) and the −0.1875 headline in `test_the_run_headline_is_the_hand_built_one` (`tests/unit/inspect/test_local_task_healthbench.py:193`, `:321`). None of these uses a `# NAMED DEVIATION` marker, but the row states it to every reader.
- **Where.** Ours: `_accuracy` (`apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1275`, `:1303`). Theirs: `np.clip(np.mean(values), 0, 1)` (`fork:healthbench_eval.py:228`), which the paper uses for subsets too (p.9 §4.1).
- **What differs.** Identical while the run's mean is in [0, 1]. Below 0, ours reports the mean and theirs reports 0.0. On the 157 physician answers with only the penalty lines met, 109 Cases score below 0 and the mean is −0.7493. Ours also rounds to four decimals (≤ 0.00005, cosmetic).
- **Severity / bound.** `score-changing`, bound `max(0, −run mean)` per run, so `unbounded` in general. On the recorded worst-30 run (golden `final_score -0.091`), the gap is 0.091.

### D3 — judge: floating `gpt-5.4` slug, no `reasoning_effort="low"`, a 4096-token cap

- **Partly declared.** The slug is declared: "OpenRouter routes the floating slug (a named deviation, as hand-built)" (`benchmarks.py:4756-4758`) and the README (`local_tasks/healthbench/README.md:60-63`). The 4096 cap is declared as "an Engine-side safety cap the official judge does not send" (`benchmarks.py:4760-4764`). The missing `reasoning_effort="low"` is **undeclared**. The row comment names it as the official judge's setting (`benchmarks.py:4756-4757`), but the pinned params are only `web_search=false, max_tokens=4096` (`benchmarks.py:4765-4768`; Checks run 4).
- **Where.** Theirs: `ResponsesSampler(model="gpt-5.4-2026-03-05", reasoning_model=True, reasoning_effort="low")` (`fork:simple_evals.py:338-346`), which sends `reasoning={"effort": "low"}` and no `max_output_tokens` (`fork:sampler/responses_sampler.py:63-73`). The paper says "the default grader is GPT-5.4 at low reasoning" (p.9 §4.1).
- **What differs.** OpenRouter picks the gpt-5.4 snapshot, the reasoning effort is the provider's default rather than `low`, and a reply can be cut off at 4096 output tokens, reasoning included.
- **Severity / bound.** `possibly-score-changing`, `unknown` (Recommended paid runs). On its own it is also a grader configured differently from the one the paper's rule names.

### D4 — judge reply: a more lenient parser and a 2-redraw budget

- **Undeclared as a difference.** The README describes our rule (`local_tasks/healthbench/README.md:45-47`) and never says the reference differs.
- **Where.** Ours: `parse_verdict` (`healthbench.py:222-237`, `VERDICT_FORMAT` at `:93`) and `MAX_JUDGE_REDRAWS: Final[int] = 2` (`apps/screamingface-engine/src/screamingface_engine_inspect/judge_redraw.py:38`). Theirs: `parse_json_to_dict` strips only a leading ```` ```json ```` and a trailing ```` ``` ```` (`fork:healthbench_eval.py:100-108`), then retries `while True` until `label is True or label is False` (`fork:healthbench_eval.py:415-423`).
- **What differs.** 7 of 20 synthetic shapes: a bare ```` ``` ```` fence, a fence followed by text, an upper-case ```` ```JSON ```` fence, and text before the fence are verdicts for us and redraws for them; prose before the JSON is a verdict for us (False) and a redraw for them; two JSON objects in one reply, we take the first and they redraw; a bare `true`, we redraw and the harness crashes with `TypeError` (`fork:healthbench_eval.py:419`). On all 268 real judge replies of this row's recorded run the verdicts are identical. After 3 unparseable asks we fail the Case as `judge_reply_invalid`; the harness never gives up.
- **Severity / bound.** `possibly-score-changing`, `unknown`. Where they differ the harness takes a fresh draw instead of our verdict. Each run's `judge_redraws` and `judge_reply_invalid` counts show how often this happens.

### D5 — a Case that cannot be graded leaves the mean

- **Not a Named Deviation.** It follows the row's `failure_policy="coverage_declare"` (`benchmarks.py:4746`), and the Report states coverage beside the headline.
- **Where.** Ours: a Case whose Candidate call fails, or whose judge gives no verdict on a line after its redraws, is left out of the mean (pinned by `test_the_run_headline_is_the_hand_built_one`, `tests/unit/inspect/test_local_task_healthbench.py:321`, `scored_cases == 4`). Theirs: every example is graded; the sampler retries any exception forever and turns a `BadRequestError` into an empty answer that is still graded (`fork:sampler/responses_sampler.py:86-100`), and the judge loop never gives up (`fork:healthbench_eval.py:415`).
- **Severity / bound.** `score-changing`, bound `k/157` for a run with k failed Cases, which the Report lists; 0 at full coverage. The recorded worst-30 Fusion run lost 33 of 157 Cases, all `('candidate', 'upstream_error')` (Checks run 6).
- **Related, Fusion only.** An abstaining Fusion's Case is scored 0.0 even when the judge rated its empty answer (`tests/unit/inspect/test_local_task_healthbench.py:380`). The harness has no notion of abstaining.

## Upstream notes

- **No published number for this Case set, and the paper's own hard cases are a different selection.** The paper selected its 525 for difficulty with stratified sampling and tags each row `typical` or `difficult` (p.2 and p.6; 269 `difficult` in the file). Our 157 come from our own July 2026 panel ranking (`subset.py:3-6`); 130 of them carry the paper's `difficult` tag and 27 `typical`. simple-evals' `hard` subset (`INPUT_PATH_HARD`, `fork:healthbench_eval.py:37`) belongs to the original 2025 HealthBench, not to Professional, so it is not a reference for this row either.
- **The published HealthBench Professional numbers did not come from simple-evals.** The dataset card at `349962fd` says OpenAI used "an internal evaluation implementation" and calls simple-evals a "reference implementation" with "an option to use settings matching our internal implementation". `fingerprint.harness_url` is therefore the closest public code, not the code behind the paper's numbers. Bound `unknown`.
- **The harness's grader depends on a flag.** Without `--healthbench-use-gpt-5-4-low-grader`, simple-evals grades HealthBench with `gpt-4.1-2025-04-14` plus `OPENAI_SYSTEM_MESSAGE_API` and `max_tokens=2048` (`fork:simple_evals.py:333-346`). This audit compares against the Professional-mode grader the paper names; against the default grader, D3 would be larger.
- **Paper vs harness, samples per example.** The paper averages 8 samples per example for its main comparisons (p.9 §4.2); simple-evals defaults to `n_repeats=1` (`fork:simple_evals.py:394`). The harness wins, so `sampling` is a match. Averaging narrows noise but leaves the expected per-Case score unchanged. Bound 0 on the expectation.
- **Paper vs harness, length adjustment and clip: they agree.** Professional mode requires both adjustment flags (`fork:simple_evals.py:135-142`) and computes the paper's formula (`fork:healthbench_eval.py:164`), but the CLI has no default coefficient, so a user must pass 2000 and 0.0147. The harness's top-level `score`, which its summary table prints (`fork:simple_evals.py:515`), is the unadjusted clipped mean; the adjusted one sits in `metrics["overall_score_length_adjusted"]`.
- **The harness cannot read the Hub file as published.** `HealthBenchEval` expects `prompt`, `rubrics[].criterion`/`points`/`tags`, `example_tags` and `prompt_id` (`fork:healthbench_eval.py:332-335,497,516-517,550`); the Hub file has `conversation.messages` and `rubric_items[].criterion_text`/`points`. This audit used a field-rename shim (Checks run 8).
- **Harness bug on a bare JSON scalar.** A judge reply such as `true` makes `parse_json_to_dict` return a bool, and `"criteria_met" in grading_response_dict` raises `TypeError` (`fork:healthbench_eval.py:419`). None of the 268 real replies hit this.
- **Candidate system message in the harness.** simple-evals' chat-completion model entries add `OPENAI_SYSTEM_MESSAGE_API` (`fork:simple_evals.py:216`, …), which then reaches the judge's transcript through `actual_queried_message_list` (`fork:healthbench_eval.py:507`). Its reasoning-model entries add none, and the paper uses "default system message settings". Ours never adds one.
- **[inspect_evals' `healthbench`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/healthbench) (v0.20.0) is not a reference here.** The README (`local_tasks/healthbench/README.md:17-19`) says it reads the original HealthBench, not Professional, and that its judge sends temperature 0.0 and a system message.
