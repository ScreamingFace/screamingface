# FORTRESS (benign prompts) — Fidelity Record

## Verdict

**`not-comparable`.** Our Candidate reads the same 500 benign prompts as [inspect_evals' `fortress_benign`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/fortress), byte for byte. They are the same 500 rows, in the same order, as the parquet [Scale AI published](https://huggingface.co/datasets/ScaleAI/fortress_public/tree/0c096becbc75bb12065c8059a53960c7f0d4d35c) (Checks run 4). Our grading hook runs inspect's own scorer. On 19,500 answer sheets it builds the same judge prompt, and its mark is the complement of inspect's grade (`1 - grade`) on every sheet (Checks run 6). Our headline equals `1 - ORS/100` from inspect's real `eval()` to four decimals on 11 vectors (Checks run 7). The paper's overall ORS is also pooled, with unjudged prompts dropped (Checks run 3). But the examiner is not the paper's. The [paper](https://arxiv.org/abs/2506.14922v2) judges benign replies with GPT-4o-mini (§4.3), its judge prompt is not published (`inspect_evals:fortress/README.md:179`), and no harness code was released (Checks run 2). Our row grades with the house judge `openrouter/openai/gpt-5.4` (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5633-5639`, declared). Spec §2.3 makes a judge model other than the paper's `not-comparable` by rule. So the row's frontier score of 0.994 (DeepSeek R1, `1 - 0.60/100`, `benchmarks.py:5671-5674`) is the paper's number, not one ours reproduces. The bound arithmetic, for the record: `bounds vs the paper's process = D1 0 = 0`, with D2 `unknown`. The judge process differs by design, so the judge clause of the rule decides, not the sum. Against inspect_evals (the ceiling here, `comparable-to-inspect`), the sum of the bounds is `D1 0 = 0 ≤ 0.005`. But D2 is an open `possibly-score-changing` deviation, so that verdict would be `unverified`.
