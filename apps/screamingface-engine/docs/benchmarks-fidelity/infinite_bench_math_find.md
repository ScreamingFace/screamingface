# InfiniteBench Math.Find — Fidelity Record

## Verdict

**`unverified`.** The grading and the whole-run number are the authors' own. Our first-number scorer and the [InfiniteBench](https://github.com/OpenBMB/InfiniteBench/tree/220fd2e0dad86a9e5839ab2793ceea5b20f52d61) harness's `get_score_one_math_find` mark all 6,750 answer sheets the harness can mark identically. That covers all 2,450 replies the authors published for seven models. Run through our Engine's headline reduction, those published replies give exactly the [paper's Table 3](https://arxiv.org/abs/2402.13718v3) Math.Find numbers: GPT-4 0.6000, Claude 2 0.3229, Kimi-Chat 0.1257, YaRN-Mistral 0.1714. What stays open is **what the Candidate is sent**. The replies behind the published 0.60 were made by the init-commit harness. That code fills the instruction line from an `eg["prompt"]` field that no published data file holds. The paper prints that line for the "largest" question only, and it matches ours. The other 300 Cases' instruction text has no published reference, so `prompt` is `unchecked`. Separately, D1 is open: the system message reaches the Candidate as leading user text "You are a helpful assistant." (with a period), not as the harness's system turn "You are a helpful assistant" (no period). That deviation is `possibly-score-changing`. `sum of bounds against the original harness = 0/350 (D2) + 0/350 (D3) + unknown (D1)`, which is not computable, and `prompt` is `unchecked` → `unverified`. If the authors' later prompt builder (`51d9b37`) were taken as the reference, the instruction line would differ on all 350 Cases (score-changing, unbounded) → `not-comparable`. That is an owner call; see Upstream notes.

## Deviations

### D1 — the system message arrives as leading user text, with a trailing period

- **Declared at the plugin level, not on the row.** `apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:75-79` says: "Named deviation (contracteval pattern): a Benchmark cannot address a Candidate's system role, so the eval's system instruction rides ahead of the user prompt". The glossary's **Named Deviation** names "a system message delivered as input text" (`CONTEXT.md:323-326`). The row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5854-5933`) and the README (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/infinite_bench/README.md:7-9`) say only that we reuse inspect_evals' system message, not that it is folded. So it is a finding for the row's declaration, as in the HLE record.
- **Where.** Ours: `system_message_solver(create_system_msg(TASK_NAME))` (`infinite_bench.py:145`) gives `"You are a helpful assistant."` (`inspect_evals:infinite_bench/constants.py:25`). Capture then joins it ahead of the user text with `"\n\n"` (`capture.py:79,538`). Every one of the 350 Case inputs starts `You are a helpful assistant.\n\n` (Checks run 8). Theirs: a separate system turn `{"role": "system", "content": "You are a helpful assistant"}` with no period, then the user prompt (`fork:src/eval_utils.py:245`, unchanged at `fork@51d9b37:src/eval_utils.py:428`).
- **What differs.** The role (system turn vs leading user text) and one character (the period).
- **Severity / bound.** `possibly-score-changing`, `unknown`: whether a Candidate reads its system role and the same sentence in the user turn differently can only be measured with replies. See Recommended paid runs.

### D2 — one fixed input cut instead of a per-model cut

- **Declared.** NAMED DEVIATION 1 (`infinite_bench.py:30-35`), README "Why a local Task" / "What that changes" (`README.md:11-26`), and the row's provenance comment (`benchmarks.py:5880-5888`).
- **Where.** Ours: `fixed_cut` at `MAX_CHARS = int((128,000 - 500) * 3.5) = 446,250` characters (`infinite_bench.py:92,95-110`). The authors' harness: a 127,000-token middle cut in GPT-4's tokenizer (`fork:src/eval_utils.py:231`, `fork:src/eval_gpt4.py:51`). inspect_evals: a per-model cut that calls `get_model()` (`inspect_evals:infinite_bench/infinite_bench.py:39-60`, `inspect_evals:infinite_bench/truncate_input.py:157-175`).
- **What differs.** Only the rule. Our longest Case input is 120,185 characters (`over: 0` against 446,250). The harness's longest prompt is 90,033 GPT-4 tokens (`rows over 127000: 0`). So no Case is cut on either side.
- **Severity / bound.** `cosmetic`, `0`: every Case is the whole input on both sides (Checks run 9-10).

### D3 — a decimal reply to a whole-number answer is marked by value; the harness raises

- **Declared.** The `numbers_equal` docstring (`math_find_scorer.py:72-76`: "Where upstream raises ValueError, a decimal prediction against an int label, this returns the float comparison instead"). It is part of NAMED DEVIATION 2, copied from [inspect_evals PR #2346](https://github.com/UKGovernmentBEIS/inspect_evals/pull/2346) (`infinite_bench.py:37-49`). Our file equals the PR head's `math_find_scorer.py` at `0174742e` except the documented header and the one inlined constant (Checks run 16).
- **Where.** Ours: `math_find_scorer.py:82`. Theirs: `int(first_num) == label` (`fork:src/compute_scores.py:215`), which raises `ValueError` for `"88.0"`.
- **What differs.** On the 300 int-answer Cases, a reply whose first number has a decimal point: ours gives `88.0` → 1 and `88.5` → 0, while the harness raises. `get_score` (`fork:src/compute_scores.py:364-375`) has no handler, so the harness prints no headline at all for such a run.
- **Severity / bound.** `cosmetic`, `0`. No harness mark exists to differ from: the reference never produces a number when this branch is hit. 0 of the 2,450 published replies hit it (`harness raised` only on the two synthetic decimal sheets, Checks run 13).
