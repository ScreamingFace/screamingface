## Verdict

**`unverified`.** The Candidate gets exactly what [inspect_evals v0.20.0 `agie_aqua_rat`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/agieval) sends, on all 254 Cases: the same bytes in one user message, with no system message. One deviation is open, and nothing declares it (D1). inspect_evals pins `GenerateConfig(temperature=0, max_tokens=2048, top_p=1)` on the Task, which copies the paper's §4.2.4 settings. Our Benchmark applies no generation settings, because the importer never reads `task.config`. This changes what the Candidate writes, not how a reply is marked, so only a paid run can bound it:

`bounds vs inspect_evals = 0/254 (dataset, prompt, extraction, metric, roll-up) + unknown (D1, sampling, undeclared) → an open possibly-score-changing deviation → unverified`

The paper's number is out of reach in any case. The [authors' harness](https://github.com/ruixiangcui/AGIEval/tree/84ab72d94318290aad2e4ec820d535a95a1f7552) asks a completion-style `A: Among A through E, the answer is` question, sends a second "Therefore, among A through E, the answer is" turn, and takes the **first** capital A–F in the reply. inspect_evals asks for `ANSWER: $LETTER` and reads only that line. `inspect_evals vs original harness ≥ 254/254 = 1.0000 > COMPARABLE_TOLERANCE (0.005)` (Upstream notes)

## Deviations

### D1 — inspect_evals' temperature 0, 2,048-token cap and top_p 1 are not applied

- **Undeclared, so this is a finding.** The row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:2498-2557`) has no `# NAMED DEVIATION` or `Named Deviation` line (Checks run 10). Its description says nothing about generation settings (`:2502-2510`). The Task-replay declaration (`apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:277-289`) has none either. There is no `dropped_scorers` and no `excluded_sample_ids` (Checks run 2). The catalogue's convention for a dropped `task.config` is a sentence in the row's description, named as a Named Deviation (`docs/plan/2026-10-05-OME-1268-multi-score-benchmarks.md:70`, decision D10). The MATH row follows it (`benchmarks.py:4189-4191`). This row does not.
- **Where.** Theirs: `inspect_evals:agieval/utils.py:196`, on the shared `task_template`, so every agieval Task has the same config. Ours: no setting exists. Our Task-replay modules never read `task.config`: a `grep -n "\.config\b\|task\.config\|GenerateConfig"` over `importer.py`, `capture.py`, `task_replay.py`, `prepare.py`, `single_shot.py` and `task_replay_rows.py` hits only a judge-side docstring (`single_shot.py:185`). Capture's stand-in `generate` accepts the generation config and ignores it (`apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:247`) (Checks run 10).
- **What differs.** An inspect_evals run asks the model for greedy decoding with at most 2,048 output tokens. Our Candidate answers with its provider's defaults and no cap. Two failure modes follow. A sampled reply can pick a different letter. And a reply longer than 2,048 tokens would be cut off under inspect, often before its `ANSWER:` line (a 0), but runs to completion under ours. Some reasoning models reject or ignore `temperature` anyway.
- **Severity / bound.** `possibly-score-changing`, `unknown`. It changes what the Candidate writes, not how a reply is marked (the marks match on every sheet). Only a paid run can measure the gap.

## Upstream notes

- **inspect_evals vs the original harness: a different examiner, `unbounded`.** [inspect_evals v0.20.0 `agieval`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/agieval) says its prompts are "based on the original implementation" (`inspect_evals:agieval/README.md:207`), but it departs from [ruixiangcui/AGIEval@84ab72d9](https://github.com/ruixiangcui/AGIEval/tree/84ab72d94318290aad2e4ec820d535a95a1f7552) on three dimensions:
  1. **Prompt.** inspect sends one user message: the `ANSWER: $LETTER` instruction, the question, and `A) option` lines (Case 1: 569 chars). The harness's zero-shot setting sends `Q: <question> Answer Choices: (A)… (B)…` and then `A: Among A through E, the answer is` (`fork:src/dataset_loader.py:25-35`; Case 1: 437 chars). It sends that under a "You are a helpful AI assistant." system message (`fork:openai_api.py:88`). Then, in a second call, it sends the first reply back followed by "Therefore, among A through E, the answer is" (`fork:src/dataset_loader.py:250-277`, `fork:run_prediction.py:190-198`).
  2. **Answer extraction.** inspect reads only an `ANSWER:` line. The harness takes the **first** capital A–F anywhere in the final reply (`fork:src/post_process.py:72-78`, `:187-189`). On the sheets this has odd results. inspect's own format, `ANSWER: C`, is read by the harness as `A` (the A of "ANSWER"), so it is credited only on the 63 Cases keyed A: 191/254 Cases differ. The harness's natural continuation ` C.` scores 254/254 under the harness and 0/254 under inspect.
  3. **Sampling.** Both use temperature 0. The harness's chat call sets no `max_tokens` (`fork:openai_api.py:98-103`), where inspect caps at 2048.
