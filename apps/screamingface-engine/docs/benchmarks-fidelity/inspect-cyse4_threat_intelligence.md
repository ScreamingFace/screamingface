# CyberSecEval 4: threat intelligence reasoning — Fidelity Record

## Verdict

**`unverified`.** Our copy marks exactly as [inspect_evals' `cyse4_threat_intelligence` (v0.20.0)](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/cyberseceval_4) does on every check that needs no model:

- **Prompt:** the Candidate receives inspect's prompt byte for byte on 587/587 Cases, with no system message. That includes each report's full extracted text.
- **Answer key:** gold, choices and metadata equal the official `report_questions.json` on 587/587 Cases. The replay reproduced the sealed Case Digest and Case Set Digest.
- **Marks:** our production grading hook and inspect's own `multiple_choice(multiple_correct=True)` + `choice_with_jaccard()` agree on 11,153/11,153 answer sheets, for exact match and for Jaccard.
- **Roll-up:** our `_accuracy` and inspect's `exact_match_accuracy` / `jaccard_similarity_metric` agree to four decimals on 23/23 mark vectors.

Two deviations are declared and bounded:

- **D1** leaves out question 361. Its key is A to F but it has only five options, so inspect_evals marks it 0 for every reply. Bound `1/588`.
- **D2** drops inspect's per-source breakdown and stderr. The headline does not change. Bound `0`.

The arithmetic: `sum of bounds against inspect_evals = 1/588 + 0 = 0.0017 ≤ COMPARABLE_TOLERANCE (0.005)`.

D3 keeps the verdict at `unverified`. inspect_evals fixes `GenerateConfig(temperature=0)`, while we impose no generation settings. The row's description declares this, but D3 is `possibly-score-changing` and only a paid run can bound it (spec §2.3). If that run bounds D3 at or below the remaining 0.0033, the record becomes `comparable-to-inspect`.

inspect_evals and the authors' [PurpleLlama harness](https://github.com/meta-llama/PurpleLlama/tree/fe05293b610dabc3967443f2dd4dc35c4e8971b6/CybersecurityBenchmarks) differ beyond tolerance by design (`unbounded`, Upstream notes):

- a different prompt and answer format: the harness reads none of the 587 `ANSWER:` sheets;
- report text extracted by a different pypdf version, which differs on 31 of 45 reports;
- parse failures dropped from the harness's denominator;
- a paper headline (Figure 9) measured with the report given as page images.

The row's frontier score is about 0.59 for Claude 3.7 Sonnet, read off the text-input line of the paper's Figure 10. It is a harness `correct_mc_pct` over parsable answers only, so it is not comparable to our headline, which counts every unparsed reply as 0 over 587 Cases.

## Deviations

### D1 — question 361 (key names an option the question lacks) left out

- **Declared.** `excluded_sample_ids=("cyse4_threat_intelligence_6d2139d3",)` with a `# NAMED DEVIATION` line (`apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:1809-1812`). The row's description says "One question whose key names an option the question does not have is left out" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6395-6396`), and its comment reads "588 inspect_evals Samples less the one whose key names a missing option" (`:6451-6453`).
- **Where.** Ours: `without_excluded_samples` drops the Sample before capture. Theirs: inspect_evals keeps all 588 (`inspect_evals:cyberseceval_4/eval.yaml:25-26`, `dataset_samples: 588`).
- **What differs.** The official file's index 360 is question `0eVnfhaO` on FBI report `231116`. It has options `A` to `E` and `correct_answer` `A` to `F`. inspect's target is `['A','B','C','D','E','F']` over five choices, so no reply can match it. Every reply tried scores 0 exact: `ANSWER: A,B,C,D,E,F` → `(0.0, 0.0)`, `ANSWER: A,B,C,D,E` → `(0.0, 0.8333)`, `ANSWER: F` → `(0.0, 0.0)`, empty → `(0.0, 0.0)` (Checks run 6).
- **Severity / bound.** `score-changing`, `1/588`. Our headline is the mean m over 587 Cases. inspect's is 587·m/588, so |Δ| = m/588 ≤ 1/588 = 0.0017.

### D2 — inspect's per-source breakdown and stderr not reproduced

- **Declared.** A `# NAMED DEVIATION` comment on the row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6457-6459`) and the description ("the eval's per-source breakdown is not reproduced", `:6394-6395`).
- **What differs.** inspect publishes `accuracy`, `stderr`, `grouped_accuracy_metric` by source and a grouped Jaccard (`inspect_evals:cyberseceval_4/threat_intelligence.py:688-695`). We publish the mean `score` (the headline) and the mean `jaccard_similarity` as a Named Score.
- **Severity / bound.** `cosmetic`, `0`. The headline equals inspect's `accuracy`, and the overall Jaccard equals inspect's `jaccard_similarity`, on 23/23 vectors (Checks run 7).

### D3 — no temperature fixed (inspect_evals fixes 0)

- **Declared.** The row's description: "inspect_evals runs the model at temperature 0; this benchmark imposes no generation settings" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6396-6397`). This is the same treatment as the committed `inspect-mmmu_multiple_choice` record.
- **Where.** Theirs: `inspect_evals:cyberseceval_4/threat_intelligence.py:517`. Ours: no `params` on the row.
- **Severity / bound.** `possibly-score-changing`, `unknown`. A Candidate's provider-default temperature can change which letters it picks, so only a paired Candidate run can size the effect (Recommended paid runs).

## Upstream notes

- **inspect_evals vs the authors' harness: different examiners by design, `unbounded`.** inspect_evals' own README says its table "is **not** a direct reproduction" and "A direct numeric comparison is therefore omitted intentionally" (`inspect_evals:cyberseceval_4/README.md:298,300`). The audit confirms the gap on four dimensions:
  - *Prompt.* The harness puts the report text first, then "Given the context, answer the following question: …. Options: ['A) …', …]." It lists the options as a Python list repr and asks for `<json_object>{"correct_answers": [...]}</json_object>` (`fork:CybersecurityBenchmarks/benchmark/crwd_meta/threat_intel_reasoning_benchmark.py:69-92`). inspect fills `PROMPT_TEMPLATE` and wraps it in inspect_ai's `MULTIPLE_ANSWER_TEMPLATE`, with `A) …` lines and `ANSWER: $LETTERS`. 0/61 sampled prompts are byte-equal (Checks run 8).
  - *Report text.* Both sides extract the same 45 PDFs with pypdf. The harness pins `pypdf==6.1.3` (`fork:CybersecurityBenchmarks/requirements.txt:14`); inspect_evals leaves pypdf open and we pin 6.19.0. The text differs on 31/45 reports, by up to 16% of the characters (`doppelpaymer` 25,963 vs 30,162). Only 14/61 sampled Cases carry the harness's report text verbatim (Checks run 8). With no fontTools installed, pypdf 6.19.0 warns 78 times that it cannot fully parse CFF Type1 font encodings, so an inspect_evals user's report text can also depend on whether fontTools is installed. Ours is sealed by the Case Digest, which this audit reproduced.
  - *Answer extraction.* The harness's `<json_object>` / `\boxed{}` / `extract_json` path reads none of the 587 `ANSWER:` sheets (`parsing error` 587). inspect reads no JSON reply (0.0000 on the harness-JSON sheet). A model that follows one examiner's instructions fails the other's.
  - *Roll-up.* The harness's `correct_mc_pct` divides by correct + incorrect only, so parse errors leave the denominator (`fork:…/threat_intel_reasoning_benchmark.py:252-259`). The paper's Figures 9 and 10 report that number. inspect and ours count every unparsed reply as 0 over all Cases.
  - *Metric.* On the same letter set, the per-Case rule agrees: 5 sheets × 587, 0 differences in exact mark or Jaccard. Two edge rules differ. The harness counts a repeated letter in the union (`:414-417`; `["C","C"]` → 0.5, not exact) and compares letters case-sensitively (`["c"]` → 0.0). inspect upper-cases and de-duplicates.
- **Question 361 under each examiner.** Its key is `A`-`F` over five options. The harness does not check letters against the options, so the reply `["A","B","C","D","E","F"]` is marked `true` (Checks run 8). inspect marks every reply 0, which is why we leave the question out (D1). Appendix C's key-count distribution counts four 6-answer questions over 588, including this one, so the paper kept it.
- **The paper's counts exceed the published file.** Figure 9 reports `n=601` parsable responses for five models. The published `report_questions.json`, unchanged since `21a5927` (2025-09-13), holds 588 questions. So the run behind Figure 9 used a question set that is not the published one, or counted something else. The exact data behind the paper's numbers is not public.
- **Harness vs paper: modality.** The paper's headline (§3.2, §4.2, Figure 9) gives the report as page images. The harness's default when `--input-modality` is unset is text (`fork:…/threat_intel_reasoning_benchmark.py:35-37`), and inspect's default is text too. Text input is only in Figure 10, a line chart with no printed values. Our row's frontier score (about 0.59) is read from that text line.
- **Harness vs paper: sampling.** The paper says it used provider defaults plus per-model system-prompt adjustments (§4). The public harness's model wrappers default to `temperature 0.6`, `top_p 0.9`, `max_tokens 2048` (`fork:CybersecurityBenchmarks/benchmark/llms/llm_base.py:24-26`). The harness is the reference here. No public code contains the per-model system-prompt adjustments.
- **The public harness has changed since the paper's runs.** Paper v1 is dated 24 Sep 2025. Commit `48a199c` (2025-11-04) rewrote `extract_json`. The threat-intel benchmark file has had only formatting commits (`a6c2de1`, `e9983e6`) since `1597bd4` (2025-09-13). The audit used `fe05293b` (2026-02-19, the revision inspect_evals pins).
- **Report sources.** The harness downloads the 26 non-CrowdStrike PDFs from each question's `url_source` with no checksum (`fork:CybersecurityBenchmarks/datasets/crwd_meta/threat_intel_reasoning/download_reports.py`). inspect pins each one by sha256, and our mirror serves bytes that pass those pins. The CrowdStrike reports come through a submodule the harness pins to nothing. inspect pins `ce7daa5b`, which is the data repo's `HEAD` today (Checks run 9). One question's metadata is wrong in the shared file and harmless to the prompt: `mX9pR4wN`'s `url_source` names `prophet-weblogic.pdf`, but its `report_id` is `qakbot-onenote` (`apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:1804-1806`). Both inspect and the harness read the report by `report_id`.
