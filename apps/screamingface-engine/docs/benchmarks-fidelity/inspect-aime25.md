## Verdict

**`unverified`.** There is no paper and no authors' grading code to sit beside: AIME 2025 is the [Mathematical Association of America's](https://maa.org/) competition, the row's `paper_url` is the Hub dataset itself (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:1034`), its card cites only `Zhang, Yifan and Math-AI Team` with no code, and the [inspect_evals v0.20.0 `aime2025`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/aime2025) README links nothing but the dataset. The one published number the row carries, GPT-5.2 Thinking at 100% ([OpenAI, "Introducing GPT-5.2"](https://openai.com/index/introducing-gpt-5-2/), `benchmarks.py:1048-1053`), was produced by the vendor's own unpublished examiner, a different process by design, so `comparable-to-paper` is out of reach. Against inspect_evals, everything but the mark rule matches with evidence: the 30 Cases are the pinned Hub rows in Hub order with the pinned Case Digest, every Candidate input equals inspect's own `prompt_template` output byte for byte, all 1,080 marks for replies that finished (`stop`) or carry no finish reason equal inspect's `aime_scorer`, and the roll-up equals inspect's `accuracy()` to four decimals on 13 vectors. The mark rule carries one declared Named Deviation (D1, the cut-off guard adopted from [inspect_evals issue #2701](https://github.com/UKGovernmentBEIS/inspect_evals/issues/2701)): a reply stopped at `max_tokens` whose last line has no `ANSWER:` is wrong under ours and read by inspect. On the answer sheets it flips every Case on the four cut-off sheets (ours 0 / inspect 1); on a real run it touches only the Cases whose reply was cut off, a count the run's Report reveals, so its bound is `unknown`: `sum of enumerable bounds against inspect_evals = 0/30 = 0.0000`, plus D1 `unknown` (open, `possibly-score-changing`) → `unverified`. With 30 Cases one moved Case is already `1/30 = 0.0333 > COMPARABLE_TOLERANCE (0.005)`, so a run whose Report shows no `finish_reason: length` Case without an `ANSWER:` last line is `comparable-to-inspect` for that run, and any other count is `not-comparable` against v0.20.0. On such a run, ours and inspect's marks are identical.

## Deviations

### D1 — a reply cut off before an `ANSWER:` line is marked wrong

- **Declared.** `# NAMED DEVIATION` on the row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:1021-1025`), the scorer under `named_deviations/` (`apps/screamingface-engine/src/screamingface_engine_inspect/named_deviations/aime/aime.py:10-33`), the catalogue description (`benchmarks.py:1005-1008`), and the tripwire test `tests/unit/inspect/test_named_deviation_aime.py:61` that fails once the pinned inspect_evals carries the fix. Adopted from [inspect_evals issue #2701](https://github.com/UKGovernmentBEIS/inspect_evals/issues/2701) (open at v0.20.0, per the module docstring).
- **Where.** Ours: `aime.py:57-67` (`if state.output.stop_reason == "max_tokens" and ANSWER_LINE_MARK not in last_line` → `INCORRECT`, `answer=None`), fed by `scorer_adapter.py:641` (`stop_reason=_stop_reason(request.finish_reason)`, `"length"` → `"max_tokens"` via `as_stop_reason`, `:778`). Theirs: `inspect_evals:utils/aime_common.py:70-100`, which reads the last substantive line whatever the stop reason.
- **What differs.** Only replies whose stop reason is `max_tokens`. Among those, a last line without `ANSWER:` that inspect would credit is wrong under ours. That covers #2701's own case, reasoning cut off mid-way whose last number happens to equal the key. It also covers a reply that hit the limit right after a complete `\boxed{g}` block or `The answer is g.` (sheets `display_boxed_gold`, `boxed_gold_last`, `the_answer_is_gold`). That falls inside the declared rule ("whose last substantive line has no `ANSWER:`", `aime.py:20-22`), though the catalogue text names only the first case. A cut-off reply whose last line carries `ANSWER:` keeps inspect's mark, including the stated limitation (cut inside the `ANSWER:` digits, `aime.py:30-33`). Ours can only lower a mark relative to inspect, never raise one.
- **Severity / bound.** `possibly-score-changing`, `unknown` (30/30 Cases on the cut-off answer sheets; a run's Report gives the real count). The answer sheets flip every Case (`('length', 'cut_off_mid_reasoning_gold') cases [1..30] ours/ref [(0.0, 1.0)]`, and the same for the three other sheets, Checks run 6). A single flipped Case moves the headline by 1/30 = 0.0333. In a real run the affected Cases are exactly those whose Candidate reply carries `finish_reason: length` and whose last line inspect would credit, countable from that run's records with no model call.
