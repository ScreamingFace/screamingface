# ARC-Challenge — Fidelity Record

## Verdict

**`comparable-to-inspect`.** Our headline, plain accuracy over the 1,172 ARC-Challenge test questions, can sit beside a run of [inspect_evals v0.20.0 `arc_challenge`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/arc) (zero-shot `multiple_choice()` with inspect_ai's default single-answer template, `choice()` scorer, `accuracy` metric). Against inspect_evals every dimension matches: the same 1,172 Hub rows in the same order with the same keys, the Candidate gets byte-identical prompts (one user message, no system message) on all 1,172 Cases, our served Benchmark's marks equal inspect's own solver plus scorer on all 17,580 sheet marks, the headline equals inspect's `accuracy()` to four decimals on nine vectors, and neither side fixes any generation setting. No deviation, declared or undeclared, was found: `sum of bounds against inspect_evals = 0/1172 = 0.0000 ≤ COMPARABLE_TOLERANCE (0.005)`.

It is **not** comparable to the paper's numbers ([Clark et al. 2018, baselines table, `\label{baselines}`](https://arxiv.org/abs/1803.05457v1): best baseline DGEM 27.11%). The paper's examiner is [allenai/ARC-Solvers](https://github.com/allenai/ARC-Solvers/tree/8f21cb821b3a457f25535ccd1b5cddb01ed1bc4e): retrieval and entailment solvers that score every answer option, with no prompt and no generated text, and a rubric that gives `1/k` for a `k`-way tie. inspect_evals asks a model for `ANSWER: $LETTER` and gives 0 to anything it cannot parse. The harness's own aggregator gives a no-preference sheet 0.2502 (the paper's Guess-all 25.02), where inspect and ours give 0.0000: `inspect_evals vs original harness ≥ 0.2502 > COMPARABLE_TOLERANCE (0.005)`, and on real replies the gap cannot be bounded at all, because the harness cannot read a reply (Upstream notes). Hence `comparable-to-inspect`, not `comparable-to-paper`.

## Upstream notes

- **inspect_evals vs the original harness: a different examiner by design, `unbounded`.** [inspect_evals v0.20.0 `arc`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/arc) cites the paper (`inspect_evals:arc/arc.py:1-5`) but not its code. The paper's numbers come from [allenai/ARC-Solvers@8f21cb82](https://github.com/allenai/ARC-Solvers/tree/8f21cb821b3a457f25535ccd1b5cddb01ed1bc4e) and AI2's other 2018 solvers, which differ on three dimensions:
  1. **Prompt.** The harness's solvers are never prompted: each turns the question plus one option into a hypothesis or search query and scores it (`arxiv-src:v1/ASQ.tex:591`). inspect sends one user message with the `ANSWER: $LETTER` instruction and `A) option` lines (Case 1 above).
  2. **Answer extraction.** The harness reads a per-option `score` and takes the argmax (`fork:arc_solvers/processing/calculate_scores.py:44-47`); there is no text to parse. inspect reads only an `ANSWER:` line (`inspect_ai:solver/_multiple_choice.py:98-110`).
  3. **Metric.** The harness and paper give `1/k` for a k-way tie that includes the key (`fork:…/calculate_scores.py:50-51`; `arxiv-src:v1/ASQ.tex:573`). inspect gives 1 or 0, and 0 for a reply it cannot parse. On the same 1,172 Cases a no-preference answer scores 0.2502 under the harness (the paper's Guess-all, 25.02, `:626`) and 0.0000 under inspect and ours: a gap of 0.2502 > 0.005. Because the harness cannot read a generated reply at all, the gap on real Candidate replies cannot be bounded: `unbounded`. On one-hot selections (exactly one option chosen) the two aggregators agree to four decimals (roll-up row), so the gap is all in how a selection is made, not in how selections are averaged.
- **Harness vs paper.** No disagreement found: the harness's tie rule is the paper's rubric, and its aggregator reproduces Guess-all to two decimals of a percent. The harness's scoring files date from 2018-02-26 / 2018-03-02, before the paper (Checks run 9). The dataset file the harness downloads equals the Hub rows on every id, stem, option and key (dataset row).
- **No published inspect_evals number.** The eval's README has no evaluation-report section (`inspect_evals:arc/README.md:88-90` says only "A simple accuracy is calculated over the datapoints"), so `comparable-to-inspect` means comparable to a run of the pinned eval, not to a number inspect_evals printed.
- **Reviewer note, outside the seven dimensions.** The row's `frontier_score` is 0.969, Llama 3.1 405B Instruct (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:542-547`). That number is Meta's own 0-shot `acc` evaluation from the model card (instruct table, `ARC-C 0 acc … 96.9`, Checks run 11), a third examiner with its own prompt and parsing. Neither inspect_evals nor the ARC paper produced it, so it is not evidence that our headline is on the same scale.
