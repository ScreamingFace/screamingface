# Humanity's Last Exam (HLE) — Fidelity Record

## Verdict

**`not-comparable`.** Our headline, the mean of the judge's correct/incorrect over the 2,500 Cases run with an ungradable reply counting 0, is the accounting of the [CAIS harness](https://github.com/centerforaisafety/hle/tree/26dca2e253b405105b4c3d8c2f5af06f86f90c66) (`sum(correct) / n`, Checks run 13) and the Candidate reads the same 204 prompt bytes the harness sends (Checks run 9, 14). But the examiner is not the paper's: the [paper](https://arxiv.org/abs/2501.14249v12) and the harness grade with `openai/o3-mini-2025-01-31`, the official JSON judge prompt, structured output and one judging pass (`fork:hle_eval/run_judge_results.py:16-53,198`), while our row grades with [inspect_evals' maintained default](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/hle): `regex_judge` under `openrouter/z-ai/glm-5.3-flash`, a paraphrased `GRADE: C/I` prompt, up to three asks (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:7365-7401`; `inspect_evals:hle/run_configs/default.yaml:29-51`). Spec §2.3 makes a different judge model `not-comparable` by rule, and inspect_evals' own README says the same of its default (`inspect_evals:hle/README.md:238-239`, "Default-run scores are not comparable"). Bound arithmetic, for the record: `bounds vs original harness = D1 0 + D2 0 + D5 0 = 0`, with D3 and D4 `unknown`; the judge process differs by design, so the third clause of the rule decides, not the sum. Against inspect_evals (the ceiling here, `comparable-to-inspect`) the audit matches on dataset, answer extraction, metric and whole-run arithmetic, but D3 and D4 are open `possibly-score-changing` deviations and the official rows were not rendered (gated dataset), so that verdict would be `unverified`.

## Deviations

### D1 — ungradable Cases count 0 in the headline, where inspect's `accuracy` drops them

- **Declared.** `# NAMED DEVIATION` on the row, `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:7378-7382`; `failure_policy="withhold"` at `:7035`; the description names it (`:7016-7018`). Pinned by `tests/unit/inspect/test_hle_importer_scorer.py:129-140` (`mean_instead_of == "accuracy"`, passed).
- **Where.** Ours `single_shot.py:1275,1303` + `aggregation.py:94-106`; theirs `inspect_evals:hle/metrics.py:66-84` (`accuracy`, scored only) vs `:101-123` (`original_accuracy`, all attempted); harness `fork:hle_eval/run_judge_results.py:148`.
- **What differs.** A Case whose judge reply carried no `GRADE` line in three asks is 0 in our denominator and in the harness's; inspect's headline leaves it out.
- **Severity / bound.** `score-changing`. Bound 0 against the harness and against inspect's `original_accuracy` (identical to four decimals on six vectors, Checks run 13); against inspect's `accuracy`, `unscored/2500` per run, unknown before a run (0 on every sheet where the judge wrote a grade).

### D2 — the backup judge is not run

- **Declared.** `benchmarks.py:7386-7388`.
- **Where.** Theirs `inspect_evals:hle/run_configs/default.yaml:53-57` (`grader_2: openrouter/google/gemini-3.7-flash`); `README.md:123,129`: a separate score column, "not voted or averaged"; "For a single headline number, use the primary judge."
- **Severity / bound.** `cosmetic`, `0`: no mark of the primary column depends on it.

### D3 — the judge's fp8 provider pin is not sent

- **Declared.** `benchmarks.py:7389-7391`; `judge_provider.py:362` names the loss.
- **Where.** Theirs `default.yaml:46-48` (`provider: quantizations: [fp8]`, a `model_args` entry; README `:131` says a bound role "does not inherit `model_args` such as the default GLM fp8 provider filter"). Ours sends model + `temperature`/`max_tokens` only (`benchmarks.py:7392-7397`).
- **Severity / bound.** `possibly-score-changing`, `unknown`: OpenRouter may serve `glm-5.3-flash` at another precision; only a paired judge run bounds it (Recommended paid runs).

### D4 — the eval's system message rides inside the user prompt

- **Declared at the plugin level, not on the row** (a finding for the row): `capture.py:75-79` ("Named deviation (contracteval pattern): a Benchmark cannot address a Candidate's system role, so the eval's system instruction rides ahead of the user prompt"), `picture_input.py:75-78,123-129`, and the glossary's Named Deviation definition names "a system message delivered as input text" (`CONTEXT.md:323-326`). The HLE row (`benchmarks.py:7005-7405`) carries no `# NAMED DEVIATION` line for it and its description does not say it.
- **Where.** Ours: text Case `system_mc + "\n\n" + question` (`capture.py:79`), picture Case `[text(system_mc), text(question), image_url]` in one user message (`picture_input.py:127-129`). Theirs: `ChatMessageSystem(system_prompt)` + `ChatMessageUser(content)` (`inspect_evals:hle/dataset.py:148-151`); harness `{"role": "system"}` (user for o1) + user (`fork:hle_eval/run_model_predictions.py:23-27`).
- **What differs.** Every byte of text is equal (Checks run 14); the Candidate receives it as user text, not a system turn. The judge never sees it: it quotes the kept Sample question (`scorer_adapter.py:617-633`, `prepare.py:2156`), equal to inspect's `state.input_text` on 48/48 sheets.
- **Severity / bound.** `possibly-score-changing`, `unknown`: a Candidate may follow a system instruction differently from user text; 2,500 Cases, needs a paired Candidate run.

### D5 — a lower-case grade letter fails the Case here, scores 0.0 with a warning there

- **Undeclared.** Finding, cosmetic for the headline.
- **Where.** The regex is case-insensitive (`(?is)`, `inspect_evals:hle/prompts.py:75`), so `grade: c` yields `"c"`; inspect's `regex_judge` keeps it (`scorers.py:211-215`), `value_to_float` lower-cases only yes/no/true/false and returns 0.0 with "Unable to convert value to float: c" (`inspect_ai:scorer/_metric.py:328,337-338`), and `_scored` keeps the sample (`metrics.py:46-53`). Ours: `_score_as_float` looks the letter up case-sensitively (`scorer_adapter.py:880-881`, map `:111`) → `invalid_score_value` (`:549-550`) → failed Case, 0 under `withhold`.
- **Severity / bound.** `cosmetic`, `0`: 3/3 sheets and the "3 lower-case c" vector give 0.9988 on both sides (Checks run 11, 13). The accounting differs (our coverage shows a failed Case; inspect's `unscored` stays 0). Note that a lower-case **c** is a *correct* verdict that both sides mark 0; see Upstream notes.

## Upstream notes

- **inspect_evals' default vs the CAIS harness: a different examiner by design.** Judge model (`glm-5.3-flash` vs `o3-mini-2025-01-31`), prompt (paraphrased `regex_judge_template` + `GRADE: C/I` vs the 1,290-byte official JSON prompt, Checks run 9), parsing (regex on free text vs structured output, `inspect_evals:hle/scorers.py:189-195` vs `fork:hle_eval/run_judge_results.py:52`), attempts (3 vs 1, `default.yaml:35` vs `original.yaml:25`), judge `max_tokens` (32768 vs 4096, `default.yaml:51` vs `original.yaml:36`). inspect_evals' own README calls default-run scores "not comparable with earlier versions" and offers `original.yaml` as the paper-faithful config (`README.md:19,121,238-239`). Bound: unbounded by design; this is why `comparable-to-inspect` is the ceiling for this row and why the verdict is `not-comparable` against the paper.
- **Harness vs paper: the exact-answer prompt was never sent.** The first harness commit chose a prompt by `answer_type == 'exact_match'` while the dataset writes `exactMatch` (`386ed4b:hle_eval/run_model_predictions.py:12-19`), so every question got the multiple-choice prompt; commit `67b3251` (2025-06-06) made that the single `SYSTEM_PROMPT`. inspect_evals records this in `prompts.py:22,34` and ships `system_mc` as the leaderboard prompt. Harness wins; ours equals it byte for byte.
- **Calibration error is not comparable between harness and inspect_evals**, and ours reproduces neither: the harness drops the top-confidence bin and prints integer percent (`fork:hle_eval/run_judge_results.py:107,151`), inspect keeps every bin (`inspect_evals:hle/metrics.py:231-234`). Our second Named Score is the confidence mean, not a calibration error (`benchmarks.py:7024-7026`).
- **Dataset size moved under the harness.** The harness README's example reports `n = 2700` (`fork:README.md:52`); the pinned Hub commit holds the 2,500-question set inspect_evals and we both read (`inspect_evals:hle/eval.yaml:11`; README `:27`). The harness itself pins nothing (`fork:hle_eval/run_judge_results.py:162`).
- **A lower-case grade letter is scored 0.0 upstream, not left unscored.** inspect's case-insensitive regex (`prompts.py:75`) accepts `grade: c`, `regex_judge` keeps `"c"`, and inspect_ai's `value_to_float` returns 0.0 with a warning (`inspect_ai:scorer/_metric.py:337-338`), so a correct verdict spelled in lower case counts as incorrect under inspect's `accuracy`; our path fails the Case instead, the same 0 in the headline (D5).
