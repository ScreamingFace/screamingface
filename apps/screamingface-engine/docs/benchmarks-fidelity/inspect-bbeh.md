# BIG-Bench Extra Hard — Fidelity Record

## Verdict

**`unverified`.** Our headline is plain accuracy over 4,519 Cases. The number it is built to sit beside is the paper's **micro average**: Table "The micro average performance of various models on BBEH" in [Kazemi et al. 2025, v2](https://arxiv.org/abs/2502.19187v2) (o3-mini (high) 54.2, GPT4o 22.3), the same column as "BBEH (Micro Avg)" in the [authors' leaderboard](https://github.com/google-deepmind/bbeh/tree/80d12ca916b7158f22293fcf3144f4d3d854d4be). It is **not** the paper's headline, the adjusted harmonic mean (o3-mini (high) 44.8). It is not [inspect_evals' `bbeh`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/bbeh) headline either: that Task reports 23 per-task accuracies and the harmonic mean, and no pooled accuracy (D3, declared, Checks run 6).

Against the [authors' harness](https://github.com/google-deepmind/bbeh/tree/80d12ca916b7158f22293fcf3144f4d3d854d4be), the Cases, the marks and the roll-up all match:
- **Cases.** Our Case set equals the authors' 23 `task.json` files as a multiset, minus one exact duplicate. inspect_evals drops that duplicate (D1).
- **Marks.** All 94,899 answer-sheet marks are identical across ours, inspect_evals' `bbeh_scorer` and the authors' `evaluate.py`.
- **Roll-up.** Ours equals the pooled mean on eight vectors.

What stops `comparable-to-paper` is the prompt (D2, undeclared, inherited byte for byte from inspect_evals). The paper's instruction suffix, as its LaTeX source writes it, is one paragraph. inspect_evals' copy breaks it into five lines at what look like the PDF's wrap points, and turns one double space into a single space. The authors never published their prompt builder, so the exact bytes they sent cannot be recovered. How a Candidate reacts to those line breaks can only be measured by a paired run.

Arithmetic: `enumerable bounds against the original harness = 1/4520 (D1) + 0 (D3) = 0.0002 ≤ COMPARABLE_TOLERANCE (0.005)`, plus D2 `possibly-score-changing`, bound `unknown`. One such deviation is open, so the verdict is `unverified`. If the paired run bounds D2 at ≤ 0.0048, the rule gives `comparable-to-paper` against the micro-average table, never against the harmonic-mean headline.

## Deviations

### D1 — one duplicated problem is served once, where the harness counts it twice

- **Declared.** The row description says "the eval drops one duplicated problem from the published 4,520" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:3953-3955`). `case_count=4519` is at `prepare.py:646`.
- **Where.** Ours: the replay of `load_bbeh_dataset`, whose `filter_duplicate_ids` (`inspect_evals:bbeh/data.py:60`; `inspect_evals:utils/deps_utils.py:70`, "keeping only the first occurrence") drops the second copy. The Sample id is a hash of `(task, input, target)` (`inspect_evals:bbeh/data.py:86-88`). Theirs: `fork:bbeh/benchmark_tasks/bbeh_spatial_reasoning/task.json` holds the row twice. The authors' note is at `fork:bbeh/benchmark_tasks/bbeh_spatial_reasoning/README.md:41` ("there is one duplicate example in our set").
- **What differs.** The spatial-reasoning row with key `pill bottle` (our Case 4002) has weight 1/4519 in our mean and 2/4520 in the harness's. Spatial reasoning has 199 Cases here and 200 in the paper.
- **Severity / bound.** `score-changing`, `1/4519` (Case 4002). The headline moves by at most `|4519·m − S| / (4520·4519) ≤ 1/4520 = 0.0002`. Measured shifts were `0.4992 → 0.4991` (alternating) and `0.0445 → 0.0447` (only spatial reasoning) (Checks run 5).

### D2 — the instruction suffix's whitespace differs from the paper's

- **Undeclared (a finding), inherited from inspect_evals byte for byte.** The row description says "Every prompt carries the paper's instruction to think step by step" (`benchmarks.py:3955-3957`). Nothing on the row, the spec or a README names the whitespace.
- **Where.** Ours: the Case input, equal to inspect's `Sample.input` on 4,519/4,519. Theirs: `inspect_evals:bbeh/data.py:13-17` (the comment at `:12` says the suffix "is provided in the original paper appendix") and the join at `:84`. Paper: `main.tex:946` (v2), identical in v1 (`main.tex:920`).
- **What differs.** The four line breaks fall at `"The answer is:"⏎without`, `no bolding, and⏎no markup`, `If the question is multiple⏎choice` and `corresponding to⏎the correct answer`. They sit where a PDF text column wraps, while the LaTeX source has spaces there. The source also has `or  "The answer is: yes"` with two spaces where inspect has one. With whitespace collapsed, the texts are equal. The join is one space after the question, and 1,418 of 4,519 questions already end in whitespace, so those get `\n ` or `\n\n ` before `Think step by step` (Checks run 7). The authors' own builder is not published, so their exact bytes, line breaks and join cannot be recovered.
- **Severity / bound.** `possibly-score-changing`, `unknown`. No scorer reads the prompt, but a Candidate may follow a line-broken instruction differently from a one-paragraph one, e.g. in how often it emits the `The answer is:` prefix. This needs a paired Candidate run (Recommended paid runs).

### D3 — the headline is the paper's micro average, not its harmonic-mean headline

- **Declared.** The row comment reads "The eval's own accuracy metric IS the board's mean per-case score. Its per-task accuracies (inspect_ai/grouped) and their harmonic mean (inspect_evals/harmonic_mean_across_tasks) are not reported; the description names that" (`benchmarks.py:3979-3982`). The row description reads "Benchmark score = plain accuracy (micro average) … the paper's headline BBEH score is the harmonic mean of the 23 per-task accuracies (each plus 0.01), which the board does not compute" (`benchmarks.py:3962-3966`). The frontier score is the micro-average figure, `score=0.542` (`benchmarks.py:4006-4012`). Note: the row lacks the `# NAMED DEVIATION:` tag that the importer now writes for a kept mean (`tests/unit/inspect/test_importer_whole_run_choice.py:139`). The row predates that path, and its comment and description carry the same declaration.
- **Where.** Ours: `apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1275-1303`. Theirs: `inspect_evals:bbeh/bbeh.py:40-47`, `:70-87`. Paper: `main.tex:398` (harmonic mean as "our primary evaluation metric for BBEH") and `:402`, `:485` (micro average "for completeness").
- **What differs.** No Case's mark. Only which whole-run statistic is printed. Ours equals the paper's micro-average table and the count-weighted mean of inspect's 23 per-task accuracies on every vector tested. Never read it against 44.8 or against inspect's `harmonic_mean_across_tasks`.
- **Severity / bound.** `cosmetic`, `0`, against the micro-average number the record names.

## Upstream notes

- **The authors' harness publishes no prompt builder and no aggregator.** inspect_evals' prompt is its copy of the paper's appendix text. The harmonic mean and the pooled mean are the paper's definitions (`main.tex:398`, `:402`). D2 is the one place the copy is not exact, and it is counted above because the paper is the only reference for the prompt.
- **inspect_evals' harmonic mean matches the paper's arithmetic.** It adds 0.01 to each per-task accuracy and does not subtract it afterwards (`inspect_evals:bbeh/bbeh.py:84-85`). The paper's Table "performance … overall on BBEH" equals `harmonic_mean(acc + 1)` with nothing subtracted, on all 13 models (Checks run 8). So a perfect run reads `1.0075`, not 1.0 (Checks run 6). Bound 0.
- **inspect_evals' own README run is not evidence either way.** Its gpt-4o run reports harmonic mean `0.079` against the paper's `0.060`, and its pooled micro is `0.2151` against the paper's `0.223` (Checks run 8). The run was on 11 August 2025 against `openai/gpt-4o`, while the paper used the 2024-11-20 snapshot (`main.tex:396`). Neither the model nor the sampling is held fixed, so the gap is not attributable to the grader. The grader is identical by the answer sheets.
- **Paper vs harness on extraction (the harness wins, recorded, not counted).** The paper says it looks for four prefixes "until one of them is found" and treats quotes or brackets at either end as equal (`main.tex:950`). `fork:bbeh/evaluate.py:31-45` instead splits on every listed prefix in turn, keeping the text after the last occurrence each time. It strips one trailing `.` from the reply only (`:43-44`, `:85`), and its bracket rule is only `[ref]` vs `pred` (`:71-72`). One consequence is that the 11 linguini keys ending in `.` can never be matched (metric row). The published numbers come from this code, and all three examiners reproduce it.
- **The data's own known issues** are kept on every side: the exact spatial-reasoning duplicate, where inspect_evals keeps one copy (D1, `1/4520`), and the 7 linguini rows sharing one input. The authors document both (`fork:bbeh/benchmark_tasks/bbeh_spatial_reasoning/README.md:41`, `fork:bbeh/benchmark_tasks/bbeh_linguini/README.md:18-19`).
- **inspect_evals vs the original harness**, for completeness: D1 (`1/4520`) plus D2 (`unknown`). This is not above tolerance on any established bound. So even without D3, this record could not be `comparable-to-inspect`; and with D3, inspect_evals publishes no pooled number to be comparable to.
