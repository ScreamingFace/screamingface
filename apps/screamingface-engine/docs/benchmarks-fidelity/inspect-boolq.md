# BoolQ — Fidelity Record

## Verdict

**`unverified`.** Our headline is plain accuracy over the 3,270 questions of the BoolQ dev split (`google/boolq` `validation`). It is meant to sit beside the dev-set numbers of [Clark et al. 2019, arXiv 1905.10044v1](https://arxiv.org/abs/1905.10044v1) (Table 4: BERT-L + MultiNLI 82.20 dev / 80.43 test; majority 62.17 dev) and beside a run of [inspect_evals v0.20.0 `boolq`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/boolq). The audit could not settle it. Most of the exam is the same. Case input bytes equal the eval's `Sample.input` on 3,270 of 3,270 Cases. Our Sample ids, inputs and gold equal the Hub's at the pin. Question, passage and label equal the authors' dev file (via its [SuperGLUE v2](https://super.gluebenchmark.com/tasks) copy) on all 3,270 rows. The roll-up equals inspect's `accuracy()` and the authors' label-accuracy to four decimals on 14 vectors. One thing is open: **the declared Named Deviation D2 grades with inspect_evals' later bare-word pattern (PR #2334, eval version `3-A`), not the pinned v0.20.0 pattern.** On the answer sheets it equals the merged fix on every mark, and differs from v0.20.0 on 11 of 23 reply forms. Examples: `**Yes**`, `Yes` plus a trailing newline and `Yes!!` are right only under ours; `The answer is: No`, a reasoning line then `No`, and `I don't know` (on the 1,237 No Cases) are right only under v0.20.0. How many Cases move depends on how a Candidate words its replies. No Report exists to rescore (the row records no leaderboard entry), so D2 is `possibly-score-changing`, bound `unknown`. The other two deviations are cosmetic: D1, a declared seeded row order, and D3, inspect's `stderr` not published. Arithmetic: `sum of stated bounds = 0/3270 (D1) + 0/3270 (D3) = 0.0000`, plus D2 `unknown` (open) → `unverified`. D2 would be bounded within tolerance if, on a real run, ours and v0.20.0 differ on at most 16 Cases (`16/3270 = 0.0049 ≤ COMPARABLE_TOLERANCE (0.005)`; 17 would be `0.0052`). See Recommended paid runs.

## Deviations

### D1 — row order forced by a declared shuffle seed

- **Declared.** `apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:989` ("Fold: same Cases; order forced by shuffle_seed through inspect's shuffle (D1)"), with `shuffle_seed=20260917` at `:1001`. The mechanism is in `docs/spec/2026-10-02-ome-1460-one-fetch-path.md:281`, and boolq is listed under "our row shuffle, upstream unseeded" at `:365`. The row description says "Cases are served in a fixed seeded shuffle (inspect_evals randomizes order per run)" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:694-696`).
- **Where.** Ours: `fetch_pins_of(spec)` (`apps/screamingface-engine/src/screamingface_engine_inspect/task_replay.py:404`) hands the seed to the recorder, which forces it onto the eval's `hf_dataset(shuffle=True)`. Theirs: `inspect_evals:boolq/boolq.py:40`, `:46` (`shuffle: bool = True`, no seed) → `inspect_ai:dataset/_sources/hf.py:264-265`.
- **What differs.** Only the Case numbering. Every Case's text and key equal the Hub's (dataset row).
- **Severity / bound.** `cosmetic`, `0`. A mark does not depend on position: the answer sheets mark per Case, and the roll-up is order-free.

### D2 — graded on a bare Yes or No (inspect_evals PR #2334), not the pinned v0.20.0 pattern

- **Declared.** `# NAMED DEVIATION` on the row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:707-710`). The scorer lives under `named_deviations/` (`apps/screamingface-engine/src/screamingface_engine_inspect/named_deviations/yes_no/yes_no.py:10-16`, `:46-49`). A tripwire test fails when the pin reaches the fix (`tests/unit/inspect/test_named_deviation_yes_no.py:98-106`). The row description spells out the trade (`benchmarks.py:685-698`).
- **Where.** Ours: `yes_no.py:49`, `pattern(r"\A[\W_]*(Yes|No)[\W_]*\Z")`. Theirs at the pin: `inspect_evals:boolq/boolq.py:53`, `pattern(r"(Yes|No).?\Z")`. inspect_evals' own later version, at [`2999eaad` line 53](https://github.com/UKGovernmentBEIS/inspect_evals/blob/2999eaadad35edebada59bac4a687793c11d1c3c/src/inspect_evals/boolq/boolq.py#L53), is byte-equal to ours. Its README changelog for `[3-A] - 2026-08-31` says: "This is not a strict tightening… Results are not comparable with `2-A`." The pinned v0.20.0 is eval version `2-A` (`inspect_evals:boolq/eval.yaml:8`).
- **What differs.** v0.20.0 uses `re.search` for Yes/No plus at most one character at the very end. So it accepts the label inside prose (`The answer is: No`) and the tail of a non-answer (`I don't know` → `now`, `Domino`, `Yes or No`). It rejects two or more wrapping characters (`**Yes**`, `Yes!!`, `  Yes  `) and a trailing newline. Ours accepts only the bare word, with any run of non-word characters or underscores around it.
- **Severity / bound.** `possibly-score-changing`, `unknown`. On every answer sheet, the Cases that move are all Cases or all No Cases of that reply form (Checks run 5). So the size of the gap depends on how often a Candidate writes each form, and only a run's replies show that. Applied as the sweep applies it to reply-dependent grading differences (AIME's cut-off guard).
- **Evidence.** Checks run 5. `ours vs fix: sheets with any differing mark: none`. Ours vs v0.20.0 differs on 11 of 23 sheets, as listed in the answer-extraction row.

### D3 — inspect's `stderr` not published

- **Undeclared.** There is no declaration form for it on the row. The description says "benchmark score = plain accuracy over the cases run" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:696`), which states the choice but is not a declaration.
- **Where.** inspect's `pattern()` declares `metrics=[accuracy(), stderr()]` (`inspect_ai:scorer/_pattern.py:55`). Ours publishes one headline (`apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1275-1303`).
- **Severity / bound.** `cosmetic`, `0`. It changes no mark and not the headline (roll-up row).

## Upstream notes

- **inspect_evals v0.20.0 vs the authors: a lenient pattern that reads non-answers as labels, `unbounded`.** The authors score labels: a fine-tuned classifier emits yes/no (`fork:README.md:7`, paper Tables 3-4). v0.20.0's `pattern(r"(Yes|No).?\Z")` (`inspect_evals:boolq/boolq.py:53`) turns a free-form reply into a label. It reads `I don't know`, `Domino` or `Yes or No` as the label No, credited on all 1,237 No Cases (`0.3783` for a Candidate that always says "I don't know"). It reads no label from `**Yes**`, `Yes!!` or `Yes` plus a newline. inspect_evals fixed this in eval version `3-A` (PR #2334, merged sha `2999eaad`) and says "Results are not comparable with `2-A`". The gap depends on reply wording, so it cannot be bounded without a run. Ours adopts the fix (D2).
- **The authors define no prompt and no reply format.** The prompt (`Given a passage, answer the subsequent question with either Yes or No. Include nothing else in your response.`, `inspect_evals:boolq/boolq.py:27-33`) and the bare-word rule are inspect_evals'. Under ours, a Candidate that wraps a right label in prose (`The answer is: No`) gets 0, though a person turning its replies into a label file would read `no`. That is the prompt's instruction, not a harness rule.
- **The article title is dropped.** The authors' examples carry `title` "as optional additional context" (`fork:README.md:6`, `:32`). The paper says "We include the article title since it can potentially help resolve ambiguities" (§3). SuperGLUE serves it as a `title -- ` passage prefix on all 3,270 rows. The Hub `google/boolq` that inspect_evals loads has no title column, so neither inspect's nor our prompt shows it. The authors call it optional and the paper does not say its models read it, so it is recorded, not counted. A Candidate's accuracy with and without the title has not been measured.
- **Which published number is the dev number.** The paper's headline 80.43% is **test**-set accuracy (labels hidden, `fork:README.md:42`). The dev-set figure for the same model is 82.20 (Table 4), which is the one our dev-split headline sits beside. The row's human baseline (0.90, `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:739`) is the annotators' agreement with the authors' gold on 110 sampled examples (§3.3), not a human sitting the 3,270 dev questions. The row's frontier score (PaLM 2-L 0.909, `benchmarks.py:741-746`) is a vendor-run 1-shot evaluation on the splits of Brown et al. 2020 ([PaLM 2 report v3, Table 2](https://arxiv.org/abs/2305.10403v3)). Its prompt and reply reading are the vendor's own, not this template and pattern.
- **The authors' dev file is no longer served.** `https://storage.googleapis.com/boolq/dev.jsonl` (linked at `fork:README.md:46`) returns a GCS billing error. The [SuperGLUE v2](https://dl.fbaipublicfiles.com/glue/superglue/data/v2/BoolQ.zip) `val.jsonl` was used as the authors' data. Row by row, with its title prefix stripped, it equals the Hub on question, passage and label for all 3,270 rows, in the same order.
- **No published inspect_evals number.** The eval's README has no results section (`inspect_evals:boolq/README.md:73-75`), so there is no inspect_evals figure to sit beside.
