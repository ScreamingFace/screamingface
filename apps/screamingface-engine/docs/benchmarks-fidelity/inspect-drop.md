# DROP — Fidelity Record

## Verdict

**`unverified`.** Our headline is mean F1 over the 9,535 Cases. It is built to sit beside a run of [inspect_evals v0.20.0 `drop`](https://github.com/UKGovernmentBEIS/inspect_evals/tree/v0.20.0/src/inspect_evals/drop) with its defaults: 3 worked examples drawn with seed 42, the "Answer: $ANSWER" instruction, `f1(extract_answer)` and the `mean()` metric. inspect_evals publishes no number for this eval.

Our headline is **not** comparable to the paper's numbers. [Dua et al. 2019, v2](https://arxiv.org/abs/1903.00161v2), Table 4, reports NAQANet 47.01 F1 and humans 96.42 F1 on the test set. Those come from the authors' official evaluator, [`drop_eval.py`](https://github.com/allenai/allennlp-reading-comprehension/tree/14fc0a424441de1b1c9cba8745f678df447b407f/allennlp_rc/eval), which marks differently from inspect's `f1` in two ways:
- It sets F1 to 0 when the numbers disagree.
- It aligns multi-span answers one-to-one.

On our answer sheets the two examiners disagree on 466 to 1,945 Cases per sheet. A gold reply scores 1.0000 on inspect and 0.9525 on the official evaluator (Upstream notes, `unbounded`). Our row's description says so itself (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:6327-6329`).

Against inspect_evals, three things hold:
1. Every Case is served with inspect's exact text and accepted answers.
2. Our 152,560 sheet marks equal inspect's own scorer on every sheet, and 239 more equal inspect's real `eval()`.
3. The headline equals inspect's `mean()` to four decimals on eight vectors.

There are two deviations, both undeclared on the row:
- D2, the unpublished clustered `stderr`, is cosmetic with bound 0.
- D1, the system message delivered as leading user text, is `possibly-score-changing` with bound `unknown`.

Arithmetic: `bounds against inspect_evals = 0/9535 (D2) + unknown (D1)`. One `possibly-score-changing` deviation is open, so the verdict is `unverified`. Once D1 is bounded at ≤ 0.005, the rule gives `comparable-to-inspect`, because inspect_evals vs the original harness is `unbounded`.

## Deviations

### D1 — the eval's system message rides inside the user prompt

- **Declared?** Not on the row. The plugin-level rule is named at `apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:75-77` ("Named deviation (contracteval pattern): a Benchmark cannot address a Candidate's system role…"). The glossary's Named Deviation lists "a system message delivered as input text" and says "It is written on the Benchmark" (`CONTEXT.md:325`). The drop row (`benchmarks.py:6315-6380`) and its Task-replay declaration (`prepare.py:1723-1739`) carry no `# NAMED DEVIATION` line. The description (`benchmarks.py:6319-6331`) does not mention the role. Under the agent's rule this counts as undeclared. It is the same mechanism the sibling records (musr, cybermetric, sad_*) record.
- **Where.** Ours: system text + `"\n\n"` + user text, sent as one user turn (`apps/screamingface-engine/src/screamingface_engine_inspect/capture.py:79`, `:538`). The grader's state holds the same single user message (`apps/screamingface-engine/src/screamingface_engine_inspect/scorer_adapter.py:635`). Theirs: `system_message(SYSTEM_W_EXAMPLES_PROMPT_TEMPLATE.format(...))` inserts a system turn ahead of the user turn (`inspect_evals:drop/drop.py:137-143`, `:147-151`).
- **What differs.** Every byte of text is equal on all 9,535 Cases (Checks 4, 5). The Candidate receives two things as the opening of its user turn instead of as a system turn: the task instruction and the three worked examples ("Passage: … Question: … Answer: second,fourth", "… Answer: 205", "… Answer: 10167"). The scorer never reads the prompt: `f1` reads only the reply and the target.
- **Severity / bound.** `possibly-score-changing`, `unknown`. A Candidate may follow few-shot examples and instructions in a system turn differently from the same text in its user turn. Only a paired Candidate run can bound it (Recommended paid runs).

### D2 — inspect's clustered standard error is not published

- **Declared?** No. The row's description says "Benchmark score = mean F1 over the cases run" (`benchmarks.py:6329`) and does not mention `stderr`.
- **Where.** Ours: `_accuracy` publishes the mean, plus `correct` and `scored_cases` (`apps/screamingface-engine/src/screamingface_engine_inspect/single_shot.py:1275-1303`). Theirs: `stderr(cluster="passage_hash")` (`inspect_evals:drop/drop.py:92`), clustered on the MD5 of the passage (`:159`). Our Task-replay declaration keeps no Sample metadata (`keep_sample_metadata False`, Checks 3), so no cluster key reaches the run.
- **What differs.** Only the run's reported uncertainty. The headline is identical.
- **Severity / bound.** `cosmetic`, `0`. No Case's mark and no headline changes (Checks 8).

## Upstream notes

- **inspect_evals vs the authors' official evaluator: a different examiner, `unbounded`.** The paper's numbers come from `drop_eval.py`, which marks in three ways inspect's `f1` does not:

  - Multi-span golds are aligned one-to-one (`:87-102`, `:161-169`).
  - A number is kept only when Python's `float()` parses the whole token (`:29-33`).

  inspect's `f1` compares one bag of words against each accepted answer (`inspect_ai:scorer/_classification.py:85-114`). inspect_evals joins every multi-span gold into one comma-joined string (`inspect_evals:drop/drop.py:216`). The same sheets, scored by both (Checks 7):
