## Deviations

### D1 — the authors' system prompt sent as leading user text

- **Declared.** The row's description says so (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:4384-4388`: "One named deviation from the paper: it sends its extraction instructions as a system message, while this board delivers them as the leading text of the single candidate input…"). The package README says it too (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/contracteval/README.md:23-27`), as does `contracteval.py:33-37`.
- **Where.** Ours: `contracteval.py:99-102` (`f"{SYSTEM_PROMPT}\n{USER_TEMPLATE.format(...)}"` as `Sample.input`, `:127`). Theirs: `fork:proprietary_model.py:38-57` (`"role": "system"` at `:40`, `"role": "user"` at `:49`); `fork:open_source_model.py:56-57`.
- **What differs.** The instruction text is the same (Checks run 12). The Candidate gets it as the head of one user message, joined by one newline, where the harness sent it as a separate system turn.
- **Severity / bound.** `possibly-score-changing`, `unknown`: how a model treats a system turn versus a user prefix is model behaviour, and only a paid run can bound it.

### D2 — `Context: ` loses its trailing space

- **Declared.** `README.md:25-26` ("one known delta from the reference: `Context:` without the reference's trailing space") and `contracteval.py:71-75` (the PR #984 review note, which keeps the published bytes).
- **Where.** Ours: `contracteval.py:88` (`USER_TEMPLATE = """Context:`). Theirs: `fork:proprietary_model.py:19` (`prompt = """Context: `).
- **What differs.** One byte (U+0020) is missing before the first newline, on all 4,182 Cases (Checks run 5).
- **Severity / bound.** `possibly-score-changing`, `unknown`: the bytes the Candidate reads differ, so its replies may differ. The same paid run as D1 bounds both.

### D3 — the decline test case-folds where the harness lower-cases

- **Undeclared (a finding).** `README.md:37` says our test is "case-folded", but neither it, the spec nor the code names this as a difference from the harness. `grading.py:11-14` says every rule is "the reference's behaviour including its quirks".
- **Where.** Ours: `grading.py:52` (`_ABSTENTION in normalized(output).casefold()`) and, for Jaccard, `grading.py:95` (`text.casefold()`). Theirs: `fork:Evaluation.py:50,63` (`'no related clause' in output.strip(" \n`").lower()`) and `fork:Evaluation.py:111-112` (`.lower()`). The repo's verbatim test copy keeps `.lower()` (`tests/unit/_contracteval_reference.py:49`). Its parity replies include no case-folding-only character, so the parity test cannot see this.
- **What differs.** A reply whose decline phrase matches only after case-folding is a TN for us and an FP for the harness. U+017F LATIN SMALL LETTER LONG S is the only code point whose `casefold()` lands inside `no related clause` while its `lower()` does not (exhaustive scan, Checks run 10). The reverse never happens. It touches only the 2,938 no-clause Cases: the clause Cases are marked by containment, which uses no case mapping on either side. The same root cause moves the per-Case Jaccard (18 clause Cases on the probe sheet) and `jaccard_mean` (0.0027 vs 0.0025), which are not marks. CUAD's gold spans contain no character where the two foldings differ, and the contracts contain only `µ`, which can't affect a match (Checks run 10).
- **Severity / bound.** `possibly-score-changing`, `unknown`. It is 0 on every plausible reply shape: 16 of 17 sheets, 66,912 marks. It is 2,938/4,182 on the probe. On a real run the bound is the number of no-clause Cases whose reply contains U+017F in the phrase, divided by 4,182. It is free to count from any Report's replies, but unknown before a run.

### D4 — F1 is 0.0 where the harness divides by zero

- **Declared.** `grading.py:106-108` (`NAMED DEVIATION`) and `README.md:41-42`, asserted by `test_we_return_zero_where_the_reference_raises` (`tests/unit/test_contracteval_parity.py:144`, passed).
- **Where.** Ours: `grading.py:111-115`, and F2 at `contracteval.py:196-198`. Theirs: `fork:Evaluation.py:76-77` (no guard).
- **What differs.** On a run with no true positive, the harness raises and publishes nothing, while we publish F1 0.0 and F2 0.0. This happened on 7 of the 20 roll-up vectors (Checks run 15).
- **Severity / bound.** `cosmetic`, `0`: no Case's mark moves, and wherever the harness returns a number ours is equal to four decimals.

### D5 — laziness divides by the graded clause Cases, not a hard-coded 1,244

- **Declared.** `contracteval.py:210-214` (`NAMED DEVIATION`) and `README.md:51-54`.
- **Where.** Ours: `contracteval.py:212-214`. Theirs: `fork:Evaluation.py:57` (`/1244`).
- **What differs.** On a full run, the graded clause Cases number exactly 1,244 (Checks run 5), so the two rates are equal: they agree to four decimals on all 13 defined vectors (Checks run 15). They differ only on a subset or partial-coverage run.
- **Severity / bound.** `cosmetic`, `0`: a secondary run metric, never a mark and never the headline.

### D6 — Jaccard is defined on an empty or NaN reply

- **Undeclared (a finding, cosmetic).** The harness writes replies to CSV and reads them back (`fork:proprietary_model.py:118`; `fork:Evaluation.py:133`). An empty reply, or `N/A`, comes back as NaN, and `output.strip(...)` at `fork:Evaluation.py:146` then raises `AttributeError`. Its Jaccard mean is undefined for such a run. Ours scores the reply as text (`grading.py:69-81`).
- **What differs.** `jaccard_mean` exists for us and is undefined for the harness on 2 of 20 vectors (`empty`, `csv_na`, Checks run 14).
- **Severity / bound.** `cosmetic`, `0`: `jaccard_mean` is a secondary run metric, and the marks on both sheets are identical.

### D7 — decoding settings the harness fixes are not fixed on the row

- **Undeclared (a finding).** The hand-built spec records `temperature=0` (`docs/spec/2026-09-17-OME-1148-contracteval-containment.md:99`). The row's description, the README and the Task all say nothing about it, and the row sets no decoding knob (Checks run 3).
- **Where.** Theirs: `fork:proprietary_model.py:34,65-67,88` (`temperature=0.`, `top_p=0.9`, `max_output_tokens=400000`) and `fork:open_source_model.py:59` (`do_sample=False, max_new_tokens=5000, temperature=0.`). Ours: none; a Candidate's Model Config decides.
- **What differs.** A Candidate run at its own default temperature samples where the paper's numbers came from greedy or near-greedy decoding.
- **Severity / bound.** `possibly-score-changing`, `unknown` until a paid run compares the two decoding settings.

## Upstream notes

- **Paper vs harness: Case count.** The paper says "4,128 data points" (`arxiv-src:v1/30_Setup_and_Implementation.tex:10`). The harness iterates the whole CUAD test split, 4,182 rows = 102 contracts × 41 categories (Checks run 5), and divides laziness by 1,244 (`fork:Evaluation.py:57`), which is exactly the full split's clause count. The harness wins. The 54-row gap is most likely rows missing from the paper's own output files (`fork:Evaluation.py:38` prints the "Valid data cnt" it actually read), not a different answer key. Bound 0 for us.
- **Paper vs harness: appendix prompt.** `70_Appendix.tex:125` ends `respond with: "No related clause.` with no closing quote and no trailing newline. The harness's `system_prompt` (`fork:proprietary_model.py:75-79`) has both, and ours equals the harness's (Checks run 12). The harness wins. Bound 0.

Ours mirrors `Evaluation.py` (`grading.py:31-36`). Bound 0.
