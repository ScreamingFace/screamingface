## Deviations

### D1 — a reply cut off before its `ANSWER:` line is marked wrong

- **Declared.** `# NAMED DEVIATION` on the row (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:5111-5115`), the scorer under `named_deviations/` (`scorer=` at `benchmarks.py:5116`), the module docstring (`apps/screamingface-engine/src/screamingface_engine_inspect/named_deviations/aime/aime.py:10`), and the row description ("A reply the token limit cut off before its 'ANSWER:' line is wrong"). It adopts the fix proposed on [inspect_evals issue #2701](https://github.com/UKGovernmentBEIS/inspect_evals/issues/2701), which is still open at v0.20.0. A tripwire test fails when the pin reaches inspect_evals' fix (`tests/unit/inspect/test_named_deviation_aime.py:61`).
- **Where.** Ours: `aime.py:57-67`, with the guard at `:61`, and every other reply goes to `aime_scorer` at `:69`. Theirs: `inspect_evals:utils/aime_common.py:71-98` reads the last substantive line whether or not the model finished.
- **What differs.** The mark differs only on a reply that meets all three conditions: its stop reason is `max_tokens` (the Candidate reported `finish_reason: length`), its last substantive line has no `ANSWER:`, and that line ends in a number that matches the key. Such a reply is 0 for us and 1 for v0.20.0. A cut-off reply ending `\boxed{g}` with no `ANSWER:` falls in the same set (sheet `cutoff_boxed_gold`, 30/30 differ). The docstring states one limitation, faithful to #2701 (`aime.py:30-33`): a reply cut off inside its `ANSWER:` line keeps the credit its truncated digits earn.
- **Severity / bound.** `possibly-score-changing`, `unknown`. Any of the 30 Cases can be affected, and which ones depends only on the Candidate's replies (sheets: 30/30 Cases differ on both cut-off sheets, Checks run 5). The count for a given run is exact and free to read off its Report once the run exists. It is the number of Cases whose `finish_reason` is `length`, whose last substantive line lacks `ANSWER:`, and whose v0.20.0 mark is 1. One such Case is `1/30 = 0.0333`, above tolerance. Charged as `possibly-score-changing`, like the reply-dependent deviations in the [ARC-AGI-2 record](arc_agi_2.md), because only a run can bound it.

## Upstream notes

- **inspect_evals vs the MathArena harness: a different examiner, `unbounded`.** The MathArena number on our row (GPT-5.2 (high) 0.983) came from [eth-sri/matharena](https://github.com/eth-sri/matharena/tree/cec19dfe83e2881a8bfcf640f16d0d29718b033a), not from inspect_evals (whose README says "there are no publicly available results to compare against", `inspect_evals:aime2026/README.md:15`). The two differ on four dimensions:
  1. **Prompt.** inspect asks for a closing `ANSWER: $ANSWER` line and says no `\boxed` is needed (`aime_common.py:23`). MathArena asks for `\boxed{}` and states the 0–999 range (`fork:configs/competitions/aime/aime_2026.yaml:1`). Case 1 is 998 vs 720 characters.
  2. **Answer extraction.** inspect numeric-matches the end of the last substantive line. MathArena takes the last `\boxed{}` in the reply, else the last integer anywhere in it. A correct `ANSWER: g` followed by a trailing sentence is wrong for inspect and right for MathArena on 30/30 Cases (Checks run 6).
  3. **Roll-up.** MathArena averages 4 runs per problem (`fork:scripts/run.py:77`, `runs.py:282`); inspect and ours make 1 Attempt. The expectation is the same, the variance is not.
  4. **Sampling.** MathArena fixes per-model `max_tokens` (128000 here); inspect and ours fix none.
  A reply's formatting decides the mark gap, so it cannot be bounded without a run: `unbounded`, which meets the second condition for `comparable-to-inspect`. Note that MathArena, like inspect v0.20.0, ignores the stop reason, so on D1 MathArena marks like inspect, not like us.
- **The dataset inspect_evals pins differs from MathArena's on 2 of 30 problem texts, bound `2/30 = 0.0667` on the inspect-vs-harness gap.** Answers are equal on all 30, and so are ids and order. The problem text differs on two Cases:
  - **Case 10** (key 156). math-ai has "so that `${}\overline{AC}$` is perpendicular `$\overline{BC},$`"; MathArena has "`$\overline{A'C'}$` is perpendicular". The two say different things.
  - **Case 13** (key 39). math-ai has `S_r=\sum_{m\ge 0}\dbinom{10000}{502n+r}`, which sums over `m` while indexing by `n`; MathArena has `502m+r`.
