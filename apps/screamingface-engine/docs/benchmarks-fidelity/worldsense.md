# WorldSense — Fidelity Record

## Verdict

**`not-comparable`.** Our headline cannot sit beside the [paper's Table 2](https://arxiv.org/abs/2311.15930v1) "WS avg." (GPT4 75.6, GPT3.5 55.6, Llama2-chat 56.2, Llama2-FT+1M 77.4). The two numbers come from the same replies through two different formulas. The Cases are the authors' trials exactly: all 87,048, in file order, with the same gold, options and metadata. Every Candidate input equals the trial's `text` byte for byte. The marking differs in three places:

- **D2, the per-trial mark (undeclared).** The authors fold the completeness answers "1" and "2" into one KNOW answer. This touches 13,392 Cases.
- **D3, the roll-up (declared).** The authors take a per-tuple weighted mean and then rebalance by problem size and problem name. We take a plain per-trial mean.
- **D1, the reply reader (undeclared).** Ours reads the reply's leading token. The paper reads the last word and re-asks when that word is not an option.

`sum of bounds against the original harness = 13,392/87,048 (D2) + unbounded (D1) + unbounded (D3) = unbounded > COMPARABLE_TOLERANCE (0.005) → not-comparable`; D2 alone is `0.1538 > 0.005`.

The authors' own [analysis code at `bd81d945`](https://github.com/facebookresearch/worldsense/tree/bd81d945077f169cf95ff39207f788f86e4645e9) reproduces Table 2 to the digit, which shows the size of the gap. Through it, the authors' published GPT4 replies score 0.7564. Through our Engine's hook and tally they score 0.7301, which is exactly the row's Frontier Score (`score=0.730`, `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:3305`). That Frontier Score is therefore comparable to our headline. The paper's number is not.

## Deviations

### D1 — the reply reader: leading token, no re-ask, where the paper reads the last word and re-asks

- **Undeclared.** The README describes our reader: "the leading 1/2/3/TRUE/FALSE/POSSIBLE/IMPOSSIBLE of the reply against the key" (`apps/screamingface-engine/src/screamingface_engine_inspect/local_tasks/worldsense/README.md:36-37`). Nothing on the row, in the README or in the Task docstring says that the paper reads differently. No `# NAMED DEVIATION` covers it.
- **Where.** Ours: `benchmarks.py:3259-3260` (scorer and pattern), the same pattern in `local_tasks/worldsense/worldsense.py:111`, and inspect's `re.search(pattern, completion, re.IGNORECASE)` (`inspect_ai:scorer/_pattern.py:76-78`). Theirs: paper §4.2, p.7: "we select the last word of the generated text and normalise it by upcasing and removing extra punctuation. If this does not match the set of acceptable answers … the model receives a continued conversation where the user asks: 'What is the final answer? Respond only using one of these possible answers: TRUE, FALSE'". The harness repo ships no query code. Its README describes the same procedure with an "e.g." re-ask sentence (`fork:README.md:189-191`) and stores only the read answer (`fork:README.md:180`).
- **What differs.** A reply that reasons before it answers ("The answer is TRUE.") scores 0 for us and 1 for the paper. A reply that answers and then explains ("TRUE, because …") scores 1 for us. The paper would re-ask it, and a model decides that outcome. We never send the second turn.
- **Severity / bound.** `score-changing`, `unbounded`. The trigger is a reply shape, not a set of Case ids. The `answer_is_gold` and `reason_then_final_gold` sheets differ on every one of the 87,048 Cases. On the authors' published replies, which were stored already read as single tokens, the reader makes no difference: every one of their 9,555 differing marks is D2. How often a real Candidate's reply would trigger the paper's re-ask, and what it answers then, needs a model. It cannot change this verdict.

### D2 — completeness answers "1" and "2" graded as distinct options, where the authors fold them into KNOW

- **Undeclared** under this record's rule. No `# NAMED DEVIATION` line covers it and no README paragraph says it. The README's "not the paper's bias-corrected accuracy" (`README.md:37-38`) names the roll-up only. The row does describe it in its Frontier Score comment: "the Compl questions are graded know/don't-know: answers "1" and "2" both map to KNOW … where we need the exact option" (`benchmarks.py:3291-3303`). One README sentence would make it declared. The verdict is the same either way.
- **Where.** Ours: inspect's `match_target` checks `match in target` (`inspect_ai:scorer/_pattern.py:12-17`) against the single gold option (`local_tasks/worldsense/worldsense.py:132`, the `target=` line of `record_to_sample`). Theirs: `resp_map` (`fork:worldsense/analysis.py:192-200`) and `df['acc'] = (resp_map(resp) == resp_map(goldresp))` (`analysis.py:225`). This matches paper §4.2: "responses 1 and 2 are folded as KNOWN, and response 3 as UNKNOWN".
- **What differs.** On a Compl trial whose gold is "1", the reply "2" is wrong for us and right for the authors, and the same holds the other way round.
- **Severity / bound.** `score-changing`, `13,392/87,048 = 0.1538`. The affected Cases are every Compl trial with gold "1" or "2": 3,348 × 2 answers × 2 grades (`Compl.trivial`, `Compl.normal`). The ids were enumerated by `compare_cases.py` (Checks run 6) and confirmed by the `other_known` sheet, which differs on exactly 13,392 Cases (Checks run 12).

### D3 — plain per-trial mean, where the authors take a weighted per-tuple mean, rebalanced

- **Declared.** README: "Benchmark score is plain accuracy over the Cases run, not the paper's bias-corrected accuracy" (`README.md:37-38`). Row description: "Benchmark score = plain accuracy over the cases run; the eval's own bias-corrected accuracy and bias metrics are not reported" (`benchmarks.py:3239`).
- **Where.** Ours: `single_shot.py:1275-1303`. Theirs: `fork:worldsense/analysis.py:212-220` sets the weights (gold 1/2 → 0.25, every other gold → 0.5). `:228` averages each tuple with those weights and `:235` keeps one row per tuple. `:254-281` and `:394-415` take the mean per problem size, then per problem name, giving each group the smallest group's count. `fork:worldsense/benchmark.py:89` is the headline.
- **What differs.** The authors weight each tuple (one described world) equally, so a constant answer scores the 0.5 chance level. We weight each trial equally across the 40,176 tuples (33,480 of size 2, 6,696 of size 3), so under our exact-option marks a constant answer scores 0.4615.
- **Severity / bound.** `score-changing`, `unbounded`. This is an aggregation change, not a set of Cases. Fed the same per-trial marks (the authors' own), the two formulas differ by 0.0063 (GPT4) to 0.0513 (Llama2-FT+1M) (Checks run 15).
