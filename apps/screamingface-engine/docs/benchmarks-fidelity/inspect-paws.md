## Deviations

### D1 — graded by the bare Yes/No pattern of inspect_evals PR #2334, not v0.20.0's `includes()`

- **Declared.** `# NAMED DEVIATION: graded by our bare Yes/No pattern, inspect_evals' merged fix (https://github.com/UKGovernmentBEIS/inspect_evals/pull/2334); v0.20.0's includes() finds "no" inside "cannot"…` at `apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:635-638`. The scorer lives under `named_deviations/`: `apps/screamingface-engine/src/screamingface_engine_inspect/named_deviations/yes_no/yes_no.py:38-42`, whose header (`:10-27`) names the PR, the merge commit and the trade in both directions. A tripwire pins it: `tests/unit/inspect/test_named_deviation_yes_no.py:98` fails once the pin reaches the fix.
- **Where.** Ours `yes_no.py:42` `return pattern(r"\A\W*\b(Yes|No)\b\W*\Z")`. Theirs at the pin: `inspect_evals:paws/paws.py:41` `scorer=includes()`. The merged fix, [`2999eaad` `paws.py:41`](https://github.com/UKGovernmentBEIS/inspect_evals/blob/2999eaadad35edebada59bac4a687793c11d1c3c/src/inspect_evals/paws/paws.py#L41): `scorer=pattern(r"\A\W*\b(Yes|No)\b\W*\Z")`. `diff` of v0.20.0 against 2999eaad `paws.py` → only the import line `:5` and `:41` (Checks run 2). The GitHub API confirms the PR is merged: `closed True 2026-09-16T13:34:08Z 2999eaadad35edebada59bac4a687793c11d1c3c PAWS, BoolQ: score only a bare Yes/No answer instead of substring matches`.
- **What differs.** v0.20.0 credits any reply that contains the gold word as a substring, case-insensitive. Ours credits a reply only when it is the gold word with nothing around it but non-word characters. On the sheets (Checks run 6) the marks flip on 12 of 22 reply shapes. A label inside prose (`The answer is: No`, `Answer: Yes`, `Yes, the two sentences say the same thing.`, `No\n\nExplanation: …`) moves all 8,000 Cases. `No. Actually, Yes.` and `Yes or No` also move all 8,000. A non-answer that contains "no" (`I cannot determine this.`, `I don't know`, `None`, `Nope`) moves the 4,464 No Cases; v0.20.0 scores each of these 0.5580, the all-No majority rate and the paper's BOW accuracy (Table 8). `Yesterday` moves the 3,536 Yes Cases. Ours is 1 only where v0.20.0 is also 1: `pattern` matching the gold word implies the substring is present. So D1 can only lower our score relative to v0.20.0 on the same replies.
- **Severity / bound.** `possibly-score-changing`, `unknown`. The Cases that move are the ones where a real Candidate wraps its label in prose or answers with a non-answer containing the gold word, and that depends on the Candidate's reply wording. Worst case 8000/8000 = 1.0000. The bound becomes enumerable after one run: see Recommended paid runs.

- **Undeclared.** The row's description says "Cases are served in a fixed seeded shuffle (inspect_evals randomizes order per run)" (`apps/screamingface-engine/src/screamingface_engine_inspect/benchmarks.py:622-623`), and `prepare.py:970` carries a Fold comment. - **Where.** Ours `shuffle_seed=20260917` (`apps/screamingface-engine/src/screamingface_engine_inspect/prepare.py:982`), forced through inspect's own `hf_dataset` shuffle (`seeds applied {'shuffle_seed'}`, Checks run 4). - **What differs.** Only the order the Candidate sees the 8,000 Cases in. `our order == hub test order shuffled by datasets.shuffle(seed=20260917): True`. Ours is one of the orders inspect_evals' own shuffle can produce.
- **Severity / bound.** `cosmetic`, `0`. Accuracy is a mean over all Cases, and the Cases are scored independently (single-shot, no shared state), so order cannot change a mark or the headline.
